# 治疗性评估七对象复用与数据流事实基准

日期：2026-07-19
任务：TA-01
状态：`documented`

## 1. 决策

现有任务十二、日记、测评、报告、消息、训练、连续记录和审计可以承载合成 L0 的大部分演示，但不能在没有对象级授权、版本链和状态机前承载真实治疗性评估。TA-01 不创建新表、不创建新页面，也不把七对象塞入一个自由 JSON 后直接开放。

## 2. 七对象复用矩阵

| 对象 | 页面 | 现有 API | 现有表/字段 | 权限事实 | 版本事实 | 结论 |
|---|---|---|---|---|---|---|
| Assessment Question 评估问题 | `assessment-result`、`relationship-report`、`program-detail` | `GET /api/assessment-results/<id>`、`GET /api/relationship-pilot/reports/<id>`、项目 entries | `relationship_screening_reports.report_json.suggested_assessment_questions`、项目反思题 | 报告按本人/后台角色；项目按本人 | 报告有 `version`，问题无独立版本 | 只可展示候选；正式接入需稳定 ID、原话、状态、共享范围和修订链 |
| Episode 代表事件 | `diary-form`、`relationship-task`、`relationship-growth` | `POST /api/diaries`、`POST .../tasks`、`POST .../longitudinal` | `emotion_diaries`、`relationship_pilot_tasks`、`relationship_longitudinal_entries` | 普通用户本人；关系任务绑定 enrollment | 事件有创建时间，缺内容版本 | 可直接复用记录；需兼容增加 question 引用和逐对象共享，不能复制原文 |
| Evidence Item 证据条目 | 测评结果、关系报告、成长时间线 | assessment/profile/report/growth 既有 API | `assessment_results`、`student_profiles`、`records`、日记和关系任务 | 来源表各自校验 | 模型/规则/报告版本不完全统一 | 先建立只读引用；正式接入需来源类型、来源 ID、版本、限制、共享范围和 O/P/H/U 作用 |
| Hypothesis 工作假设 | `relationship-report` | `GET report`、`PUT .../hypotheses/<index>` | `report_json.four_layer_profile.mechanism.hypotheses`、`relationship_hypothesis_feedback` | 本人核对；研究者确认报告 | 报告版本存在，单条假设无稳定 ID | 现有共同核对可复用；需稳定 hypothesis ID、O/P/H/U、替代解释、证据引用和修订链 |
| Feedback Revision 反馈版本 | `feedback-result`、`relationship-report`、`message-detail` | `POST /api/feedback/generate`、报告 confirm/send、messages、`POST /api/feedback-ledger` | `feedback_results`、`relationship_screening_reports`、`messages`、`feedback_ledger` | 本人评价；研究者仅看分配范围摘要 | 新账本保留 `content_version`，旧输出仍分散 | T23-02 已补统一评价；正式 TA 仍需草稿—真人批准—用户修订—最终确认不可变版本链 |
| Action Experiment 微行动 | `training-card`、`personalized-plan`、`checkin` | cards/recommend、training-plan、checkins | `training_cards`、`checkins`、`records` 中 assignment | 本人选择和打卡；后台按角色查看 | 卡有 version；assignment 以记录保存 | 直接复用；需关联已确认问题/反馈版本、停止条件和备用动作，不另建排序源 |
| Follow-up 随访 | `weekly-report`、`relationship-growth`、messages | weekly-report、growth、longitudinal、messages | `weekly_reports`、`relationship_longitudinal_entries`、`checkins`、`messages` | 本人查看；研究者按分配范围 | 以时间点/报告版本为主 | 可复用时间线；不得把频次或分数自动解释为疗效 |

## 3. 数据流

```text
用户原话/事件/测评
→ 原始来源表（不覆盖）
→ 只读来源引用
→ O/P/H/U 候选（L0 仅合成）
→ 真人待审版本（真实流程当前阻断）
→ 参与者统一评价 feedback_ledger
→ 经确认的一个微行动
→ checkin / weekly / longitudinal 随访
```

原始事实、系统整理、研究者判断、参与者确认必须保持为不同记录。新建 `feedback_ledger` 只解决评价来源和版本留痕，不等于已经完成完整反馈修订链。

## 4. 最小增量判断

| 范围 | 可直接复用 | 兼容层需要 | 正式接入前确需新增 |
|---|---|---|---|
| 页面 | 日记、报告、消息、训练、周报 | 首页 Journey 只读进行中状态 | 暂不新增；先用外部合成点击原型验证 |
| API | 现有记录、报告、消息、训练和反馈账本 | 统一分页/错误/对象授权 | TA-03 以后才考虑 question/evidence/revision API |
| 数据库 | 所有来源表和新评价账本 | 稳定来源引用、内容版本 | 未经 T31-01/D17/D18 不建共享与正式 TA 表 |
| shared | Journey 与 Feedback Ledger 已统一 | 七对象枚举和状态机草案 | TA-02 合成契约通过后再落地 |
| 权限 | 本人、研究者分配范围、督导/管理员 | 对象级 create/read/update/send/export/delete | T31-01 前不得开放真实流程 |

## 5. 冲突记录

1. 外部蓝图建议正式试点新增七对象表；当前代码已有大量可复用事实源。处理：先引用、不复制，TA-03 前不建表。
2. 旧关系假设使用“符合/不符合/不确定”，T23-02 新统一评价使用“符合/部分符合/不符合/让我不舒服”。处理：旧表继续保留，新账本兼容汇总，不覆盖旧记录。
3. 临时展示越权与对象级授权目标冲突。处理：按负责人要求暂不关闭，但真实 TA 能力保持关闭，后续权限验收必须单独记录该已知例外。
