# 项目架构边界与后续开发规则

## 2026-08-25：研究执行证明边界

当前在线研究执行器只接受项目自有 `synthetic_fixture`。服务端只读取一次来源字节：同一份字节既用于计算 SHA-256、保存不可变 source object，也用于算法执行，避免“hash 旧文件、分析新文件”的替换竞态。真实参与者来源、跨用户来源和外部数据在研究数据与伦理门禁批准前固定拒绝。

任务完成必须来自内部 worker 流程。worker 先领取租约、准备 Manifest，再生成完整聚合结果、签发结果引用和日志摘要；`complete_job` 在同一事务核对 Manifest/任务/算法/来源/metrics hash 并消费证明。公开 `POST .../complete` 不能提供内部证明，因此合法格式的自报 metrics 也返回 `server_execution_proof_required`。

当前算法是确定性的：相同来源、代码、环境、依赖、版本、快照、参数和随机种子必须得到相同结果 hash；差异未解释时失败关闭。production 执行、真实参与者数据、外部数据下载和训练均未开放。

## 2026-08-25：动态内容运行边界

受控发布不再修改 `content/` 或容器内文件。发布服务先从当前 active 制品（没有时才从仓库基线）构造完整文件快照，校验根结构、目标 ID 和重复 ID，再把 payload、schema、hash、作者、四类审核、发布时间、依赖和状态写入数据库不可变制品表。

运行端每次先读取数据库 active 指针，并校验完整文件 SHA-256；缓存键为 `filename + artifact_hash`。因此多实例和重启都读取同一版本，指针变化后不会沿用旧缓存。hash 不匹配时失败关闭，不回退容器基线。

发布、暂停、退役和恢复都使用数据库比较并交换指针。恢复只指向已有且重新校验通过的旧制品。production 的内容负责人和平台负责人证据仍为 `pending_external`，不能据此开放正式动态发布。

## 1. 当前模块结构

- `backend`：Flask API、SQLite 初始化、导出、风险筛查、画像和家长测评。
- `apps/web`：网站前台和研究/后台管理页面。
- `apps/miniprogram`：家长和学生侧小程序使用入口。
- `content`：正式训练卡、反馈规则、风险词库、量表和候选库。
- `shared`：前后端共用 API 类型、常量和 mock。
- `docs`：进度、接口、数据库、部署、验收和交接文档。

## 2. 后端边界

后端只提供记录、反馈、训练卡、画像、复核、导出和健康检查接口。不要新增自由心理咨询、诊断、医疗级危机干预、正式登录注册或复杂权限系统。

## 3. Web 后台边界

Web 后台用于查看、复核、导出和管理试点数据。不得复制小程序日常使用流程，不展示自由文本原文作为默认研究视图，不绕过 `X-Admin-Token`。

## 4. 小程序边界

小程序是用户主入口，保留核心闭环：目标、记录、反馈、训练卡、打卡、周报、督导。继续保留 `pages/integration-test/index` 和 `pages/debug/index`。

## 5. content 边界

正式运行只读取正式 content 文件。`content/enrichment/` 是候选库，必须人工审核后小批量导入，不得自动进入正式运行。

## 6. 数据库边界

当前仍使用 SQLite 小样本试用方案。不要自动迁移 PostgreSQL/Supabase，不提交数据库文件，不删除旧字段。

## 7. 心理学内容边界

所有用户端内容必须非诊断、非标签化、支持性、非评判。高风险内容只进入人工关注和现实支持提示，不生成普通训练建议。

## 8. 不要重复开发

不要重复开发 6.3/6.4 已完成项：

- 风险预检和 high 风险训练卡阻断；
- production 默认 token/demo-parent 禁止；
- CORS 白名单；
- audit_logs、risk_review_records、consent_records；
- `/healthz`、`/healthz/deep`、schema_migrations；
- SQLite 备份恢复脚本；
- 小程序 debug、CloudBase 配置集中化；
- 匿名用户 ID、导出 limit、常用索引；
- Web 401 提示。

## 9. 下一步只能做什么

1. 试点前人工验收；
2. 根据人工验收修 P0/P1 小问题；
3. 小批量审核后导入 content 候选内容。
