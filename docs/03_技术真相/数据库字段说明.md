# 数据库字段说明

最后更新时间：2026-07-01

本文档定义安心陪伴 MVP 1.0 的 SQLite 第一版数据表。字段命名采用英文 snake_case，展示文案使用中文。

进度口径：当前真实数据库表以前文已实现表和第 11 节研究平台化表为准；学生画像同时写入 `assessment_results` 和 `student_profiles`，研究摘要写入 `records`，导出/查看/人工复核写入 `audit_logs`。`records` 统一导出和高风险导出确认审计元数据已补齐。当前总进度见 `docs/00_当前事实基准/项目进度统一口径.md`。

阅读方式：先按表名查字段；如历史规划文档提到 `profile_results` 或尚未创建的研究表，以本文第 11 节和 `docs/00_当前事实基准/项目进度统一口径.md` 的当前状态为准。导出 CSV 字段含义、脱敏和敏感性说明见 `docs/03_技术真相/数据字典.md`。

## 0. 导出数据字典

2026-06-04 已新增 `docs/03_技术真相/数据字典.md`，用于说明 `GET /api/admin/export` 各类 CSV 导出的字段名、中文含义、数据类型、是否脱敏、是否敏感、研究用途和缺失说明。

导出前必须确认：

```text
1. 用户授权和研究授权；
2. 是否包含高风险或需复核记录；
3. 是否需要进一步去除可识别身份信息；
4. 不把导出数据用于诊断、治疗、危机干预或法律判断。
```

## 1A. `consent_records`

保存用户使用说明、隐私说明、非诊断边界说明和匿名研究授权等同意记录。第一版只保存匿名 `user_id`，不采集真实姓名、手机号或身份证号。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PRIMARY KEY | 同意记录 ID |
| `user_id` | TEXT | 匿名用户 ID |
| `consent_type` | TEXT | 同意类型，例如 `user_agreement`、`privacy_policy`、`non_diagnostic_notice`、`research_authorization` |
| `consent_version` | TEXT | 同意文本版本 |
| `agreed` | INTEGER | 1 表示同意，0 表示不同意或撤回 |
| `agreed_at` | TEXT | 记录该选择的时间 |
| `revoked_at` | TEXT | 不同意或撤回时间，可为空 |
| `created_at` | TEXT | 创建时间 |

边界：

- `research_authorization` 可为 0，不应影响基础使用；
- 正式试点前如需撤回流程，可以继续复用同表新增一条 `agreed=0` 记录；
- 该表不是登录权限表，不保存强身份信息。

## 1B. `risk_review_records`

保存 high/medium 风险初筛后的人工关注队列。该表用于记录处理状态，不保存完整高风险自由文本原文。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PRIMARY KEY | 风险复核记录 ID |
| `user_id` | TEXT | 匿名用户 ID |
| `source_type` | TEXT | 来源类型，例如 `feedback`、`student_profile` |
| `source_id` | TEXT | 来源记录 ID |
| `risk_level` | TEXT | `medium` 或 `high` 为主要复核对象 |
| `matched_categories_json` | TEXT | 命中的风险类别和关键词摘要，不保存完整原文 |
| `review_status` | TEXT | `pending`、`reviewed`、`follow_up_needed`、`transferred`、`closed` |
| `reviewer_id` | TEXT | 复核人匿名 ID |
| `review_note` | TEXT | 后台复核备注 |
| `action_taken` | TEXT | 已采取的最小处置动作 |
| `closed_reason` | TEXT | 关闭或暂不继续处理的原因 |
| `reviewed_at` | TEXT | 复核时间 |
| `created_at` | TEXT | 创建时间 |
| `updated_at` | TEXT | 更新时间 |

边界：

- `POST /api/feedback/generate` 和 `POST /api/profile` 命中 medium/high 风险时会自动创建记录；
- 复核状态更新会写入 `audit_logs.action=review_risk`；
- 该表不代表系统提供实时危机干预，只用于人工关注流转。

## 1C. `schema_migrations`

保存数据库 schema 初始化版本，避免后续不知道当前库是否升级过。

| 字段 | 类型 | 说明 |
|---|---|---|
| `version` | TEXT PRIMARY KEY | 迁移版本，例如 `2026_07_01_001` |
| `name` | TEXT | 迁移名称，例如 `assessment_worksheets_and_profile_positions` |
| `applied_at` | TEXT | 记录时间 |

当前不使用 Alembic，不迁移 PostgreSQL；该表只做 SQLite 试用阶段的最小版本留痕。

## 1D. `emotion_thermometer`

保存用户当天可多次记录的情绪温度计。该表只用于自我观察、日曲线和练习提示，不保存诊断、筛查或人格结论。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PRIMARY KEY | 温度计记录 ID |
| `user_id` | TEXT | 匿名用户 ID |
| `intensity_level` | INTEGER | 1-10 的情绪强度 |
| `valence_level` | INTEGER | 1-10 的愉悦度/不愉悦度观察，可为空 |
| `arousal_level` | INTEGER | 1-10 的身体唤起水平观察，可为空 |
| `control_level` | INTEGER | 1-10 的可控感观察，可为空 |
| `emotion_label` | TEXT | 情绪命名，可为空，不作为诊断标签 |
| `brief_text` | TEXT | 200 字内简短备注，可为空 |
| `created_at` | TEXT | 创建时间 |
| `updated_at` | TEXT | 更新时间 |

查询约定：

```text
GET /api/emotion-thermometer/day 使用 user_id + substr(created_at, 1, 10) 查询当天记录。
索引：idx_emotion_thermometer_user_created。
```

2026-07-05 任务十补充说明：`valence_level`、`arousal_level`、`control_level` 和 `emotion_label` 是轻量观察字段，用于周报和阶段性反馈中的过程复盘；不能用于诊断、筛查、人格定性或风险预测。

## 10. 数据边界

- 第一版不采集姓名、手机号、身份证等强身份字段。
- 开发环境可使用 `demo-parent` 做本地测试；`APP_ENV=production` 时写入型接口必须传匿名 `user_id`，不得缺省写入 `demo-parent`。
- 任何联系方式字段都应明确告知用途。
- 高风险文本只用于提示人工复核或转介，不由 AI 自动处理。
- 导出数据应尽量使用匿名 ID。

## 11. 0版网页评估画像整合保存策略

本节根据夏老师“学生画像”“records 表结构”“数据导出分析”思维导图整理。短期复用 `assessment_results` 已保留；中长期研究平台化表 `student_profiles`、`records` 和 `audit_logs` 已创建。

### 11.1 短期策略：复用 `assessment_results`

在最小实现阶段，当前已经复用 `assessment_results` 保存学生画像结果：

| 字段 | 用法 |
|---|---|
| `worksheet_id` | 使用画像测评条目 ID，例如 `student_profile_v1` |
| `worksheet_title` | 保存展示标题，例如 `学生支持性画像测评` |
| `category` | 使用 `学生画像` |
| `answers_json` | 保存量表分数、支持资源和自由文本脱敏摘要，不默认保存自由文本原文 |
| `scores_json` | 保存输入分数、画像编码、画像名称、置信度、风险等级、推荐训练卡和规则版本 |
| `result_summary` | 保存支持性解释和非诊断提示 |

优点：无需第一步改表，能快速打通“测评 -> 画像结果 -> 训练卡推荐 -> 历史查询”闭环。
