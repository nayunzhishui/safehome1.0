# SafeHome 无障碍验收基线（WCAG 2.2 AA）

更新时间：2026-08-07  
适用范围：SafeHome Web；小程序保留现有设计与信息架构，本轮只统一验收原则，不进行未授权的页面重构。

## 1. 标准

正式目标升级为 **WCAG 2.2 Level AA**：

- W3C Recommendation: https://www.w3.org/TR/WCAG22/
- 继续满足既有 2.1 AA 要求，并补充 2.2 新增成功标准。

## 2. SafeHome 必验项目

### 感知与文本

- 文本与背景保持足够对比度；不能只靠颜色传递风险、状态或权限结果。
- 图像有等价文本；纯装饰图像使用空 `alt` 或等效忽略机制。
- 页面缩放、窄屏和较大字体下不能出现关键操作不可达。

### 键盘与焦点

- 所有 Web 主操作可通过键盘到达和触发。
- 使用 `:focus-visible` 或浏览器默认可见焦点；禁止无替代方案地移除 outline。
- 焦点不能被 sticky/fixed 区域完全遮挡（WCAG 2.2 Focus Not Obscured）。
- 弹窗、错误提示和异步状态变化需要可感知的焦点/状态管理。

### 目标尺寸

- 主按钮、表单控件和独立图标按钮优先达到至少 44×44 CSS px；最低不得低于 WCAG 2.2 Target Size (Minimum) 的 24×24 CSS px，除非符合标准例外。
- 高压力或安全支持页面不使用密集的小点击目标。

### 表单与认证

- input/select/textarea 必须有可访问名称，优先显式 `<label>`。
- 错误说明应关联到对应字段，并可被辅助技术感知。
- 登录不应依赖仅记忆/抄写复杂信息才能完成的认知功能测试；允许密码管理器和粘贴（Accessible Authentication）。
- 不阻断浏览器/辅助技术的密码自动填充与复制粘贴能力。

### 状态与动态内容

- loading、保存成功、失败、风险提示等关键状态使用 `aria-live` / `role=status|alert` 等合适机制。
- 动画尊重 `prefers-reduced-motion`。
- 自动更新内容不能导致意外焦点跳转。

### 心理支持场景补充

- 安全/风险信息不能只使用红色或图标；必须有明确文字。
- 不通过倒计时、闪烁、强制连续弹窗制造额外压力。
- 关键求助入口在键盘、窄屏和放大模式下保持可达。
- 错误文案说明“发生了什么、能做什么”，避免羞辱性或责备性语言。

## 3. 自动检查与人工检查边界

自动检查负责发现：明显缺失 accessible name、heading 跳级、焦点样式缺失、reduced-motion 缺失、明显过小目标、横向溢出等。

自动检查**不能替代**：屏幕阅读器真实操作、键盘完整旅程、400% zoom、颜色/认知负荷评估、真实移动端和高压力场景可用性测试。

## 4. 发布要求

- PR：运行静态无障碍基线和 Web typecheck/build。
- 候选试点：运行 Playwright WCAG 2.2 核心旅程检查。
- 正式发布：完成桌面 Chrome + 移动 Chrome 的人工键盘/缩放/焦点检查，并保存证据。
- 任何自动通过结论只能写“自动门禁通过”，不能写“已完成全部 WCAG 2.2 AA 认证”。
