# UI 审美评估与后续修改建议（2026-10-09）

## 一句话结论

基础是对的：青瓷主色统一、标题居中、正文 30rpx、触控 96rpx，安全边界也清楚。但整体仍偏“用力”和“工具感”：字重过重、卡片与阴影偏多、部分页面同屏多个实心主按钮、治理说明挡在用户视线中央。最值得做的三件事是：**降字重、减卡片、每屏一个主行动**。这三件都不改功能和位置，只改样式层级。

## 评估依据与局限

- 代码静态扫描：`apps/miniprogram` 全部 55 个页面的 WXML/WXSS（脚本只读，不改文件）。
- 已有图像：2026-08 真机首页截图、`design/ui-product` 中的 Figma 画面。
- 外部参考：Calm 设计系统的“克制”原则（单一品牌色、标题字重 600、正文行高 1.6、引文靠排版）[1]；中文移动端排版经验（正文行高 1.5–2 倍、标题与正文约 1.5 倍、正文对比度 ≥7:1）[2]。
- 局限：仓库里没有 9 月 UIproduct2 改版后的真机截图，本评估以代码为准；视觉细节最终仍需真机截图确认。

## 扫描得到的事实

| 指标 | 数量 | 说明 |
|---|---|---|
| 页面总数 | 55 | 含本轮新增 2 页 |
| 同屏出现多个实心主按钮的页面 | 8 | 例：测评填写 4 处、设置详情 6 处、项目详情 3 处、关系成长 3 处（部分为条件互斥，需逐页确认） |
| 字重 ≥800 的声明 | 212 处 | 全局 `safe-h1` 为 900、`safe-h2` 为 850 |
| 阴影声明 | 46 处 | 主要在训练卡、测评列表、反馈结果、周报 |
| 页面样式里小于 26rpx 的字号声明 | 195 处 | 不少已被 ui2 覆盖放大，但基础样式仍残留，后续改动容易“复活”小字 |

## 做得好的地方（保留）

1. 单一主色（青瓷 #23666e）贯穿全站，没有花哨渐变；全站只剩 1 处渐变。
2. 标题居中、标题下不放说明小字的规则已基本落实。
3. 风险提示与求助入口清楚，没有用恐吓式颜色。
4. 草稿保存、离线、撤回等状态都有真实文案，没有假进度。

## 主要问题（按影响排序）

1. **字重太重，页面像在“喊”。** 900/850 的标题配 28–30rpx 正文，层级跳得太猛，和“安静、可信”的产品调性相反。建议标题 600–700、区块标题 600、正文 400。
2. **卡片与阴影仍多。** 训练、反馈结果、周报、质量页还有“卡片墙”。建议普通内容改为细线分组 + 留白；只保留“行动卡”和“风险卡”两种容器。
3. **主行动竞争。** 8 个页面同屏有多个实心主按钮。建议每屏只有一个实心按钮，其余改描边或文字按钮。
4. **治理和免责说明挡在中央。** 例如旧版首页底部的“阶段性反馈”、旧版支持性评估总览的六段规则说明。建议页面级只说一次，详细规则折叠。
5. **色温偏冷。** 青瓷配冷灰底（#f4f8f8）读起来更像医疗工具。阅读和情绪相关页面可以加入暖白“纸面”（#fffdf8 + 暖色细线），像青瓷配米纸，不改主色。本轮在支持性评估已试用。
6. **首页首屏过满。** 温度计、测一测、日记、今天的一小步、如何开始、更多（3 项）、最近记录、阶段性反馈同时出现。建议首屏只留“今天的一小步”、三个快速记录入口和最近一条记录。
7. **训练卡不够“拿来就用”。** 卡片内容已重写为日常工具包，但训练卡页只显示“今天的小目标”，具体步骤要点进下一页才看到。建议卡片上直接显示 3 步要点、时长和“什么时候用”。

## 分页修改建议

| 优先级 | 页面 | 现在的问题 | 建议修改（不改功能和位置） |
|---|---|---|---|
| P1 | 首页 | 首屏入口过多，阶段性反馈的说明文字密 | 首屏只留今天的一小步 + 三个记录入口；阶段性反馈折叠成一行摘要 |
| P1 | 训练卡 | 步骤藏在下一页；卡片有阴影 | 主卡直接列出 3 步要点与时长；去阴影，改细线；备选卡降为列表行 |
| P1 | 测评结果 | 维度、画像、推荐、边界层层堆叠 | 顺序固定为“结论一句话 → 维度 → 今天试一个练习”；边界合并为页尾一次 |
| P2 | 测评列表 | 卡片多、标签多 | 改为分组列表，每行只显示名称、题数、用时；标签只留“适合谁” |
| P2 | 测评填写 | 4 处实心按钮 | 只保留“下一题/提交”实心，其余改描边 |
| P2 | 情绪日记 | 字段多时显得长 | 必填在前，选填折叠；保存状态放到底部按钮旁 |
| P2 | 周报 / 反馈结果 | 卡片墙 | 改为“本周三件事”的编辑式排版 |
| P3 | 我的 | 小字较多 | 入口统一为列表行，元数据 26rpx |
| P3 | 研究者工作台 | 信息密度高 | 研究者端可以密，但用表格和分组，不用卡片墙 |

## 建议的全局排版（需要你确认后再改）

按项目规则，改全局 token 会影响所有页面，必须先经你确认。建议值：

| 用途 | 现在 | 建议 |
|---|---|---|
| 页面主标题 | 44–46rpx / 700–900 | 44rpx / 600 |
| 区块标题 | 30–36rpx / 750–850 | 32–34rpx / 600 |
| 正文 | 28–30rpx / 行高 1.6 | 30rpx / 行高 1.75（长文） |
| 元数据 | 22–26rpx | 统一 26rpx，只用于日期、数量、状态 |
| 阅读型底色 | #f4f8f8 | 阅读与情绪页可用 #fffdf8 纸面，其余页不变 |
| 阴影 | 多处 | 只用于浮层；普通内容用 1rpx 细线 |

## 本轮已经应用的改进

- 支持性评估总览：自助整理在先、真人复核在后；一个实心主行动；规则说明折叠；暖白纸面入口。
- 自助整理分步页与回看信页：按上表的建议值实现（标题 600、正文 30rpx、竹节进度、四段核对控件、衬线只用于信件标题和本人原话）。
- 测评结果页风险条：正文 30rpx，同色系底色与描边按钮，并加入“查看紧急求助资源”。

## 下一步怎么做

1. 你确认两件事：是否在阅读型页面引入暖白纸面；是否把全站标题字重降到 600。
2. 我先改 3 个样板页（首页、训练卡、测评结果），只动样式和信息顺序，不动接口和数据。
3. 在微信开发者工具编译，并请你用真机各截一张图；确认后再推到其余页面。
