## 修订要点(相对 0726 首版)
1. **页面数 40 → 41**(以 `app.json` 实际 pages 为准,脚本已改为动态读取,不写死)。
2. **风险等级修正**:批次 A/D 从"零业务风险"改为**"低至中风险"**——tokens 影响全局样式、字号影响排版,均需截图确认。
3. **字号收敛(219 处)**:批量提升到 ≥24rpx 可能造成**错版/换行错位**,**必须逐批截图验收**,不得全量一次替换。
4. **颜色 token 化**:**只做精确映射**(hex 值与 token 完全一致才替换),**禁止"最近邻"近似替换**;无精确映射的一律进人工清单,由设计确认。
5. **开发页隔离**:`integration-test`/`debug` 与"项目长期保留联调入口"的规则**存在冲突**——不硬删源码,改为**构建期按环境剔除**,发布包不含、开发包保留(见 D1)。
6. **Error Boundary 优先实施**(线上白屏事故级);**React Router 与巨型文件拆分独立排期**,不与视觉改造混做(见 C 批说明)。
7. **新基线**:以**任务33 / F19 现有审计器**(`scripts/audit_task23_visual_system.mjs` 双视口溢出+触控+可达、`backend/scripts/audit_task33_experience.py` 八类体验门禁)和 `shared/design/experience-tokens.json` 设计系统为准,不另起炉灶。

## 全局铁律
不改后端 API / shared 类型 / content 来源 / 小程序联调页业务逻辑 / 核心链路。每卡执行后跑该卡验证命令 + 逐批截图,绿灯且截图无回归才算完成;红灯回滚该卡。

## 批次 A:设计 token 单一化(**低至中风险**,先做,逐批截图)

- **A1 token 单一来源**:`gen_design_tokens.py` 从 `experience-tokens.json` 生成 `app.wxss`/`styles.css` 锚点区(`AUTO-GEN:tokens`),**只接管与现值完全一致的变量**,不一致项写 `design_token_mismatch_report.md` 由设计决策(现有 warning/danger/web 主色三处不一致,不强改)。验证:`--check` diff 为空 + build 通过。
- **A2 色值 token 化**:`map_hex_to_token.py` **仅精确映射**,高频(≥3 次)同值 hex 建同值新变量(值不变),低频/渐变/阴影内一律进 `hex_manual_review.md` 不自动改。验证:残留可替换 hex=0(`--check`);**关键页 375/430/768/1440 逐页截图比对无差异**。
- **A3 tabBar 色值对齐**:`#4E7C6B`→token(色差 1/255 不可感知)。验证:字符串比对。
- **A4 字号收敛**:`normalize_font_sizes.py` 把 <24rpx 提到 `var(--safe-font-caption)`(=24rpx,由 tokens 生成三档 caption/small/body)。验证:计数归零(`--check`);**逐批截图确认无换行错位/错版**——本项风险最高,建议按页分 3–4 批,每批截图通过再下一批。

## 批次 B:组件复用与状态/无障碍补齐(中风险,需回归 + 截图)

以页审报告为准,重点先补**关键路径与安全语义缺陷**,再做机械铺开:
