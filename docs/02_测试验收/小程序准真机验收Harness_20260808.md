# SafeHome 小程序准真机验收 Harness

更新时间：2026-08-08

## 1. 目的

本 Harness 用于把 SafeHome 当前“本地工程完成但微信开发者工具/真机验收未完成”的外部门禁转为可重复执行、可留证据、可回归的验收流程。

它不把 GitHub 或模拟器结果冒充物理真机结论。验收分为五层：

| 层级 | 内容 | 自动化程度 | 能否作为上线批准 |
|---|---|---:|---:|
| L0 | GitHub 静态门禁：清单、页面注册、安全保护、Task36 微信登录工程审计 | 全自动 | 否 |
| L1 | 微信开发者工具 Safe Mode：全部注册页面启动、截图、脱敏 page.data | 全自动 | 否 |
| L2 | 本地后端真实三步联调：日记→反馈→训练卡 | 自动，显式允许测试写入 | 否 |
| L3 | 已批准测试云环境：微信登录、授权取消、Token 过期/停用账号 | 半自动/受控 | 否 |
| L4 | Android + iOS 微信正式客户端真机 UAT | 人工+证据 | 是上线门禁之一 |

## 2. 当前仓库事实

- 小程序工程：`apps/miniprogram/`，原生微信小程序 JS。
- `app.json` 当前注册首页、登录、消息、训练、课程、测评、关系试点、治疗性评估、研究者工作台、debug 与 integration-test 等页面。
- `pages/integration-test/index` 已能执行“创建情绪事件记录→即时反馈→训练卡推荐”三步联调。
- Task36 微信登录审计当前明确仍缺微信开发者工具首次/重复登录、Android/iOS 真机、停用账号与 Token 过期等外部门禁。
- 当前默认 `cloudConfig.js` 指向生产 CloudBase，因此 Harness 默认强制覆盖为本地 HTTP，并在启动后清空缓存登录态，避免误读/误截图真实账户数据。

## 4. Safe Mode：默认执行方式

### 前置条件

1. Windows 已安装微信开发者工具。
2. 微信开发者工具“设置→安全设置”已开启服务端口。
3. Node.js >= 18。
4. 本地 SafeHome 后端如需业务联调，应先按项目既有方式启动。

### 安装

```powershell
cd tools\miniprogram-acceptance
npm install
```

设置微信开发者工具 CLI 路径（示例仅表示变量格式，实际路径以本机安装位置为准）：

```powershell
$env:WECHAT_DEVTOOLS_CLI="<微信开发者工具CLI完整路径>"
```

### L0：静态门禁

```powershell
python ..\..\scripts\validate_miniprogram_acceptance.py
python ..\..\scripts\audit_task36_wechat_login.py
node --check .\run.js
```

### L1：全部页面准真机扫描

```powershell
npm run routes
```

执行行为：

1. 启动微信开发者工具自动化。
2. 清除本地 Storage 中的登录态。
3. 写入仅本次测试使用的 `safehome_cloud_config`，默认指向 `http://127.0.0.1:5000`。
4. 从 `apps/miniprogram/app.json` 动态读取全部页面。
5. 对每个页面执行 `reLaunch`。
6. 等待页面稳定后保存模拟器截图。
7. 保存脱敏后的 `page.data`。
8. 汇总 passed/failed/skipped。

这一步的目标不是证明每个页面业务数据都正确，而是发现：编译/启动失败、页面崩溃、注册路径漂移、明显空白页、未登录状态泄露以及适配证据缺失。

### 登录入口检查

```powershell
npm run auth
```

至少验证：

- 微信一键登录或“暂不可用”状态存在；
- 账号密码登录仍存在；
- 注册入口仍存在；
- 快捷登录能力不可用时不会丢失账号密码兜底。

## 5. L2：三步真实业务联调

该场景会产生本地测试写入，因此默认跳过。

确认本地后端与本地测试数据库已启动后：

```powershell
$env:SAFEHOME_ACCEPTANCE_ALLOW_TEST_WRITES="1"
npm run smoke
```

通过标准：

```text
pages/integration-test/index
→ 点击“运行联调测试”
→ healthz 可用
→ 创建测试情绪事件
→ 生成即时反馈
→ 获取训练卡推荐
→ page.data.status == "success"
```

如果未设置 `SAFEHOME_ACCEPTANCE_ALLOW_TEST_WRITES=1`，Harness 必须返回 `skipped`，不能偷偷执行写入。

## 6. 外部测试环境保护

默认仅允许 loopback 地址。若把 `SAFEHOME_ACCEPTANCE_BASE_URL` 指向非 `localhost/127.0.0.1` 地址，必须额外设置：

```powershell
$env:SAFEHOME_ACCEPTANCE_ALLOW_EXTERNAL_READS="1"
```

这只代表允许读取已批准的测试环境，不代表允许生产写入。生产账号创建/绑定、真实手机号授权、真实参与者数据写入仍不应由本 Harness 自动开启。

## 7. L3：微信登录与会话专项

以下项目应在明确的测试账号/测试云环境完成，不在 GitHub CI 中执行：

1. 微信一键登录首次进入。
2. 同一微信重复登录，确认不会异常创建重复账号。
3. 用户取消微信登录。
4. 用户取消手机号授权。
5. 快捷登录不可用时账号密码兜底。
6. Token 过期后自动清理本地会话并要求重新登录。
7. 已停用账号无法继续使用旧 Token。
8. student 角色登录后未成年人保护门禁 fail-closed。

证据中禁止记录：登录 code、Bearer token、AppSecret、openid/unionid、完整手机号、联系人信息。

## 8. L4：最终真机验收矩阵

至少覆盖 Android 与 iOS 各一台：

| 类别 | 必验项目 |
|---|---|
| 启动 | 冷启动、热启动、重复进入、前后台切换 |
| 导航 | tabBar、返回、深层页面返回、重复点击 |
| 登录 | 微信/手机号取消、失败、成功、过期、账号停用 |
| 核心闭环 | 目标→情绪记录→反馈→训练→打卡→周报 |
| 测评 | 填写、提交、结果、历史记录、重复提交 |
| 治疗性评估 | 边界→问题→近期事件→资源→分享→总结→反馈确认→行动复盘 |
| 风险安全 | 高风险输入不生成训练卡，现实支持资源持续可达 |
| 弱网 | 超时、断网、恢复；不得把服务错误伪装成空数据 |
| UI/UX | 小屏、大字体、键盘、安全区、长文本、按钮防重复提交 |
| 隐私 | 无真实 token/手机号/研究数据出现在日志、截图或错误详情 |

## 9. 判定规则

- **BLOCKER**：泄露真实敏感数据、越权访问、高风险路径生成不当建议、登录绕过、核心数据写错用户。
- **P0**：登录或核心闭环无法完成；崩溃；关键页面无法进入；网络异常导致错误写入。
- **P1**：重要页面明显错位、重复提交、错误态不可恢复、关键提示缺失。
- **P2**：轻微视觉/文案/非核心交互问题。

只有 L0-L3 达标且 L4 Android/iOS 真机 UAT 完成后，才能把“真机验收”从 pending 改为 passed。GitHub Actions 绿色不能替代 L4。
