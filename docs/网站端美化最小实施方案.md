# 网站端美化最小实施方案

创建日期：2026-05-23

项目：`safehome1.0 / 安心陪伴 / ReadFeedback`

本文档用于补齐网站端的可执行视觉优化方案。当前只做规划，不修改代码，不修改后端 API，不修改数据库，不新增登录注册，不做正式部署。

进度说明：截至 2026-06-01，网站端首页和后台已完成第一轮视觉改版，本文不再代表“尚未开始美化”的状态。后续若继续优化，应先参考 `docs/项目进度统一口径.md`、`docs/UI与伦理边界验收清单.md` 和最新页面截图，只修明确的布局、间距、文字溢出、可用性和伦理边界问题。

## 1. 目标

网站端美化目标不是把网站做成小程序的网页版，而是让网站更清楚地承担两个职责：

1. 网站前台：面向合作方、家长、研究人员和督导老师，说明项目定位、使用方式、试点边界和伦理边界。
2. 网站后台：面向项目管理员、研究人员和督导老师，清楚查看记录、反馈、训练卡、打卡、周报、督导请求和导出状态。

视觉优化需要做到：

1. 更温和、专业、可信；
2. 降低医疗化、诊断化、测评化观感；
3. 提升后台信息密度和可扫描性；
4. 保持小程序端和网站端字段一致；
5. 不改变现有页面路径和业务逻辑；
6. 不新增后端接口；
7. 不修改数据库。

## 4. 视觉方向

### 4.1 网站前台

网站前台应呈现：

1. 温暖但不幼稚；
2. 专业但不医疗化；
3. 清楚说明项目价值和边界；
4. 适合给合作方、家长和研究人员快速理解项目；
5. 第一屏就能看出这是“家长陪伴练习支持系统”，不是心理诊断工具。

建议视觉元素：

1. 大面积浅色背景；
2. 柔和绿色为主色；
3. 暖橙和浅蓝作为少量辅助色；
4. 真实感较弱、低压力的扁平插画；
5. 清晰的核心闭环步骤图；
6. 明确的伦理边界区块。

### 4.2 网站后台

网站后台应呈现：

1. 数据管理工具感；
2. 信息密度比小程序更高；
3. 表格、筛选、详情卡片清楚；
4. 状态标签克制，不制造风险感；
5. 重要边界提示固定可见；
6. 能快速判断数据是否完整、反馈是否合规、督导请求是否需要查看。

建议视觉元素：

1. 左侧导航或顶部管理导航保持稳定；
2. 页面标题区显示当前页面用途；
3. 数据指标使用紧凑统计卡；
4. 列表页优先表格和筛选；
5. 详情页采用左侧记录内容、右侧关联信息；
6. 风险和边界信息使用低饱和提示条，不使用大面积红色。

## 5. 页面级优化建议

### 5.1 `LandingPage.tsx`

优先级：P0

建议优化：

1. 首页 Hero 增加项目名称、支持性副标题和边界提示；
2. 首屏使用温和家庭陪伴插画或真实感较低的项目视觉图；
3. 增加“核心闭环”横向步骤区；
4. 增加“家长小程序”和“研究管理后台”双列说明；
5. 增加伦理边界区，明确非诊断、非替代专业服务；
6. 试点招募区文案保持审慎，不承诺效果。

不建议：

1. 不做营销式夸张大标题；
2. 不使用“解决孩子问题”“治疗情绪问题”等表达；
3. 不把首页做成登录入口。

### 5.2 `AdminDashboard.tsx` / `ResearchDashboard.tsx`

优先级：P0

建议优化：

1. 统一为研究管理总览视觉；
2. 指标卡显示目标、记录、反馈、打卡、周报、督导请求数量；
3. 最近记录和最近督导请求用紧凑列表展示；
4. 增加“数据仅用于试点管理和复盘”的边界提示；
5. 避免使用风险评分、诊断结论或异常判定视觉。

### 5.3 `GoalsManagement.tsx`

优先级：P1

建议优化：

1. 用表格展示目标场景、目标内容、状态、创建时间；
2. 使用温和状态标签，例如“进行中”“已暂停”“已完成”；
3. 增加目标质量提示文案：具体、可练习、可追踪；
4. 不评价家长目标“好坏”。

### 5.4 `FeedbackManagement.tsx`

优先级：P0

建议优化：

1. 页面顶部固定显示反馈边界：非诊断、非标签化、支持性；
2. 列表中区分“模式提示”“支持性反馈”“推荐训练卡”；
3. 命中标签用低饱和胶囊标签；
4. 避免红色大面积显示，除非是明确需要人工查看的提示；
5. 提供文案抽查视角，方便检查反馈是否越界。

### 5.5 `CardsManagement.tsx`

优先级：P1

建议优化：

1. 卡片列表以训练目标、适用场景、练习步骤为主；
2. 分类标签保持清楚但不过度装饰；
3. 卡片详情强调“小步练习”，不强调矫正；
4. 保持与 `content/training_cards.json` 来源一致。

### 5.6 `RulesManagement.tsx`

优先级：P1

建议优化：

1. 反馈规则用“规则查看”而不是“诊断规则”；
2. 关键词、模式提示、反馈文案、推荐卡分区展示；
3. 增加伦理检查提示：不诊断、不标签化、不责备；
4. 不把规则标签展示成疾病或人格判断。

### 5.7 `CheckinsManagement.tsx`

优先级：P1

建议优化：

1. 用表格展示训练卡、是否完成、备注、时间；
2. 使用轻量完成状态；
3. 增加“练习追踪不是评分”的提示；
4. 备注长文本要有展开或详情区，避免表格拥挤。

### 5.8 `ReportsManagement.tsx`

优先级：P1

建议优化：

1. 周报页面强调复盘和趋势，不做成绩单；
2. 指标用“本周记录次数”“练习次数”“常见情绪词”；
3. 不做分数排名；
4. 使用柔和图表或摘要卡，避免考试报告感。

### 5.9 `SupervisionManagement.tsx`

优先级：P0

建议优化：

1. 页面顶部明确人工督导不是实时危机服务；
2. 请求列表显示提交时间、关联记录、家长补充说明、状态；
3. 状态标签使用“待查看”“已查看”“已补充”，避免“危急/异常”等刺激性表达；
4. 高风险内容只提示寻求现实支持和专业帮助，不承诺系统自动处理。

### 5.10 `ExportManagement.tsx`

优先级：P1

建议优化：

1. 导出前增加脱敏提醒；
2. 导出类型说明清楚；
3. 管理员令牌输入区保持克制；
4. 不在页面中暗示数据可随意外发。

### 5.11 `IntegrationSmokeTest.tsx`

优先级：P2

建议优化：

1. 保持开发测试属性；
2. 可以统一基础样式；
3. 不隐藏关键测试信息；
4. 不让它承担正式管理后台职责。
