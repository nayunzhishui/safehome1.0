# UI 与伦理边界验收清单

创建日期：2026-05-26

项目：`safehome1.0 / 安心陪伴 / ReadFeedback`

本文档用于每轮 UI 收口和试点前人工验收。目标是把问题记录为三类：看不懂、点不动、不舒服。

进度口径：本文用于试点前逐页验收。当前学生画像、沙盘表达、高风险复核和画像导出仍为规划检查项，不代表相关页面和接口已经实现。最新状态见 `docs/项目进度统一口径.md`。

## 1. 验收原则

本项目所有页面都应符合：

1. 非诊断；
2. 非标签化；
3. 支持性；
4. 非评判；
5. 聚焦具体事件和可练习动作；
6. 不承诺替代心理咨询、医学诊断、危机干预或法律判断。

## 5. 心理与伦理文案检查

允许表达：

1. `可能`;
2. `看起来`;
3. `这次记录中可以看到`;
4. `可以尝试`;
5. `练习位置`;
6. `支持性反馈`;
7. `补充理解`;
8. `需要时寻求现实支持或专业帮助`。

需要替换或避免的表达：

1. 直接判断孩子、家长或家庭；
2. 诊断性疾病表述；
3. 人格或家庭标签；
4. 责备、羞辱或命令式表达；
5. 承诺系统能处理危机；
6. 把周报写成成绩排名；
7. 把打卡写成评分或考核。
8. 把学生画像写成固定人格；
9. 把沙盘符号解释为潜意识诊断；
10. 对自伤、自杀、暴力、家暴等高风险文本继续输出普通训练建议。

## 6. 页面重点边界

### 6.1 AI反馈页

必须体现：

1. 反馈是支持性参考；
2. 不评价谁对谁错；
3. 识别到的是一次记录中的互动线索；
4. 下一步是可练习的小动作。

### 6.2 周报页

必须体现：

1. 周报是复盘；
2. 不排名；
3. 不评分；
4. 不给疾病或人格结论。

### 6.3 人工督导页

必须体现：

1. 人工督导是补充理解；
2. 不是实时危机服务；
3. 不替代专业服务；
4. 出现安全风险时应寻求现实支持。

### 6.4 导出页

必须体现：

1. 导出前先检查脱敏；
2. 长文本可能包含可识别信息；
3. 导出文件只给授权人员使用；
4. 不暗示数据可以随意外发。

### 6.5 学生画像结果页（规划）

必须体现：

1. 画像是阶段性支持性观察；
2. 必须显示置信度或“结果仅供参考”；
3. 必须包含优势提示；
4. 不使用“人格”“障碍”“异常”等字样；
5. 下一步是一个可练习的小任务，而不是停留在评价结果。

### 6.6 沙盘表达任务页（规划）

必须体现：

1. 沙盘是表达媒介；
2. 沙盘结果只作为访谈线索；
3. 系统不自动解释潜意识；
4. 不把具体符号和心理问题直接绑定；
5. 导出时保留授权和脱敏要求。

### 6.7 高风险复核页（规划）

必须体现：

1. 高风险内容不生成普通自动反馈；
2. 引导现实支持和专业帮助；
3. 不承诺系统能提供即时危机服务；
4. 后台能区分 `low`、`medium`、`high`；
5. 高风险原文导出需要更严格授权。

## 7. 修复优先级

P0 立即修复：

1. 按钮不可点击；
2. 主流程无法继续；
3. 文案明显诊断化或责备；
4. 移动端关键内容被遮挡；
5. 高风险边界表达错误。
6. 学生画像出现人格定性或诊断化结论；
7. 高风险文本仍展示普通训练建议。

P1 本轮修复：

1. 文字溢出；
2. 卡片拥挤；
3. 状态色不统一；
4. 空状态不清楚；
5. 用户不知道下一步。

P2 后续优化：

1. 插画细节；
2. 动效；
3. 更细的筛选；
4. 更完整的数据分析；
5. 正式权限系统。
