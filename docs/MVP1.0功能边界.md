# MVP 1.0 功能边界

## 1. 项目定位

MVP 1.0 的目标是跑通“安心陪伴”家长情绪管理支持系统的最小闭环：

```text
目标设定 → 情绪事件记录 → 情绪与互动模式识别 → 非诊断反馈
→ UP训练卡推送 → 家长练习与打卡 → 周度报告 → 人工督导补充
```

第一版重点验证流程、内容规则、数据结构和两端并行开发方式，不追求完整商业化功能。

## 2. MVP 必须包含

### 2.1 后端

- Flask + SQLite 项目骨架。
- 数据库连接与初始化占位。
- 路由模块划分。
- 服务模块划分。
- 后续可承载目标、日记、反馈、训练卡、打卡、周报、人工督导和导出接口。

### 2.2 小程序端

- 保留原生微信小程序方向的目录结构。
- 后续页面顺序应覆盖：首页、知情同意、目标设定、情绪事件记录、即时反馈、UP 训练卡、练习打卡、周度报告、人工反馈入口。
- 第一阶段不写复杂页面，只保留结构。

### 2.3 网页端

- React/Vite 方向目录结构。
- `pages`、`components`、`services` 放入 `apps/web/src` 下。
- 保留 `apps/web/package.json`，为后续初始化前端依赖做准备。
- 第一阶段不写复杂页面。

### 2.4 共同内容库

- `training_cards.json`：UP 训练卡样例。
- `feedback_rules.json`：非诊断反馈规则样例。
- `consent.md`：知情同意文本。
- `privacy.md`：隐私说明文本。

## 3. MVP 暂不包含

- 视频上传和视频分析。
- 语音上传和语音识别。
- 复杂 AI 对话。
- 社群功能。
- 完整咨询系统。
- 支付、会员、商业转化。
- 多角色复杂权限系统。
- 高风险危机内容的自动化处置。

## 4. 伦理与安全边界

- 不诊断家长或孩子。
- 不承诺改善效果。
- 不使用评判性、标签化表达。
- 不把系统反馈写成临床判断。
- 出现自伤、自杀、暴力、家庭暴力等高风险线索时，应提示人工复核或专业转介。

## 5. 当前验收标准

- 项目目录结构完整。
- 根目录、docs、backend、apps、shared、content 均有清晰职责。
- 后端文件只提供占位结构，不包含完整业务实现。
- JSON 内容样例可解析。
- 文档能指导下一步后端接口开发。
