# 量表与工作表接入方案

创建日期：2026-05-23

本文档记录 `工作表及示例` 目录中的 PDF 工作表如何接入小程序“测一测”板块。

## 1. 当前决策

本轮按用户确认执行：

1. 量表和工作表全部纳入“测一测”；
2. 用户端第一版直接展示原文标题和原工作表结构；
3. 量表填写数据保存到后端；
4. 允许新增数据库表和新增 API；
5. 结果页只做维度记录和支持性提示，不生成诊断结论。

## 3. 分类

当前分为四类：

1. 量表类；
2. 目标与进展类；
3. 情绪觉察与认知类；
4. 行为与练习类；
5. 示例参考。

附录 B 示例只作为“示例参考”，不作为默认必填量表。

## 4. 统一边界提示

小程序页面必须固定展示：

```text
本内容用于自我观察和练习记录，不用于诊断，不替代心理咨询、医学诊断、危机干预或法律判断。如你或家人正在经历明显痛苦或现实风险，请及时寻求现实支持和专业帮助。
```

即使原文包含“治疗、焦虑、抑郁、暴露”等词，也不在结果页生成疾病判断。

## 5. 数据保存

新增数据库表：

```text
assessment_results
```

保存：

1. 用户 ID；
2. 工作表 ID；
3. 工作表标题；
4. 分类；
5. 答案 JSON；
6. 分数 JSON；
7. 总分；
8. 支持性结果摘要；
9. 创建时间。

第一版不采集姓名、手机号、身份证等强身份信息。

## 6. API

新增接口：

```text
GET /api/assessments
GET /api/assessments/<worksheet_id>
POST /api/assessment-results
GET /api/assessment-results
GET /api/admin/export?type=assessments
```

接口只负责返回工作表内容和保存结果，不做诊断计算。

## 7. 小程序页面

新增页面：

```text
pages/assessment-detail/index
pages/assessment-result/index
```

保留并升级：

```text
pages/assessment/index
```

页面职责：

1. `assessment/index`：测一测列表和最近保存记录；
2. `assessment-detail/index`：展示工作表说明和填写项；
3. `assessment-result/index`：展示保存结果、总分记录和训练入口。

## 8. 后续补录任务

后续需要继续做：

1. 逐页查看 PDF 图片；
2. 将完整原题项、选项、表头补入 `content/assessment_worksheets.json`；
3. 每补完一个 PDF，抽查小程序详情页展示是否完整；
4. 对有正式计分规则的量表，补齐 `scoring` 说明；
5. 保持结果页非诊断，不输出疾病判断。

## 9. 回滚方式

如果测一测接入出现问题：

1. 先隐藏 `assessment` 页面入口；
2. 保留后端表和接口；
3. 不删除情绪记录、反馈、训练卡、打卡、周报、督导核心链路；
4. 不删除 `pages/integration-test/index`。
