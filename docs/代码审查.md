## 问题 1：`buildAdminExportUrl` 返回相对路径，`wx.downloadFile` 需要完整 HTTPS URL

**状态：** ✅ 已修复（2026-06-01）

**文件：** `apps/miniprogram/services/api.js`

### 原因分析

之前从 `wx.request` 迁移到 `wx.cloud.callContainer` 时，`buildAdminExportUrl` 从返回完整 URL：

```js
// 旧代码
const baseUrl = "https://flask-gh3l-261352-9-1436233118.sh.run.tcloudbase.com";
buildAdminExportUrl(params) {
  return `${baseUrl}${API_ENDPOINTS.adminExport}${queryString(params)}`;
}
```

变为返回相对路径：

```js
// 新代码（提交后）
buildAdminExportUrl(params) {
  return `${API_ENDPOINTS.adminExport}${queryString(params)}`;
  // 返回 "/api/admin/export?type=csv" —— 相对路径
}
```

对 `wx.cloud.callContainer({ path })` 来说，相对路径即可正常使用。但 `wx.downloadFile({ url })` **要求完整 HTTPS URL**，相对路径会导致下载静默失败。Web 端有自己的 `safehomeApi.ts` 实现，使用 `this.absoluteUrl()` 拼接，不受影响。

### 修复过程

**原则：** 不改变 `request()` 函数的 `callContainer` 调用方式（它仍然只用 `path`），只在需要完整 URL 的场景（`buildAdminExportUrl`）构造完整 URL。

**改动 1：** 新增 `DEFAULT_HTTP_BASE_URL` 常量，注释说明用途。

```js
// 仅用于 wx.downloadFile / 分享链接 / 二维码等需要完整 HTTPS URL 的场景；
// 常规 API 调用仍通过 wx.cloud.callContainer，不走此域名。
const DEFAULT_HTTP_BASE_URL = "https://flask-gh3l-261352-9-1436233118.sh.run.tcloudbase.com";
```

**改动 2：** `createSafeHomeApi` 新增 `httpBaseUrl` 配置项。

```js
const httpBaseUrl = options.httpBaseUrl || DEFAULT_HTTP_BASE_URL;
```

**改动 3：** `buildAdminExportUrl` 恢复拼接完整 URL。

```js
buildAdminExportUrl(params = {}) {
  return `${httpBaseUrl}${API_ENDPOINTS.adminExport}${queryString(params)}`;
},
```

**改动 4：** 导出 `DEFAULT_HTTP_BASE_URL`，供外部按需引用。

### 修复后验证

- `request()` 函数不受影响，仍通过 `wx.cloud.callContainer` 发送请求，只传 `path`
- `buildAdminExportUrl()` 返回完整 HTTPS URL，可安全传入 `wx.downloadFile`
- 调用方可通过 `createSafeHomeApi({ httpBaseUrl: 'https://custom.example.com' })` 覆盖默认域名
- Web 端 `safehomeApi.ts` 有独立实现，不受此变更影响

## 问题 2：`request()` 的 `fail` 回调未适配 `callContainer` 错误格式

**状态：** ✅ 已修复（2026-06-01）

**文件：** `apps/miniprogram/services/api.js`

### 原因分析

`wx.cloud.callContainer` 的 fail 回调收到的错误对象与 `wx.request` 不同：

| 字段 | `wx.request` fail | `wx.cloud.callContainer` fail |
|------|-------------------|-------------------------------|
| 错误码 | 无独立字段 | `err.errCode`（如 `INVALID_HOST`） |
| 错误信息 | `err.errMsg` | `err.errMsg` |

旧代码：
```js
fail(error) {
  reject({
    code: "network_error",        // 硬编码，丢失 CloudBase 错误码
    message: error.errMsg || "网络请求失败",
    detail: error,
  });
},
```

当 CloudBase 网关返回 `INVALID_HOST` 时，上层只能看到 `"network_error"`，无法区分是网络断连还是网关路由问题，排查时需要去 CloudBase 控制台看日志。

### 修复过程

**改动：** 将硬编码的 `"network_error"` 改为优先读取 `err.errCode`，兜底仍用 `"network_error"`。

```js
fail(err) {
  reject({
    code: err.errCode || "network_error",
    message: err.errMsg || "云托管调用失败",
    detail: err,
  });
},
```

变量名从 `error` 改为 `err`，与 WeChat 官方文档命名一致，减少歧义。

### 修复后验证

- CloudBase 网关错误（如 `INVALID_HOST`）会被正确传递到上层，显示为 `code: "INVALID_HOST"`
- 普通网络断连时 `errCode` 为空，仍走 `"network_error"` 兜底
- 配合问题 #1 的修复，错误信息链路完整：CloudBase 网关 → `fail` → 上层页面

## 任务清单审查：`docs/0版网页整合逐步开发任务清单.md`

审查日期：2026-06-01

### 🔴 会阻塞执行的问题

#### 问题 A：P0-4 画像测评条目没有题目

**位置：** 任务清单第 121-168 行

`assessment_worksheets.json` 中 `student_profile_v1` 的 `sections` 和 `questions` 都为空数组。P0-4 列出了必须包含的维度（考试焦虑、IU、恐惧、自我同情、自由文本），但没有写成可用的题目。

P2-1 依赖此条目展示测评页面，没有题目就无法进行下一步。P0-4 标记"已完成"实际只完成了一半——入口框架有了，题目内容没有。

**建议：** 新增 P0-4b 子任务，明确编写：
- 考试焦虑 3-5 题
- 不确定性不耐受 3-5 题
- 恐惧/压力警觉 3-5 题
- 自我支持/自我同情 3-5 题
- 自由文本 1 题
- 每题需定义选项格式（如 Likert 5 级）和计分方式

---

#### 问题 B：两个节都标为 P2，编号冲突

**位置：** 第 445 行和第 535 行

```text
## 4. P2：小程序学生画像页面
## 5. P2：网页后台画像列表与导出
```

执行沟通时无法区分"做 P2"具体指哪个。两者虽同属 P2 阶段，但涉及的代码库完全不同。

**建议：** 改为 `P2-小程序` 和 `P2-网页后台`，或 `P2A` / `P2B`。

---

#### 问题 C：P1-3 画像规则服务缺少兜底逻辑

**位置：** 第 348-374 行

规则库目前只有一条规则 `pressure_alert`，触发条件为 `test_anxiety >= 3.5 AND iu_score >= 3.5`。未定义分数不匹配任何规则时的行为——返回空？返回通用画像？抛错？

**建议：** P1-3 增加验收项："不匹配任何规则时返回通用画像或'暂无匹配画像'，不报错、不白屏"。

---

#### 问题 D：P2 缺少小程序端风险处理完整流程

**位置：** P2 各节

P2-2 将 `riskCheck` 标为"可选封装"，但自由文本中的高风险内容应在提交时就触发阻断，而非等到结果页。P2-1（入口页）也没有风险提示的设计。

**建议：** P2-2 把 `riskCheck` 从"可选"改为"必须"，在 P2-1 和 P2-2 之间补一个"提交前风险预检"验收项。

---

### 🟡 会导致后期返工的问题

#### 问题 E：整个 P1-P4 没有错误处理任务

没有任何任务涉及：API 超时、网络断开、后端 500、JSON 解析失败、内容文件缺失时的前端表现。对于心理支持工具，白屏或崩溃的体验代价很高。

**建议：** 每个 P 阶段末尾加"错误状态验收"，至少覆盖：网络失败、服务不可用、数据为空三种状态。

---

#### 问题 F：沙盘表达数据没有存储方案

训练卡 `sandplay_expression_01` 让学生选象征物、描述位置大小颜色、说出最想表达的话。但任务清单没有定义沙盘数据存哪里、是否进入导出、是否参与画像计算。

**建议：** P1-5 补充沙盘数据保存路径，或 P4 增加 `module_type=sandplay_task` 的 records 接入说明。

---

#### 问题 G：P1-5 复用 `assessment_results` 的字段兼容性未验证

`assessment_results` 表的 `total_score` 字段对画像场景无意义（画像没有总分），`result_summary` 格式也未定义。直接复用可能在实现时发现结构不够用。

**建议：** P1-5 增加子任务"验证 assessment_results 表字段兼容画像数据，明确 total_score 和 result_summary 的填充规则"。

---

#### 问题 H：P1-3 依赖 P1-1/P1-2，但缺少回顾步骤

P1-3（画像规则服务）要调用 `content_loader` 和 `risk_service`，但任务清单假设它们"已完成即可用"。实际开发时很可能发现 loader 返回格式需调整。

**建议：** P1-3 开头加一步"回顾 P1-1 和 P1-2 的接口签名，确认可直接调用，必要时先重构"。
