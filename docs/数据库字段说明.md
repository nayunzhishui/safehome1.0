# 数据库字段说明

最后更新时间：2026-06-04

本文档定义安心陪伴 MVP 1.0 的 SQLite 第一版数据表。字段命名采用英文 snake_case，展示文案使用中文。

进度口径：当前真实数据库表以前文已实现表和第 11 节研究平台化表为准；学生画像同时写入 `assessment_results` 和 `student_profiles`，研究摘要写入 `records`，导出/查看/人工复核写入 `audit_logs`。`records` 统一导出和高风险导出确认审计元数据已补齐。当前总进度见 `docs/项目进度统一口径.md`。

阅读方式：先按表名查字段；如历史规划文档提到 `profile_results` 或尚未创建的研究表，以本文第 11 节和 `docs/项目进度统一口径.md` 的当前状态为准。导出 CSV 字段含义、脱敏和敏感性说明见 `docs/数据字典.md`。

## 0. 导出数据字典

2026-06-04 已新增 `docs/数据字典.md`，用于说明 `GET /api/admin/export` 各类 CSV 导出的字段名、中文含义、数据类型、是否脱敏、是否敏感、研究用途和缺失说明。

导出前必须确认：

```text
1. 用户授权和研究授权；
2. 是否包含高风险或需复核记录；
3. 是否需要进一步去除可识别身份信息；
4. 不把导出数据用于诊断、治疗、危机干预或法律判断。
```

## 1A. `consent_records`

保存用户使用说明、隐私说明、非诊断边界说明和匿名研究授权等同意记录。第一版只保存匿名 `user_id`，不采集真实姓名、手机号或身份证号。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PRIMARY KEY | 同意记录 ID |
| `user_id` | TEXT | 匿名用户 ID |
| `consent_type` | TEXT | 同意类型，例如 `user_agreement`、`privacy_policy`、`non_diagnostic_notice`、`research_authorization` |
| `consent_version` | TEXT | 同意文本版本 |
| `agreed` | INTEGER | 1 表示同意，0 表示不同意或撤回 |
| `agreed_at` | TEXT | 记录该选择的时间 |
| `revoked_at` | TEXT | 不同意或撤回时间，可为空 |
| `created_at` | TEXT | 创建时间 |

边界：

- `research_authorization` 可为 0，不应影响基础使用；
- 正式试点前如需撤回流程，可以继续复用同表新增一条 `agreed=0` 记录；
- 该表不是登录权限表，不保存强身份信息。

## 10. 数据边界

- 第一版不采集姓名、手机号、身份证等强身份字段。
- 开发环境可使用 `demo-parent` 做本地测试；`APP_ENV=production` 时写入型接口必须传匿名 `user_id`，不得缺省写入 `demo-parent`。
- 任何联系方式字段都应明确告知用途。
- 高风险文本只用于提示人工复核或转介，不由 AI 自动处理。
- 导出数据应尽量使用匿名 ID。

## 11. 0版网页评估画像整合保存策略

本节根据夏老师“学生画像”“records 表结构”“数据导出分析”思维导图整理。短期复用 `assessment_results` 已保留；中长期研究平台化表 `student_profiles`、`records` 和 `audit_logs` 已创建。

### 11.1 短期策略：复用 `assessment_results`

在最小实现阶段，当前已经复用 `assessment_results` 保存学生画像结果：

| 字段 | 用法 |
|---|---|
| `worksheet_id` | 使用画像测评条目 ID，例如 `student_profile_v1` |
| `worksheet_title` | 保存展示标题，例如 `学生支持性画像测评` |
| `category` | 使用 `学生画像` |
| `answers_json` | 保存量表分数、支持资源和自由文本脱敏摘要，不默认保存自由文本原文 |
| `scores_json` | 保存输入分数、画像编码、画像名称、置信度、风险等级、推荐训练卡和规则版本 |
| `result_summary` | 保存支持性解释和非诊断提示 |

优点：无需第一步改表，能快速打通“测评 -> 画像结果 -> 训练卡推荐 -> 历史查询”闭环。

风险：画像结果、普通量表结果和工作表结果混在一张表中，后续查询和导出会变复杂。

### 11.3 `records`

统一研究导出入口，适合承载学生画像、家长记录、沙盘任务、打卡等多源数据摘要。该表不建议第一步替换现有业务表。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PRIMARY KEY | 记录 ID |
| `user_id` | TEXT NOT NULL | 用户 ID 或匿名 ID |
| `module_type` | TEXT | 模块类型 |
| `source_id` | TEXT | 来源业务表 ID，例如画像结果 ID 或打卡 ID |
| `data_json` | TEXT | 模块摘要数据 JSON |
| `created_at` | TEXT | 创建时间 |
| `updated_at` | TEXT | 更新时间 |
| `export_allowed` | INTEGER | 是否允许导出，1/0 |

`module_type` 建议值：

- `student_profile`
- `parent_log`
- `sandplay_task`
- `checkin`
- `weekly_report`
- `supervision`

推荐策略：

1. 业务页面继续读写专用表；
2. 研究导出优先从 `records` 查询；
3. 新增模块时只需增加 `module_type`，避免频繁改大宽表；
4. 自由文本原文不默认进入 `records.data_json`，只保存脱敏摘要或关键词。

导出说明：

- `GET /api/admin/export?type=records` 可导出统一研究摘要；
- 可用 `module_type=student_profile` 筛选学生画像摘要；
- 导出默认使用 `anonymous_id`，不导出自由文本原文；
- 如果摘要包含 `risk_level=high` 或 `requires_review=true`，需要 `confirm_high_risk=true`。

- 人工备注不修改原始画像结果；
- 人工复核保存会写入 `audit_logs.action=review_profile`；
- 如后续要向学生端展示人工回复，应先增加审核和展示开关，不直接公开后台备注。

### 11.6 数据边界补充

- 学生画像前端不使用“人格”字样，使用“阶段性画像”或“压力反应画像”。
- `confidence` 只能表示规则/模型匹配置信度，不代表临床判断确定性。
- `free_text`、高风险文本、联系方式均属于敏感字段，导出默认屏蔽。
- `export_allowed=false` 的数据不得进入研究导出。
- 沙盘表达只作为表达媒介和访谈线索，不自动解释潜意识。

### 11.8 `records.data_json` 学生画像摘要字典

学生画像写入 `records` 时，`module_type=student_profile`。

| JSON 字段 | 说明 | 是否包含原文 |
|---|---|---|
| `anonymous_id` | 匿名 ID | 否 |
| `assessment_result_id` | 关联测一测记录 ID | 否 |
| `profile_code` | 画像编码 | 否 |
| `profile_name` | 画像名称 | 否 |
| `confidence` | 规则匹配置信度 | 否 |
| `risk_level` | 风险初筛等级 | 否 |
| `requires_review` | 是否需要人工复核 | 否 |
| `recommended_card_ids` | 推荐训练卡 ID 列表 | 否 |
| `rules_version` | 画像规则版本 | 否 |

设计边界：

- `records` 用于研究摘要，不是完整业务详情表；
- 不在 `records.data_json` 保存自由文本原文；
- 后续接入 `checkin`、`sandplay_task`、`parent_log` 时，也应优先保存摘要字段。

### 11.9 `audit_logs` 操作字典

当前已记录的操作：

| `action` | 触发场景 | `target_type` | 说明 |
|---|---|---|---|
| `view_profile` | 查看 `GET /api/profile-results/<profile_id>` | `student_profile` | 记录画像详情查看 |
| `review_profile` | 保存人工复核记录 | `student_profile` | 记录复核状态、结论和展示边界 |
| `export_profile` | 导出 `type=profile` | `export` | 记录画像导出 |
| `export_records` | 导出 `type=records` | `export` | 记录统一研究摘要导出 |
| `export_diaries` 等 | 导出其他类型 | `export` | 记录后台导出 |

审计边界：

- 第一版不记录管理员令牌原文，只记录 `admin-token` 这类标识；
- `metadata_json` 可记录导出类型、筛选条件、导出行数、`contains_high_risk` 和 `confirmed_high_risk_export`；
- 后端已提供 `backend.database.write_audit_log()` 统一写入工具，后续敏感操作应优先复用该函数，不再手写插入 SQL；
- 后续新增规则编辑后台时，必须增加 `update_rule` 或类似操作日志；
- 人工复核处置已记录 `review_profile`，但不代表完成危机干预流程。
