# 数据库字段说明

本文档定义安心陪伴 MVP 1.0 的 SQLite 第一版数据表。字段命名采用英文 snake_case，展示文案使用中文。

进度口径：当前真实数据库表以前文已实现表为准；学生画像第一版已复用 `assessment_results` 保存结果；第 11 节中的 `profile_results`、`records`、`audit_logs` 仍为后续规划。当前总进度见 `docs/项目进度统一口径.md`。

## 1. `users`

保存家长弱身份信息或测试用户信息。第一版不采集强身份信息。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PRIMARY KEY | 用户 ID |
| `nickname` | TEXT | 昵称或测试编号 |
| `role` | TEXT | `parent`、`student`、`admin` |
| `source` | TEXT | 来源渠道 |
| `created_at` | TEXT | 创建时间 |
| `updated_at` | TEXT | 更新时间 |

## 7. `assessment_results`

保存小程序“测一测”中量表和工作表的填写结果。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PRIMARY KEY | 测一测结果 ID |
| `user_id` | TEXT | 用户 ID |
| `worksheet_id` | TEXT | 工作表 ID |
| `worksheet_title` | TEXT | 工作表标题 |
| `category` | TEXT | 分类 |
| `answers_json` | TEXT | 用户答案 JSON |
| `scores_json` | TEXT | 分数或维度结果 JSON |
| `total_score` | INTEGER | 数值题合计，记录型工作表可为空 |
| `result_summary` | TEXT | 支持性结果摘要 |
| `created_at` | TEXT | 创建时间 |

说明：

- 第一版不采集姓名、手机号、身份证等强身份信息。
- 结果用于自我观察和练习记录，不构成诊断。
- 原 PDF 为图片型，完整题项需要后续逐页转录补齐。
- 学生画像第一版使用 `worksheet_id=student_profile_v1`、`category=学生画像` 写入本表。
- 学生画像的 `answers_json` 默认只保存量表分数、支持资源和自由文本脱敏摘要，不保存自由文本原文。

## 10. 数据边界

- 第一版不采集姓名、手机号、身份证等强身份字段。
- 任何联系方式字段都应明确告知用途。
- 高风险文本只用于提示人工复核或转介，不由 AI 自动处理。
- 导出数据应尽量使用匿名 ID。

## 11. 0版网页评估画像整合保存策略

本节根据夏老师“学生画像”“records 表结构”“数据导出分析”思维导图整理。短期复用 `assessment_results` 已实现；中期 `profile_results`、长期 `records` 和 `audit_logs` 尚未创建，当前真实表结构仍以前文 1-9 节为准。

### 11.1 短期策略：复用 `assessment_results`

在最小实现阶段，当前已经复用 `assessment_results` 保存学生画像结果：

| 字段 | 用法 |
|---|---|
| `worksheet_id` | 使用画像测评条目 ID，例如 `student_profile_v1` |
| `worksheet_title` | 保存展示标题，例如 `学生支持性画像测评` |
| `category` | 使用 `学生画像` |
| `answers_json` | 保存量表分数、支持资源和自由文本脱敏摘要，不默认保存自由文本原文 |
| `scores_json` | 保存输入分数、画像编码、画像名称、置信度、风险等级、推荐训练卡和规则版本 |
| `result_summary` | 保存支持性解释和非诊断提示 |

优点：无需第一步改表，能快速打通“测评 -> 画像结果 -> 训练卡推荐 -> 历史查询”闭环。

风险：画像结果、普通量表结果和工作表结果混在一张表中，后续查询和导出会变复杂。

### 11.2 中期建议：`profile_results`

保存学生画像结果，支持轮次追踪、研究导出和后台复核。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PRIMARY KEY | 画像结果 ID |
| `user_id` | TEXT | 用户 ID 或匿名学生 ID |
| `assessment_result_id` | TEXT | 关联测一测结果，可为空 |
| `round` | INTEGER | 第几轮测评，默认 1 |
| `profile_code` | TEXT | 画像编码，例如 `pressure_alert` |
| `profile_name` | TEXT | 画像名称，例如 `压力警觉型画像` |
| `confidence` | REAL | 画像置信度，0-1 |
| `dimensions_json` | TEXT | 维度结果 JSON |
| `keywords_json` | TEXT | 文本关键词 JSON |
| `supportive_explanation` | TEXT | 支持性解释 |
| `suggested_task` | TEXT | 推荐任务 ID |
| `recommended_card_ids_json` | TEXT | 推荐训练卡 ID JSON |
| `risk_level` | TEXT | `low`、`medium`、`high` |
| `requires_review` | INTEGER | 是否需要人工复核，1/0 |
| `model_version` | TEXT | 模型版本 |
| `rules_version` | TEXT | 规则版本 |
| `boundary_notice` | TEXT | 非诊断边界说明 |
| `export_allowed` | INTEGER | 是否允许研究导出，1/0 |
| `created_at` | TEXT | 创建时间 |

### 11.3 中长期建议：`records`

统一研究导出入口，适合承载学生画像、家长记录、沙盘任务、打卡等多源数据摘要。该表不建议第一步替换现有业务表。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PRIMARY KEY | 记录 ID |
| `user_id` | TEXT NOT NULL | 用户 ID 或匿名 ID |
| `module_type` | TEXT | 模块类型 |
| `source_id` | TEXT | 来源业务表 ID，例如画像结果 ID 或打卡 ID |
| `data_json` | TEXT | 模块摘要数据 JSON |
| `created_at` | TEXT | 创建时间 |
| `updated_at` | TEXT | 更新时间 |
| `export_allowed` | INTEGER | 是否允许导出，1/0 |

`module_type` 建议值：

- `student_profile`
- `parent_log`
- `sandplay_task`
- `checkin`
- `weekly_report`
- `supervision`

推荐策略：

1. 业务页面继续读写专用表；
2. 研究导出优先从 `records` 查询；
3. 新增模块时只需增加 `module_type`，避免频繁改大宽表；
4. 自由文本原文不默认进入 `records.data_json`，只保存脱敏摘要或关键词。

### 11.4 后续建议：`audit_logs`

用于记录后台导出、风险复核、规则变更等敏感操作。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PRIMARY KEY | 日志 ID |
| `actor_id` | TEXT | 操作者 ID，第一版可为管理员令牌标识 |
| `action` | TEXT | 操作类型，例如 `export_profile`、`review_risk` |
| `target_type` | TEXT | 操作对象类型 |
| `target_id` | TEXT | 操作对象 ID |
| `metadata_json` | TEXT | 筛选条件、导出行数、脱敏状态等 |
| `created_at` | TEXT | 创建时间 |

### 11.5 数据边界补充

- 学生画像前端不使用“人格”字样，使用“阶段性画像”或“压力反应画像”。
- `confidence` 只能表示规则/模型匹配置信度，不代表临床判断确定性。
- `free_text`、高风险文本、联系方式均属于敏感字段，导出默认屏蔽。
- `export_allowed=false` 的数据不得进入研究导出。
- 沙盘表达只作为表达媒介和访谈线索，不自动解释潜意识。
