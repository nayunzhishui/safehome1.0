# 情绪记录字段对齐方案

更新时间：2026-05-21

本文档用于 MVP 1.1 第 2 批开发前的字段对齐。目标是在不改数据库的前提下，先确认小程序 `diary-form`、后端 `emotion_diaries`、`shared/types/api.ts` 和网站后台 `/diaries` 能使用同一套字段。

实施状态：

```text
已完成小程序 diary-form 最小升级：身体感觉、短期结果、长期影响已加入表单；孩子反应、短期结果、长期影响已按固定格式合并保存到 raw_text。
```

## 1. 当前结论

当前后端数据库、API 文档和 `shared/types/api.ts` 对情绪记录字段基本一致。

第一阶段不需要改数据库。

小程序 `pages/diary-form/index` 已经有部分升级字段，但存在一个需要明确的映射：

```text
孩子反应、短期结果、长期影响：第一阶段合并保存到 raw_text
```

原因：

1. 当前 `emotion_diaries` 表没有 `child_reaction`、`short_term_result`、`long_term_effect` 独立字段；
2. `docs/MVP1.1功能迭代方案.md` 已经写明第一版可合并保存；
3. 这样可以先升级小程序表单和网站详情页，不破坏现有 API；
4. 后续如果研究评估需要单独统计，再统一规划数据库迁移。

## 4. `raw_text` 第一阶段建议格式

下一轮升级小程序记录页时，建议把合并字段用清楚的文本格式保存到 `raw_text`：

```text
孩子反应：……
短期结果：……
长期影响：……
```

这样做的好处：

1. 不改数据库；
2. 网站后台详情页可以直接展示；
3. 后续如果需要迁移成独立字段，可以从结构化文本中人工或脚本辅助整理；
4. 不影响现有反馈生成逻辑。

## 5. 当前小程序字段差异

当前 `apps/miniprogram/pages/diary-form/index` 已有：

1. `eventDescription` -> `event_description`
2. `parentEmotionIntensity` -> `parent_emotion_intensity`
3. `childEmotionIntensity` -> `child_emotion_intensity`
4. `automaticThought` -> `automatic_thought`
5. `behavior` -> `behavior`
6. `childReaction` -> `raw_text`

当前缺少或待升级：

1. 场景选择或输入；
2. 家长情绪选择或输入；
3. 孩子情绪选择或输入；
4. 身体感觉；
5. 短期结果；
6. 长期影响；
7. `raw_text` 合并字段格式化。

## 6. 网站后台字段差异

当前网站 `AdminDashboard` 已展示：

1. 场景；
2. 事件描述；
3. 家长情绪和强度；
4. 孩子情绪和强度；
5. 自动想法；
6. 行为；
7. 身体感觉；
8. 创建时间。

网站 `AdminDashboard` 记录详情已补充：

1. 关联目标 ID 或目标摘要；
2. `raw_text`，用于展示孩子反应、短期结果、长期影响的合并文本；
3. 事件发生时间 `event_time`。

## 7. 已完成的最小代码任务

已完成小程序记录页最小升级：

```text
升级 apps/miniprogram/pages/diary-form/index：新增身体感觉、短期结果、长期影响输入；把孩子反应、短期结果、长期影响按固定格式合并保存到 raw_text；继续复用 POST /api/diaries，不改数据库。
```

已完成网站后台记录详情最小补齐：

```text
在 apps/web/src/pages/AdminDashboard.tsx 中显示 goal_id、event_time 和 raw_text；raw_text 多行文本按换行展示；继续复用 GET /api/diaries，不改数据库。
```

暂不做：

1. 不新增数据库字段；
2. 不新增后端 API；
3. 不做复杂标签选择器；
4. 不做诊断量表；
5. 不改反馈规则；
6. 不改训练卡逻辑。

## 8. 后续可能的数据库升级

只有在试点评估明确需要单独统计时，才考虑新增字段：

1. `emotion_diaries.child_reaction`
2. `emotion_diaries.short_term_result`
3. `emotion_diaries.long_term_effect`

新增前必须同步修改：

1. 后端模型和迁移说明；
2. API 文档；
3. `shared/types/api.ts`；
4. 小程序 `diary-form`；
5. 网站 `/diaries` 和 `/diaries/:id`；
6. 导出字段；
7. 旧数据兼容策略。
