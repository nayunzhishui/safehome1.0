# 小程序设计系统

创建日期：2026-06-02

适用范围：`apps/miniprogram`

本设计系统根据当前首页视觉稿、现有小程序页面和网站端视觉规范提取。目标是让后续小程序页面在不重写业务逻辑的前提下，逐步形成统一、精致、克制的产品气质。

本轮方向调整为：

```text
美观精致，但少 AI 味。
像真实产品团队沉淀出来的温和设计系统，而不是一组泛泛的 AI UI 关键词。
```

## 1. 设计气质

### 1.1 核心感受

页面应给家长的第一感受是：

```text
安静
干净
可信
有人味
不催促
不评判
```

不是：

```text
心理测评工具
医疗后台
营销海报
儿童 App
AI 生成的泛温暖界面
```

### 1.2 视觉关键词

保留当前方向，但表达更收敛：

```text
浅米白底
灰绿主色
少量暖橙
低饱和浅蓝
清晰留白
大圆角但不过分膨胀
轻阴影
细边线
局部绿植
自然光感
```

减少使用：

```text
大面积渐变
漂浮光斑
重复装饰叶子
过多 emoji
高饱和橙色按钮
所有模块都做成厚重卡片
没有信息意义的胶囊标签
```

## 2. 反 AI 味规则

后续页面改造时，每页都按这一节自查。

### 2.1 不要堆形容词

避免这类文案：

```text
温暖专业可信的亲子成长支持系统
每天一点点，让关系更美好
开启你的情绪成长之旅
```

优先写成具体场景：

```text
今天也辛苦了，先照顾一下自己。
用 1 分钟记录刚才的感受。
这次先练习停一停，再回应孩子。
```

### 2.2 不要做假精致

避免：

```text
每张卡都有渐变、阴影、图标、标签和装饰。
页面里同时出现圆点、星星、叶子、光斑、波浪。
按钮、标签、图标都很亮，导致没有主次。
```

优先：

```text
一个页面只保留 1 个明显视觉焦点。
普通信息用白卡和细边线即可。
只有主行动按钮使用实色。
插画只在顶部或空状态中出现，不到处铺。
```

### 2.3 不要让界面像模板

避免所有页面都长成：

```text
顶部大标题
副标题
三张卡
四个图标
底部提示语
```

每页应根据任务调整节奏：

```text
首页：今日面板，重点是“现在做什么”。
记录页：低压力表单，重点是“慢慢写清楚”。
反馈页：解释和下一步，重点是“不是评价谁对谁错”。
训练页：路径感，重点是“从稳定自己开始”。
我的页：分组入口，重点是“找记录、找支持”。
```

## 3. 颜色变量

位置：

```text
apps/miniprogram/app.wxss
```

当前变量：

```text
--safe-primary: #578b5f
--safe-primary-soft: #e9f2df
--safe-primary-pale: #f3f8ee
--safe-primary-deep: #2f5f48
--safe-orange: #f47f45
--safe-orange-soft: #fff1e4
--safe-yellow: #f1c86d
--safe-blue: #6f9cc5
--safe-blue-soft: #eef6fb
--safe-purple: #8767b7
--safe-purple-soft: #f3effb
--safe-bg: #fff8ee
--safe-bg-leaf: #f6faf2
--safe-card: #fffdf8
--safe-title: #202622
--safe-text: #555f59
--safe-muted: #7d8580
--safe-border: #e4dccf
```

使用原则：

```text
绿色：主品牌、选中态、核心行动。
橙色：只用于“开始练习”等行动点，不要到处点缀。
蓝色：周报、数据、辅助查看。
紫色：测评入口可少量使用，不做大面积背景。
米白：页面底，不要改成纯白或灰白。
深色文字：接近黑但不纯黑，避免压迫。
```

精致度控制：

```text
同一屏最多出现 3 个主题色。
同一模块内不要同时出现绿色、橙色、蓝色、紫色。
浅色背景优先用低饱和色，不用透明度很高的亮色。
```

## 4. 字体层级

全局字体：

```text
-apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif
```

推荐层级：

```text
.safe-h1: 46rpx / 900 / 首页品牌或页面主标题
.safe-h2: 36rpx / 850 / 页面模块主标题
.safe-h3: 30rpx / 800 / 卡片标题
.safe-body: 26rpx / 正文说明
.safe-caption: 22rpx / 辅助信息、时间、状态
```

文字规则：

```text
标题不要超过 14 个汉字。
副标题尽量 1 行，最多 2 行。
正文一段不超过 3 行。
不要用负字距。
不要为了“高级感”把正文变得太浅。
```

文案语气：

```text
用“可以”“先”“这次”“看起来”。
少用“必须”“立即”“改变”“治愈”“重塑”。
不说人格、疾病、诊断、异常。
```

## 5. 按钮样式

公共 class：

```text
.safe-primary-button
.safe-secondary-button
.safe-outline-button
.safe-ghost-button
.safe-orange-button
.safe-button-sm
```

按钮分工：

```text
绿色主按钮：提交记录、保存、继续核心流程。
橙色按钮：开始练习，仅用于训练行动。
浅蓝按钮：查看周报、查看详情、辅助操作。
描边按钮：返回、换一个、稍后再说。
幽灵按钮：开发入口、弱入口、非正式能力。
```

精致度规则：

```text
一个卡片里最多一个实色按钮。
同一屏最多两个实色按钮。
按钮文字用动词开头，例如“开始记录”“保存复核”。
不要写“立即开启”“马上体验”“一键生成”等营销感文案。
```

## 6. 卡片样式

公共 class：

```text
.safe-card
.safe-surface
.safe-card--hero
.safe-card--green
.safe-card--orange
.safe-card--blue
```

使用规则：

```text
普通内容卡：.safe-card
顶部重点卡：.safe-card.safe-card--hero
提示卡：可使用 green/orange/blue 变体
列表型内容：优先用 .safe-list-item，不要每条都做复杂卡片
```

卡片审美：

```text
圆角默认 24rpx，首页重点卡 32rpx。
阴影要轻，只制造层次，不做漂浮感。
边线保留 1rpx，提升真实产品感。
不要卡片套卡片。
不要所有模块都加插画。
```

## 7. 图标容器样式

公共 class：

```text
.safe-icon
.safe-icon-round
.safe-icon-soft
.safe-icon--orange
.safe-icon--blue
.safe-icon--purple
```

图标规则：

```text
图标容器默认 82rpx x 82rpx。
线性图标优先，笔画保持一致。
不要混用实心、线性、emoji、复杂插画图标。
图标只表达入口含义，不做装饰堆叠。
```

推荐图标语义：

```text
情绪日记：书写、笔记、页面。
测一测：表单、勾选、轻量测评。
目标设定：靶心、旗帜。
周报：柱状图、日历。
训练：叶芽、呼吸、路径。
课程：书本。
我的：用户轮廓。
人工督导：对话、备注。
```

## 8. 页面间距规范

页面容器：

```text
.safe-page
.safe-page--with-tabbar
```

间距：

```text
页面左右边距：40rpx
模块间距：40rpx
卡片内边距：28rpx
卡片内元素间距：12-24rpx
列表项间距：18rpx
底部 tabBar 页面建议使用 .safe-page--with-tabbar
```

页面节奏：

```text
首页可以更松，记录页和反馈页要更稳。
表单页不要为了好看压缩输入区。
长页面每 2-3 个模块后用一个轻提示或分隔节奏。
底部最后一块内容必须高于 tabBar，不被遮挡。
```

## 9. 列表项样式

公共 class：

```text
.safe-list
.safe-list-item
.safe-list-copy
.safe-list-title
.safe-list-subtitle
.safe-list-arrow
```

使用规则：

```text
最近记录、我的页面入口、周报条目、复核条目优先用列表项。
列表项保持 104rpx 以上点击高度。
左侧图标，中间文案，右侧箭头或状态。
```

列表项避免：

```text
每条都有大插画。
每条塞 3 个以上标签。
右侧状态过长导致标题换行难看。
```

## 10. 底部导航样式

配置位置：

```text
apps/miniprogram/app.json
```

当前规范：

```text
tabBar 背景：#FFFDF8
选中颜色：#4E7C6B
未选中颜色：#8A8D89
四栏：首页 / 训练 / 课程 / 我的
图标路径：apps/miniprogram/assets/tabbar/
```

页面规则：

```text
不新增第五个 tab。
首页承担“今日陪伴面板”。
训练承担“练习路径”。
课程承担“学习内容库”。
我的承担“记录和支持入口”。
测评、周报、督导等入口放在首页或我的页。
```

## 11. 公共组件

现有公共组件继续保留并接入本设计系统变量：

```text
components/welcome-card
components/function-entry-card
components/training-task-card
components/course-card
components/section-title
components/alert-card
components/bottom-tip-card
```

组件用途：

```text
welcome-card：首页或页面顶部欢迎区
function-entry-card：快速入口、功能入口
training-task-card：训练任务和推荐训练
course-card：课程卡片
section-title：模块标题和“查看全部”
alert-card：成功、提醒、边界、风险提示
bottom-tip-card：页面底部温暖提示
```

组件使用原则：

```text
优先复用，不要为每页新建相似卡片。
如果只是颜色不同，使用变体，不复制一份组件。
如果页面需要特殊结构，先确认是否会破坏现有路径和 API。
```

## 12. 插画和装饰规则

项目适合使用插画，但要克制。

推荐：

```text
浅米白背景
柔和自然光
绿植
书本
记录卡
日历
成长线索
平静交流的家庭场景
```

避免：

```text
大笑卡通人物
夸张治愈光芒
漂浮星星过多
医疗符号
恐慌表情
商业海报式大标题
看起来像 AI 素材库的通用插画
```

插画位置：

```text
首页顶部：可以使用一张主视觉。
记录页顶部：小图即可，不抢表单。
反馈页：用于降低报告感，不覆盖反馈文字。
周报页：可以表达一周复盘，不做成绩单感。
我的页：少用插画，优先清晰入口。
```

## 13. 页面级应用方向

后续改页面时按以下方向执行。

### 首页

```text
保留当前视觉稿的品牌感。
突出“今日状态”和“开始记录”。
快速入口保持 4 个以内。
最近记录和安心小贴士做轻，不抢主任务。
```

### 情绪记录页

```text
降低问卷感。
输入框要舒服，不能太窄。
字段之间有呼吸感。
提示语像陪伴，不像老师布置作业。
```

### 反馈页

```text
不要像诊断报告。
先给一句支持性总结，再分卡片解释。
推荐训练卡只给 1-2 个，不堆列表。
人工督导入口清楚但不制造恐慌。
```

### 训练页

```text
体现路径感。
从稳定情绪到改善沟通。
训练卡不要像课程广告。
按钮文案用“开始练习”，不用“立即提升”。
```

### 我的页

```text
按“我的记录 / 专业支持 / 安全支持 / 设置说明”分组。
列表项清楚，少装饰。
危机支持入口明显但不刺眼。
```

## 14. 后续改页面顺序

后续页面改造应按小步执行：

```text
1. 先选一个页面，不要批量改。
2. 保留原有跳转、API、字段和页面路径。
3. 先整理信息层级，再套样式。
4. 复用 app.wxss 变量和公共组件。
5. 检查没有诊断化、标签化、责备性文案。
6. 在微信开发者工具中人工检查裁切、间距、底部遮挡。
7. 记录问题，再进入下一个页面。
```

## 15. 交付自查清单

每改完一个页面，至少检查：

```text
1. 第一眼是否知道这个页面要做什么。
2. 是否只有一个最重要的主按钮。
3. 是否存在泛泛 AI 文案。
4. 是否用了过多渐变、阴影、装饰。
5. 页面底部是否被 tabBar 遮挡。
6. 文字是否有压缩、溢出或过浅。
7. 是否保留非诊断、非评判边界。
8. 是否没有改 API、数据库和 shared 类型。
```
