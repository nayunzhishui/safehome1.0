# 并行开发任务清单

文档状态：历史任务清单。当前最新进度以 `docs/00_当前事实基准/项目进度统一口径.md` 和 `docs/00_当前事实基准/当前进度交接.md` 为准。

截至 2026-06-01，MVP 1.0 已完成并完成封版验收，MVP 1.1 家长端主闭环与网站后台第一版已完成。本文中“建立骨架、实现基础接口、建立页面”等任务多数已经完成，后续不要把本文件当成当前未完成清单。

## 1. 小程序端任务

目标：让家长在手机端完成“记录 → 识别 → 反馈 → 练习 → 追踪 → 支持”的闭环。

- 建立小程序或 Taro 项目骨架。
- 首页：显示今日目标、记录入口、训练卡入口和周报入口。
- 知情同意页：说明非诊断、隐私和使用边界。
- 目标设定页：选择高频亲子冲突场景，设定 7 天 SMART 小目标。
- 情绪事件记录页：记录事件、情绪强度、自动想法、身体感觉和行为。
- 即时反馈页：展示触发点、互动模式、非诊断解释和替代回应建议。
- UP 训练卡页：展示后端或 mock 推荐的训练卡。
- 练习打卡页：记录是否练习、练习前后情绪强度和简短复盘。
- 周度报告页：展示高频场景、高频情绪、常见回应和下周建议。
- 人工反馈入口：允许提交典型记录给人工督导，第一版可简化为表单。

## 2. 网页端任务

目标：同时支持项目展示、研究管理和人工督导。

- 建立 React/Vite 项目骨架。
- 项目介绍页：展示项目定位、UP 理论基础、核心闭环、MVP 功能和试点招募入口。
- 管理后台首页：展示记录总数、打卡数、人工督导请求数和风险标记数。
- 情绪记录列表：查看家长记录、场景、情绪强度、标签和推荐训练卡。
- 记录详情页：查看单条记录、系统反馈和打卡情况。
- 训练卡管理页：查看和维护训练卡内容。
- 反馈规则管理页：查看和维护关键词、标签、解释和推荐训练卡。
- 人工督导反馈页：查看督导请求，记录人工回复。
- 数据导出页：导出 CSV/Excel 数据。

## 3. 后端任务

目标：为小程序端和网页端提供统一数据源与统一反馈规则。

- 建立 Flask + SQLite 后端骨架。
- 建立第一版 SQLite 数据表。
- 实现目标设定、情绪日记、反馈生成、训练卡推荐、打卡、周报、督导请求和后台导出 API。
- 使用 `content/feedback_rules.json` 生成规则反馈。
- 使用 `content/training_cards.json` 提供训练卡推荐。
- 添加 seed data，生成可演示数据。
- 添加后端 README，说明依赖安装、启动和接口测试方法。

## 4. 共同内容库任务

目标：保证小程序端、网页端和后端共用同一套内容。

- 维护 `content/training_cards.json`。
- 维护 `content/feedback_rules.json`。
- 维护 `content/consent.md`。
- 维护 `content/privacy.md`。
- 明确非诊断反馈表达规范。
- 明确高风险内容转介提示。
- 为后续版本保留内容版本字段。

## 5. 联调任务

目标：验证两端确实共用同一后端和同一内容规则。

- 小程序提交目标后，网页后台可以看到目标记录。
- 小程序提交情绪事件后，网页后台可以看到记录详情。
- 小程序即时反馈结果来自后端规则，而不是前端硬编码。
- 小程序展示的训练卡与网页后台管理的训练卡一致。
- 练习打卡后，周度报告能读取打卡数据。
- 人工督导请求能在网页端出现并记录处理状态。
- 后台导出的数据字段与数据库字段说明一致。

## 6. 测试任务

目标：保证 MVP 能稳定演示和小规模试点。

- 后端接口测试：每个 API 至少覆盖成功提交、缺字段和空数据场景。
- JSON 校验：训练卡和反馈规则必须可被解析。
- 小程序流程测试：目标设定到周报页面能完整走通。
- 网页流程测试：展示页、后台首页、记录列表和导出页面能打开。
- 联调测试：小程序提交内容能在网页后台看到。
- 伦理边界测试：页面不出现诊断化、评判化和承诺疗效表达。
- 演示数据测试：至少准备 5 条模拟记录和对应反馈。
