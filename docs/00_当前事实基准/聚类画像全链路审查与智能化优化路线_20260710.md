# 聚类画像全链路审查与智能化优化路线

更新时间：2026-07-10

## 1. 结论

当前聚类画像的工程闭环已经存在：离线建模 -> 聚合模型 JSON -> 测评结果匹配 -> 数据库存档 -> 小程序/Web 展示 -> 训练卡与人工复核。它适合继续做**受控试点**，但还不适合被描述为稳定、自动、个体化的智能画像系统。

核心原因不是“算法不够复杂”，而是准入状态、线上推断、版本冻结、个体解释和隐私闭环尚未完全一致。先修数据真相和治理，再增加更智能的推荐，收益高于直接更换大模型或增加复杂机器学习。

## 3. 发现的问题

### P0：试点扩大前先处理

1. **模型准入没有在运行时强制执行。** 2026-06-30清单把PRFQ和SCS列为“仅内部审核”，但通用加载器只排除`manual_review_required`；两份量表当前启用且模型link为空，仍可被自动匹配。
2. **通用测评提交信任客户端score。** `POST /api/assessment-results`允许answer携带任意score，也未拒绝重复question_id或核对完整题数；恶意或异常客户端可制造99分、重复计分，并污染画像和研究数据。
3. **部分用户端画像名称仍标签化。** 当前可见候选仍含“情绪波动型、过度确定型、外归因型、困惑回避型、自我批判型”等`display_name`，与项目“阶段性、非人格标签”规则冲突。
4. **研究授权撤回未覆盖关系试点。** 隐私中心没有关系试点专属撤回；研究者dashboard未过滤已撤回用户；个人数据摘要未统计关系报名、报告、任务、连续记录和假设反馈。
5. **学生模型包含逐行派生散点。** `training_points`直接进入API可视化；建议改为簇中心、置信椭圆、密度网格或经过最小单元阈值的聚合点，不向客户端发送466个逐行位置。

### P1：统计与解释质量

1. **任务十二离线GMM与线上分配不一致。** 离线模型使用簇权重、均值和对角协方差；线上只按欧氏距离找中心，忽略协方差与权重。本次复核发现2.4%至7.3%的训练样本分配会不同。
2. **“置信度”是距离启发式，不是校准概率。** 当前百分比容易被用户理解为模型准确率；低置信阈值0.15和离群阈值`1.75*sqrt(p)`没有基于留出样本或经验分布校准。
3. **三份关系模型分离度偏弱。** silhouette约0.12至0.13，说明画像之间有较大重叠；关系调节聚焦的重抽样稳定性尤其弱，不宜自动输出强画像名。
4. **Micro YSQ四簇有重复名称。** 两个偏低簇都叫“关系担心线索相对较少的观察阶段”，产品上无法区分；本质更接近连续严重度分层，而不是四种性质不同的画像。
5. **学生模型k选择缺少冻结依据。** k=2的silhouette高于k=4；若保留k=4，应补理论可解释性、重抽样稳定性、簇最小比例和外部效标证据。
6. **量尺与版本仍有桥接风险。** 关系调节聚焦训练数据1-5、产品问卷1-7；PBC训练使用6题、既往报告常用4题。线性换算不能证明两个版本测量等价。
7. **缺少真正外部验证。** 425与469样本没有稳定行ID，当前只能聚合方向核对；尚无留出样本、独立样本、重测稳定性、测量不变性或后续行为效标验证。

### P1：规则与智能程度

1. 任务十二同一量表内各簇的训练卡、问题、小步行动基本相同，`dimension_z`没有真正驱动问题生成；当前更像“换了画像名的量表级推荐”。
2. 用户对机制假设的“符合/不符合/不确定”已经入库，但尚未用于模型校准、人工覆盖率、解释命中率或后续推荐。
3. 成长报告只做首末差值，没有同版本约束、测量误差、可靠变化区间或不规则时间间隔处理。
4. 模型内容JSON缺少统一的部署状态、审批人、审批时间、训练源hash、代码版本、推断算法版本和弃用关系。

### P1：前端与UI

1. 小程序写“与既往样本的接近度XX%”，但该值不是概率；建议改为“匹配清晰度：低/中/较高”，并显示为什么暂不解释。
2. 通用测评雷达优先画的是**所选簇中心维度**，不是用户本人维度；标题和视觉容易让人误以为是自己的真实轮廓。
3. 散点图使用PC1/PC2，未显示二维解释率；学生端不应暴露内部统计轴，研究端应注明投影仅覆盖35.9%至49.0%方差。
4. 雷达标签存在PROM、PREV、PBC、BI等内部代码；应使用完整中文标签。维度较多时，中性发散条形图比雷达更易比较。
5. 当前五态、阶段状态、边界说明和共同核对控件是正确方向；需要保留，不应重新做一套视觉系统。

## 4. 推荐优化顺序

### 第一批：先把“数据真相”做对

1. 服务端完全忽略客户端score，只允许worksheet定义内的value；拒绝未知/重复题号，按量表策略校验完整性和缺失。
2. 建立模型准入枚举：`internal_only -> pilot_approved -> production_approved -> deprecated`；运行时只加载允许状态。立即把PRFQ、SCS及未签字任务十二模型限制为人工/试点状态。
3. 全部“X型”改成“阶段性位置/当前线索”，模型解释与训练卡需要审批签字后才可被用户看到。
4. 增加关系试点授权撤回、dashboard过滤、个人数据摘要和删除处理清单。
5. 从学生模型删除逐行`training_points`，用聚合密度或置信椭圆替代。

### 第二批：统一训练与线上推断

1. GMM模型保存`weights`、`means`、`diag_covariances`；线上按同一公式计算posterior responsibility。
2. 用最大后验概率、归一化熵和经验马氏距离建立三态：可解释、低确定性、样本外；阈值由重抽样/留出分布校准。
3. 增加100至500次bootstrap/subsample稳定性、簇对齐、置信区间和共识矩阵；不要再把仅换随机种子的ARI写成样本稳定性。
4. 关系调节聚焦优先回退为透明的PROM×PREV连续二维位置；Micro YSQ优先比较连续分数/3层级与4簇；关系主动性保留维度组合并验证k=2。
5. 统一1-5/1-7与PBC4/6版本；无法完成桥接研究时，不跨版本复用常模。

### 第三批：建立可追溯模型注册

建议新增：

```text
profile_model_registry
  model_id, artifact_hash, schema_version, scoring_version,
  assignment_version, training_source_hashes, admission_status,
  approved_by, approved_at, activated_at, deprecated_at

profile_assignments
  assessment_result_id, model_id, artifact_hash, cluster_id,
  posterior, entropy, outlier_score, interpretation_status,
  assigned_at, supersedes_assignment_id
```

历史结果保存不可变快照；升级模型只新增assignment，不在GET请求时静默覆盖旧画像。`/readyz`应在活动模型缺字段、hash不一致或未批准时失败。

### 第四批：做真正个体化但可解释的推荐

先使用确定性策略，不直接让大模型自由解释心理：

```text
用户目标
  + 本人维度偏离及张力
  + 画像确定性/离群状态
  + 风险与授权
  + 最近任务完成和主观帮助度
  + 用户“符合/不符合/不确定”反馈
  -> 推荐1个主任务 + 1个备用任务 + 明确理由
```

当积累足够试点数据后，再用离线策略评估或受约束contextual bandit优化“哪张卡更愿意完成/更有帮助”；禁止用点击率替代心理效果，禁止自动强化高风险内容。

### 第五批：前端改为“证据—解释—行动”

1. 第一屏：本次最重要的两个维度和一个主动作。
2. 第二层：中性发散条形图，显示“本人位置”和不确定区间；不把簇中心画成个人雷达。
3. 第三层：可展开查看群体参照、样本量、模型版本、二维解释率和边界。
4. 报告用“系统计算/规则解释/研究者确认/用户核对”四个来源标签。
5. 低置信、离群或未审批模型只显示维度，不显示画像名和自动训练建议。

## 5. 验收指标

```text
数据完整性：非法score、重复题号、未知题号、缺题提交全部被拒绝。
准入一致性：internal_only模型在API和UI均不可自动解释。
推断一致性：离线与线上同一模型、同一输入的cluster/posterior 100%一致。
稳定性：报告bootstrap ARI中位数及P10，不能只报随机初始化ARI。
解释质量：重复画像名=0；标签化词=0；研究者覆盖率、用户不符合率可监控。
隐私：客户端逐行训练点=0；撤回授权后研究dashboard不可见；个人数据摘要覆盖全部关系表。
UI：用户看到的是本人维度；统计术语有解释；低置信和离群不靠颜色单独表达。
```
