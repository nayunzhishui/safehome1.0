target: SafeHome Web 首页、登录/权限页，以及小程序 37 页代码级视觉体系
goal: 在不改变暖白、低饱和绿和非医疗化风格的前提下，提高试点用户的信任、完成率和页面辨识度

# SafeHome 当前 UI 审查

## 结论

**Needs work。** Web 首页已经具备清楚的品牌首屏和温暖、克制的视觉基础，但登录/注册等关键入口尚未完成同等质量的视觉收口；小程序已有全局 token 和基础组件，却仍存在大量页面级硬编码，导致 37 页容易出现“同为暖色卡片、细节却不一致”的情况。当前应优先修关键入口和设计系统漂移，而不是增加更多装饰图。

## 建议保留

- 暖白背景、低饱和绿、克制橙色和非医疗化表达。
- Web 首页“真实小程序界面预览”的首屏方法。
- 小程序一个页面一个主动作、关系试点五阶段和图表五态。
- 风险提示不只依赖红色，继续配合文字与人工处理动作。

## 推荐视觉方向

### 主题

**“陪伴观察手记”**：界面像一份持续记录、逐步回看的家庭成长手记，而不是测评分数面板或医疗后台。

### 视觉 token

- 松针绿 `#4F7C6B`：主动作与关键路径。
- 深林绿 `#2F5B4D`：标题与高对比文字。
- 纸张暖白 `#FFFDF8`：主要 surface。
- 晨雾灰绿 `#F2F4F0`：页面背景和分区。
- 陪伴橙 `#D98243`：提醒与进度节点。
- 安全红 `#C85F58`：仅用于必须关注的风险状态。

### 字体角色

- 正文与控件：思源黑体 / PingFang SC，保持清晰与可信。
- 报告标题与反思摘录：少量使用思源宋体 / Noto Serif SC，形成“手记”气质。
- 数据与状态：系统无衬线中等字重，使用等宽数字。

### 签名元素

用一条细的“陪伴路径线”连接记录、理解、练习、复盘节点。它只用于首页核心闭环、关系试点阶段和成长报告，其他位置保持安静；不增加全站渐变、拟人 AI 头像或装饰性图标堆叠。

## 必须人工确认

- 小程序真实页面尚未在微信开发者工具、iOS 和 Android 截图检查。
- 当前审查不能证明屏幕阅读器、键盘焦点顺序和实际 WCAG 合规。
- Canvas 的文字替代已通过静态审计，但画布触控、弱网恢复与不同屏幕比例仍需真机。
