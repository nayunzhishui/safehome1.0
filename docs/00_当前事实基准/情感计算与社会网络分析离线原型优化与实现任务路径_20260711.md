# 情感计算与社会网络分析离线原型优化与实现任务路径

更新时间：2026-07-11
适用项目：`safehome1.0 / 安心陪伴 / ReadFeedback`
文档性质：当前事实审查 + 方法优化建议 + 分阶段实施任务路径
运行边界：离线、只读输入、聚合脱敏、非诊断、不进入普通用户端实时推断

## 1. 结论

项目内已经存在可运行的情感计算与网络分析雏形，但当前更准确的状态是：

```text
代码骨架已存在
脱敏输出边界已建立
专项测试可通过
真实数据分析质量尚未验证
两种“网络”概念仍混在同一SNA口径下
```

当前不需要直接增加深度学习或大模型。优先工作应是：

1. 明确三类分析对象；
2. 冻结数据和隐私口径；
3. 合并重复实现；
4. 修正情感规则、边权和撤回过滤；
5. 建立人工标注与外部效标验证；
6. 达到准入门槛后再提供研究者只读展示。

## 3. 三类分析必须重新命名

当前“SNA”同时指两种完全不同的网络，应拆成三条任务线。

| 名称 | 节点 | 边 | 正确定位 | 是否面向用户 |
|---|---|---|---|---|
| 情感计算 | 文本记录中的情绪线索 | 无 | 情绪词、效价、唤醒、强度和时间变化 | 仅在验证后展示简化摘要 |
| 语义共现网络 | 人物、场景、想法、情绪、行为、结果概念 | 同句、同字段或同记录共现 | 反射弧概念网络，不是真实社会关系网络 | 普通用户不展示复杂图 |
| 家庭关系拓扑审计 | 经授权的家长、学生或支持角色 | 已确认的结构化关系 | 家庭绑定数据质量和结构摘要，才属于狭义SNA | 仅研究者内部使用 |

后续文档和界面中：

- `build_social_network.py` 对应内容应称为“语义共现网络”或“情绪反射弧概念网络”；
- `social_network_prototype.py` 应称为“家庭关系拓扑审计”；
- 不得把文本中提到“妈妈、老师、同学”直接解释成真实社会关系强度。

## 4. 已确认问题

## 4.1 数据与可重复性

### 问题1：两套重复原型

`analysis/profiling` 和 `analysis/text_analysis` 分别实现了情感和网络分析，输入、命名、输出目录和算法不同。

影响：后续维护者无法判断哪套是当前真相，可能重复运行并得到不可比较的结果。

### 问题2：早期原型写死绝对路径

默认输出依赖本机：

```text
D:/codex/workspace/safehome1.0其他内容/...
```

影响：其他设备、CI和云端分析环境无法复现。

### 问题3：离线分析调用 `init_db()`

离线分析应把输入视为不可变原始快照。当前主脚本会初始化数据库，理论上可能改变分析源环境。

建议：改为只读数据库连接，或读取经过授权、带哈希的分析快照。

### 问题4：缺少运行清单

当前输出没有完整记录：

- 输入文件或数据库快照 hash；
- 词典 hash；
- 代码提交；
- Python和依赖版本；
- 分析参数；
- 随机种子；
- 最小单元抑制规则；
- 质量验证结论。

## 4.2 情感计算方法

### 问题1：否定没有处理

合成验证中：

```text
“我不生气”
“我生气生气”
```

当前得到相同的愤怒、效价、唤醒和强度结果。

原因：

- 没有否定窗口；
- 分词结果被转换为集合，重复信息被删除；
- 没有程度副词和转折规则。

### 问题2：聚合口径不可直接比较

`intensity_signal_score` 是所有命中词强度之和，会随记录数和文本长度增长；不同用户、不同周之间不能直接比较。

### 问题3：不同文本来源混合

用户日记、系统支持性反馈和督导回复可以同时进入情感聚合。即使记录了 `source_type_counts`，总体效价仍可能混合不同写作者的语言。

### 问题4：无法进行纵向验证

当前分析记录只保留来源和文本，没有保留分析所需的匿名记录ID、匿名用户ID、时间、温度计值、训练前后关联和波次。

影响：无法验证文本效价是否与温度计愉悦度、唤醒度和强度一致，也无法建立可靠的个人时间趋势。

### 问题5：词典覆盖不足

26 个情绪词只能用于代码演示，不能支持正式中文情感分析。当前没有覆盖率、人工标注准确率、否定准确率和类别F1报告。

## 4.3 语义共现网络方法

### 问题1：整条记录两两连边导致团块偏差

一条记录中所有命中节点会形成近似完全图。文本越长，边越多，无法区分真正相邻或同一反射弧段的关系。

### 问题2：边权方向用于介数中心性时相反

当前：

```python
nx.betweenness_centrality(graph, weight="weight")
```

NetworkX 在最短路径中把 `weight` 当作距离。项目中的高权重表示高共现，理论上应该是更近，而当前计算会把它当作更远。

应改为：

```text
distance = 1 / (cooccurrence_weight + epsilon)
```

再用 `distance` 计算介数。

### 问题3：高频概念支配网络

当前只按共现次数建边，没有使用文档频率、Jaccard、PMI/nPMI或最小支持度，常见词会主导中心性。

### 问题4：反射弧链条选择不稳定

同一反射弧节点出现多个词时，当前逻辑可能只保留集合迭代遇到的第一个词，缺少明确、稳定的选择规则。

### 问题5：社区没有稳定性门槛

小图和稀疏图也会输出社区编号，但尚未报告不同阈值和重抽样下的社区稳定性。

## 4.4 家庭关系拓扑方法

### 问题1：已撤回关系仍会进入图

合成验证表明，`status=revoked` 的关系仍会计入边数和图结构。

### 问题2：哈希节点仍可能被关联

固定、无盐、截断的用户ID哈希会在不同运行中保持一致。对于规模很小的家庭图，即使没有姓名，也可能被结合其他信息重新识别。

### 问题3：当前结构过于稀疏

现有 `family_links` 主要是家长—学生绑定，常见情况是一户一条边。此时中心性、社区和“关键节点”没有足够研究意义。

### 问题4：不能从拓扑推断关系质量

绑定关系只说明系统账号关联，不能证明亲密度、支持度、冲突、控制或家庭功能。

## 4.5 隐私与权限

1. 通过 `--user-id` 运行时，当前输出的 `filters.user_id` 可能写入真实用户ID。
2. 聚合结果尚无最小单元阈值；少量记录的稀有词和边仍可能间接识别个体。
3. 输出没有授权状态、数据范围和撤回过滤摘要。
4. 后端只读接口没有输出新鲜度、输入版本和质量状态。
5. 高风险关键词必须继续走 `risk_review_records`，不得由情感得分或网络中心性替代。

## 4.6 测试与产品接入

当前专项测试已经验证：

- 脚本可执行；
- 有合成记录时能命中情绪和节点；
- 输出不包含测试原句；
- `raw_text_included=false`。

当前尚未验证：

- 否定、程度副词、重复、转折和多义词；
- 词典覆盖率和类别准确率；
- 效价/唤醒与温度计的一致性；
- 语义网络边权和中心性正确性；
- 社区和Top节点稳定性；
- 撤回授权和小单元抑制；
- 真实数据下的有效性；
- Web研究者页面。

## 6. 实现任务路径

## S0：定义、冻结和基线

### AC-SNA-00 冻结分析目的与禁用用途

目标：明确三条分析线，不再用一个“SNA”名称承载不同概念。

动作：

1. 冻结情感计算、语义共现网络和家庭拓扑审计定义。
2. 明确研究问题、允许输出和禁止输出。
3. 明确不用于诊断、危机预测、人格判断、关系质量打分和自动惩罚。
4. 把任何新增探索标为 exploratory，不与主要结果混写。

验收：三个概念在代码、文档、产物和界面中名称一致。

### AC-SNA-01 冻结数据范围与授权规则

目标：建立唯一文本来源和关系来源清单。

动作：

1. 校正 `supervision_requests.reply` 与真实字段 `supervisor_reply` 的文档差异。
2. 明确每个来源的写作者：用户、系统、督导或研究者。
3. 用户文本、系统反馈和督导回复分层分析，不混合总效价。
4. 明确授权、撤回、保留期、最小单元阈值和允许用途。
5. 家庭拓扑只纳入 `status=confirmed` 且未撤回的关系。

验收：代码清单与文档清单逐项一致；撤回数据不会进入分析快照。

### AC-SNA-02 建立基线缺陷测试

目标：先把当前已确认缺陷固定成失败测试。

至少包含：

```text
否定：不生气
程度：非常生气 / 有点生气
重复：生气生气
转折：虽然着急，但后来平静了
无情绪：今天完成了一次记录
多来源分层：用户文本与系统反馈不混合
高权重边使用反距离
已撤回家庭边被排除
真实user_id不出现在产物
小单元不输出稀有节点和边
```

验收：修复前测试准确暴露问题，后续每项修复都有对应回归测试。

## S1：统一输入与可重复运行

### AC-SNA-03 建立只读输入适配器

目标：原始数据不可变。

动作：

1. 不再由分析脚本调用 `init_db()`。
2. 提供 SQLite 只读适配器和脱敏快照适配器。
3. MySQL/CloudBase 不直接由个人脚本读取原文，优先生成经授权的只读分析快照。
4. 输入文件记录大小、行数、表数和 SHA-256。

验收：分析运行前后源数据库 hash 或数据状态不变。

### AC-SNA-04 建立规范化分析契约

目标：保留时间、来源和外部效标，最终仍不输出原文。

动作：

- 建立规范化记录 schema；
- 保留时间、来源、匿名范围、温度计和训练前后关联；
- 对未知缺失码、非法日期、重复记录和空文本进行审计；
- 输出参与者流程、来源计数和缺失摘要。

### AC-SNA-05 建立分析manifest

目标：相同输入和版本可重复运行。

manifest至少包含：

```text
run_id
generated_at
git_commit
python_version
package_versions
source_hashes
dictionary_hashes
analysis_version
parameters
random_seed
privacy_rules
record_counts
quality_status
```

验收：除生成时间外，相同输入与配置产生相同聚合结果 hash。

### AC-SNA-06 收敛重复原型

目标：`analysis/text_analysis` 成为唯一真相。

动作：

1. 移除早期原型的绝对输出路径。
2. 早期情感原型改为主路径兼容入口。
3. 早期SNA原型重命名语义为家庭拓扑审计。
4. 保留兼容入口，不立即删除旧文件。

## S2：情感计算优化

### AC-SNA-07 词典治理

目标：词典可授权、可追溯、可评审。

动作：

1. 记录词典名称、版本、来源、许可证、转换脚本和 hash。
2. 未获授权的完整 DLUT/BosonNLP 词库不入仓。
3. 项目自定义人物、场景、行为和反射弧词典建立人工审核表。
4. 同义词、歧义词和领域词分开维护。
5. 建立词典覆盖率报告。

### AC-SNA-08 文本规范化与规则引擎

目标：在保持可解释的前提下修正基础语言现象。

动作：

1. Unicode和标点规范化；
2. 句子级切分，不再整条记录直接成图；
3. 否定窗口；
4. 程度副词权重；
5. 重复和感叹符号作为可选强度线索；
6. 转折词前后分段；
7. 每个命中保留规则来源，但不输出原句；
8. 规则异常和零覆盖有明确状态。

### AC-SNA-09 分层与纵向聚合

目标：支持可比较的趋势，不把记录数量当情绪变化。

动作：

- 用户、系统、督导文本分别汇总；
- 每条记录先标准化，再按日/周聚合；
- 同时报告记录数、有效匹配数和覆盖率；
- 强度同时提供每记录均值和每千字标准化值；
- 个人趋势至少需要预先定义的最小记录数；
- 缺少足够记录时返回 `insufficient_data`；
- 训练前后变化只作描述，不写成疗效证明。

### AC-SNA-10 情感计算验证

目标：证明规则至少能稳定识别项目中的基础情绪线索。

验证数据：

1. 无敏感信息的合成单元句；
2. 经授权、脱敏、保存在安全环境中的人工标注片段；
3. 情绪温度计的愉悦度、唤醒度和强度作为外部效标；
4. 两名标注者独立标注并报告一致性。

建议报告：

```text
词典覆盖率
各情绪类别precision/recall/F1
macro-F1
否定与程度规则准确率
效价与温度计愉悦度Spearman相关
唤醒与温度计唤醒度Spearman相关
强度MAE或等级一致率
标注者Kappa/ICC
```

建议试点准入门槛需由统计负责人冻结。未达到门槛时只保留内部探索，不面向用户解释。

## S3：语义共现网络优化

### AC-SNA-11 字段感知的反射弧节点提取

目标：利用项目已有结构字段，而不是把整段文本做无差别词袋。

建议映射：

```text
scene/event_description → 诱因、人物、场景
automatic_thought → 想法
body_sensation → 身体感觉
parent_emotion/brief_text → 情绪
behavior → 行为
checkin/reflection → 结果与复盘
```

同一反射弧节点出现多个词时，使用确定性排序或保留全部有效路径，不依赖集合迭代顺序。

### AC-SNA-12 共现窗口和边权

目标：减少长文本形成完全图的偏差。

动作：

1. 优先句子级和字段级窗口；
2. 记录 `document_frequency` 和 `cooccurrence_count`；
3. 同时比较 Jaccard、PMI/nPMI 和原始计数；
4. 设最小文档频次和最小边支持度；
5. 稀有节点和边进入抑制，不向接口输出；
6. 边保留反射弧方向，例如“诱因→情绪”“情绪→行为”。

### AC-SNA-13 修正图指标

目标：图指标与业务含义一致。

动作：

- 加权度使用 strength；
- 介数中心性使用 `distance=1/(weight+epsilon)`；
- 特征向量中心性只在图满足连通性和收敛条件时报告；
- 社区算法记录版本和随机种子；
- 图过小或过稀时不输出中心性排名和社区解释。

### AC-SNA-14 网络稳定性

目标：避免偶然词和边被解释为稳定模式。

动作：

1. 按记录bootstrap或时间窗重抽样；
2. 比较Top节点/Top边Jaccard；
3. 比较社区NMI/ARI；
4. 对不同最小边权和nPMI阈值做敏感性分析；
5. 低稳定性网络只输出计数，不输出解释。

## S4：家庭关系拓扑审计

### AC-SNA-15 关系边准入

目标：只分析有效、授权的结构关系。

动作：

- 只纳入 `status=confirmed`；
- 排除 `revoked_at` 非空记录；
- 按生效与撤回时间构建时间切片；
- 去除重复边、自环和异常角色组合；
- 记录授权与撤回过滤数量。

### AC-SNA-16 去标识与小图保护

目标：家庭结构不能因节点哈希而被间接识别。

动作：

1. 使用运行级或项目级HMAC伪名，密钥不入仓；
2. 对外产物不输出节点列表和逐边哈希；
3. 仅输出满足最小单元阈值的组件大小、度分布和聚合计数；
4. 小样本家庭图只用于数据质量审计，不展示中心性；
5. 不跨运行公开稳定伪名。

### AC-SNA-17 家庭拓扑可用性判断

目标：数据不足时明确停止分析。

判断规则：

- 如果绝大多数连通分量只有2个节点和1条边，只报告绑定覆盖率和异常率；
- 只有存在经授权的多角色、多关系或时间互动数据时，才评估更复杂拓扑；
- 不从日记文本提到的人物自动创建真实家庭关系边；
- 不根据度数或中心性评价家庭关系好坏。

## S5：隐私、质量和输出治理

### AC-SNA-18 小单元抑制

目标：聚合结果不能暴露稀有个体线索。

建议默认：

```text
节点文档频次 < k：不输出
边共同文档数 < k：不输出
分组记录数 < k：不输出具体值
```

`k` 由伦理和统计负责人冻结，试点阶段建议至少评估 5 和 10 两档敏感性。

### AC-SNA-19 自动隐私扫描

每次运行检查：

- 原始句子片段不存在；
- 真实 user_id、手机号、邮箱和微信标识不存在；
- `filters.user_id` 不写真实ID；
- 原始记录ID不存在；
- `raw_text_included=false`；
- 输出只包含允许字段；
- 已撤回用户贡献为0。

### AC-SNA-20 质量状态

每份产物增加：

```text
available
quality_status
freshness_status
insufficient_data_reasons
source_hashes
dictionary_hashes
analysis_version
privacy_gate_passed
```

状态至少包括：

```text
valid
empty
insufficient_data
stale
validation_failed
privacy_blocked
```

空数据文件不得继续只显示 `available=true`。

## S6：研究端接入

### AC-SNA-21 后端只读接口升级

目标：只读接口能说明产物是否可用，而不是只判断文件是否存在。

动作：

- 校验manifest、hash、质量和隐私状态；
- 仅允许管理员和研究者；
- 敏感摘要查看写审计；
- 不允许接口临时分析数据库原文；
- 无效产物返回明确状态和重新生成提示。

### AC-SNA-22 Web研究页

第一版只展示：

```text
数据范围和生成时间
来源分层计数
词典覆盖率
情绪类别和效价/唤醒趋势
语义网络Top节点/边及稳定性
家庭拓扑是否具备分析条件
质量状态、隐私状态和边界说明
```

不展示：

- 原始文本；
- 真实或稳定伪名；
- 单个家庭逐边关系图；
- “高危、病理、人格、控制型家庭”等标签；
- 未通过验证的复杂社区解释。

### AC-SNA-23 普通用户端边界

普通用户端第一阶段不展示复杂网络图。若未来开放简化摘要，只允许：

```text
最近记录中更常出现的情绪线索
经常一起出现的场景和情绪
可以尝试的一项练习
数据不足时明确不解释
```

所有内容必须标明“自我观察线索，不构成诊断或风险预测”。

## S7：自动化与验收

### AC-SNA-24 测试矩阵

单元测试：

- 分词、词典、否定、程度、重复、转折；
- 记录级和周期级聚合；
- 边权、反距离、中心性和社区；
- confirmed/revoked关系过滤；
- HMAC伪名和小单元抑制；
- manifest和hash稳定性。

集成测试：

- SQLite只读快照；
- 脱敏导出快照；
- 三类聚合产物；
- 后端鉴权、质量状态和隐私字段；
- Web研究页空、少、正常、过期、失败五态。

### AC-SNA-25 重跑与数字核对

要求：

1. 从干净输入重新运行；
2. 对账每个文档和界面数字与生成产物；
3. 不手工修改数值输出；
4. 失败收敛、低覆盖、低稳定性和空结果如实保留；
5. 主要、次要、探索和敏感性结果分开写。

### AC-SNA-26 最终验收门槛

| 类别 | 验收要求 |
|---|---|
| 原始数据 | 不修改，输入有hash和来源清单 |
| 隐私 | 原文、真实ID和撤回数据均不进入产物 |
| 可重复 | 相同输入与版本产生相同结果hash |
| 情感计算 | 有覆盖率、人工标注准确性和外部效标报告 |
| 语义网络 | 边权含义正确，有阈值和稳定性报告 |
| 家庭拓扑 | 只纳入有效关系，数据不足时停止解释 |
| 接口 | 管理员/研究者鉴权，质量状态明确 |
| 用户端 | 不展示复杂网络和诊断化解释 |
| 风险 | 继续由独立风险规则和人工队列处理 |

## 11. 伦理和解释边界

本任务路径只用于离线研究方法和支持性产品探索，不构成心理诊断、临床筛查、危机预测、治疗效果证明、人格判断或家庭关系质量评价。

情感计算只能描述“文本中出现的线索”；语义网络只能描述“概念在记录中共同出现”；家庭拓扑只能描述“经授权的结构化绑定关系”。三者均不能替代人工复核和专业判断。
