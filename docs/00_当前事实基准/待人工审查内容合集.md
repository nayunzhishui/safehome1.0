## 1. 使用规则

1. 自动测试通过不等于人工审查通过。
2. 未在本文登记“审核人、日期、证据、结论”的事项不得改为已通过。
3. 量表、模型、伦理、CloudBase、真机、研究方案和外部平台事项不能由 Codex 代签。
4. 发现问题时记录具体题号、页面、设备、接口或模型版本，不只写“有问题”。
5. 涉及诊断、筛查、人格、危机、未成年人、关系解释或医疗语义时，默认从严处理。

状态枚举：`待审查 / 审查中 / 有条件通过 / 通过 / 不通过 / 暂缓`。

## 7. 产品体验、视觉和无障碍

### 7.1 小程序重点页面

设备至少覆盖一台 iOS 和一台 Android，另加窄屏模拟。每页记录“看不懂、点不动、不舒服”。

| 页面 | 重点检查 |
|---|---|
| 首页 | 入口顺序、人工支持、错误与空状态不混淆 |
| 登录/注册 | 微信、手机号、账号密码、失败恢复 |
| 测一测/详情/结果 | 长题长选项、进度、Canvas、低置信/待批准状态 |
| 情绪温度计 | 拖动、曲线、日内多次记录和屏幕适配 |
| 个性化方案 | 阶段、频率、日期、目标保存和恢复 |
| 项目列表/详情 | 测量计划、草稿恢复、正式提交和边界 |
| 关系试点/报告/任务/成长 | 权限、长图、绘画触控、叙事、时间轴 |
| 训练/课程/打卡 | 触控尺寸、推荐来源、完成/跳过状态 |
| 我的/人工支持/隐私 | 入口密度、非实时边界、撤回/删除说明 |
| debug/integration-test | 仅开发使用，不作为正式用户入口 |

### 7.2 Web 重点页面

| 页面 | 重点检查 |
|---|---|
| `/login`、`/register`、`/family` | 主按钮、键盘焦点、错误 live region、移动端布局 |
| 权限不足与 404 | 不暴露内部角色代码；有明确下一步 |
| `/dashboard`、研究者仪表盘 | 权限、退出、加载/空/错状态、敏感信息 |
| 画像和图表 | 等价文本、内部 code、低置信和待批准状态 |
| 导出/审核/复核 | 二次确认、脱敏、操作审计和触控尺寸 |

通用通过标准：无横向滚动和遮挡；主要操作等效不少于 44px；键盘焦点可见；减少动态效果设置生效；错误可恢复；Canvas/图表有等价文字；无诊断化、标签化或责备文案。
