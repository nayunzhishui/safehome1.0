总体判断：核心闭环、研究者后台、测评画像、关系试点和离线分析已有完整骨架，当前主要风险不在“缺页面”，而在身份边界、数据库唯一性、运行可观测性、前端状态完整性和持续集成门禁。任务十六优先修复可自动验证的问题；CloudBase、真机、量表版权、模型外部效标和研究伦理继续由人工验收。

## 2. 分专业审查发现

### 2.1 产品体验

1. 首页和项目入口已覆盖核心链路，但登录、注册、家庭绑定、权限不足等低频关键页面的视觉和状态一致性弱于主后台。
2. 网络失败与“暂无数据”在部分页面中仍可能被用户理解为同一状态，需为失败提供原因和重试动作。
3. `pending_approval` 已进入画像契约，但所有展示端必须持续保持“待审核时不输出明确画像结论”的统一语义。
4. 研究者能力必须以服务端角色为准，前端本地角色只能用于导航提示，不能作为权限证据。

### 2.2 视觉、交互与无障碍

1. Web 登录、注册和家庭绑定使用了未定义或语义不稳定的 `pill` 类，按钮层级不统一。
2. 全局缺少完整的 `:focus-visible`、`prefers-reduced-motion` 和跳转到主要内容能力。
3. 图表、状态徽标和异步加载需要可读文本替代及 `aria-live` 状态区域，不能只依赖颜色或 Canvas。
4. 交互控件需维持至少 44px 的稳定触控尺寸；长中文和错误信息不得挤压按钮。

### 2.3 前端工程

1. Web 已有按页懒加载和 API client，但 `package.json` 缺独立 `typecheck` 命令，CI 也未把 Web 类型、小程序静态检查作为明确门禁。
2. 登录后的身份应由 `/api/auth/me` 再确认，避免仅信任本地存储的角色和用户信息。
3. ECharts 仍产生大包告警；本轮记录为性能债，不在安全修复中贸然更换图表架构。
4. 页面错误态、重试、键盘焦点和动态状态播报需要统一最低标准。

### 2.4 后端与 API

1. 新路由多已使用 `resolve_actor_user_id`，但 `routes/utils.py` 的旧 helper 仍允许请求参数参与所有权判断，存在遗留身份边界不一致。
2. CloudBase 身份头必须通过显式部署开关启用；本地或普通公网请求不能仅凭可伪造请求头获得微信身份。
3. API 缺统一请求 ID、响应头和耗时日志，不利于联调、审计和故障定位。
4. `/healthz`、`/readyz` 应保持最小公开信息；详细内部状态只用于受控运维场景。
5. 写接口的幂等键覆盖不完整，本轮先不跨模块大改，列入后续按业务切片实施。

### 2.5 SQL 与数据库

1. `users.username`、`wechat_openid`、`phone_hash` 目前只有普通索引，身份字段缺数据库唯一约束。
2. 在旧库直接创建唯一索引可能因历史重复值失败，必须先提供重复数据预检，禁止静默合并账号。
3. `records` 的常用访问模式是 `user_id + module_type + source_id + created_at`，现有索引仅覆盖 `module_type + created_at`。
4. SQLite/MySQL 迁移与重连仍需真实环境验证；本轮只做可回滚的 schema/预检和自动测试，不冒充生产迁移完成。

### 2.6 模型与离线分析

1. 任务十四已完成模型准入、artifact hash、GMM 推断一致性、逐行点移除和离线只读输入。
2. 仍缺授权完整词典、双人标注、F1、独立样本和外部效标；这些属于人工研究验证，不接入普通用户实时解释。
3. 聚合来源 manifest 已建立，后续数据产物必须继续禁止绝对路径、稳定身份和逐行原始点。

### 2.7 技术规范与交付

1. 当前 `check_all.ps1` 能覆盖主要本地门禁，但 CI 与本地门禁尚未完全一致。
2. 需要为请求追踪、唯一约束预检、身份头策略和前端状态增加自动测试。
3. 正式发布前仍需 CloudBase、微信开发者工具、iOS/Android、真实研究者账号、备份恢复和 MySQL 演练证据。

## 3. 自动优化优先级

| 优先级 | 工作包 | 自动化交付 | 不自动完成的边界 |
|---|---|---|---|
| P0 | 身份与所有权 | CloudBase 头显式信任策略、旧 helper 收口、服务端身份测试 | 云托管网关配置、真实微信登录 |
| P0 | 数据一致性 | 身份字段重复预检、唯一索引策略、records 复合索引 | 历史重复账号人工处置、生产迁移 |
| P1 | 可观测性 | 请求 ID、响应头、耗时日志、最小健康状态 | 外部日志平台和告警值班 |
| P1 | 关键页面体验 | 登录/注册/家庭绑定/权限不足视觉与状态修复、焦点与减少动效 | 真机视觉签字和用户测试 |
| P1 | 前端可信状态 | `/auth/me` 复核、失败/空态区分、文本替代 | 正式账号与全设备验收 |
| P1 | 工程门禁 | Web typecheck 脚本、CI 同步小程序静态检查、专项测试 | 云端发布权限和密钥配置 |
| P2 | 性能与长期架构 | ECharts 拆包、全业务幂等、迁移 runner、MySQL 重连 | 本轮不做大范围重构 |

## 4. 实施原则

1. 一次只完成一个工作包，每包完成后运行专项测试并回填任务十六状态。
2. 身份边界以服务端 token/actor 为准；开发环境兼容 `demo-parent`，生产环境禁止降级。
3. 唯一约束先审计、后建索引；发现重复数据即阻断并输出匿名数量，不自动删改用户。
4. 前端状态必须同时具备视觉、文字、键盘和读屏语义。
5. 不删除核心 API、数据库字段、内容库或 `pages/integration-test/index`。
6. 自动测试通过不替代 `待人工审查内容合集.md` 中的人工签字。
