## 6. 文档阅读规则

后续阅读 Markdown 时按以下顺序判断，避免被历史规划或原始问题描述误导：

1. 先看 `docs/00_当前事实基准/项目进度统一口径.md`：判断当前真实完成状态。
2. 再看 `docs/00_当前事实基准/当前进度交接.md` 最新章节：判断最近一轮做了什么、还剩什么。
3. 涉及具体任务时，看对应执行清单的“任务总览”表，不要只看前面的“当前问题”原始描述。
4. 涉及接口、字段和导出时，看 `docs/03_技术真相/API接口文档.md`、`docs/03_技术真相/数据库字段说明.md`、`docs/03_技术真相/数据字典.md`。
5. 涉及部署、CloudBase、备份、提交时，看部署联调类文档。
6. 涉及学生、风险、隐私、研究导出、试用时，看伦理试用类文档。

历史规划类文档如果写着“需要建立”“建议新增”“当前问题”，不代表当前仍未完成；必须回到本文档、最新交接和任务总览表确认。
