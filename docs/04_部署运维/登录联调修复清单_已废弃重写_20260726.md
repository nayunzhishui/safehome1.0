# 微信登录 / 手机号登录 联调策略(0726 重写版)

> ## ⚠️ 废弃声明
> **此前的《登录联调修复清单》已废弃,请勿照其配置。**
> 旧清单建议设置 `TRUST_CLOUDBASE_IDENTITY_HEADERS=1` 来"绕过网络问题快速联通登录"。这是**错误且有安全风险**的做法:
> - 任务36 F10 已验证:CloudBase 默认公网入口**可能允许伪造 `X-WX-OPENID` / `X-WX-SOURCE` 等身份头**;
> - 当前代码在**未配置 `WECHAT_APPID` 时仍可能跳过 AppID 核对**(见《修改意见》P1-01,`auth.py` appid 比对短路);
> - 两者叠加 → 直接开启可信身份头 = **身份冒用风险**。
>
> 因此下述为正确策略,取代旧清单。

---

## 一、核心原则(不可退让)

1. **默认保持 `TRUST_CLOUDBASE_IDENTITY_HEADERS=0`**。
2. **微信登录走服务端 `jscode2session`**(前端拿 code → 后端用 AppID+Secret 换 openid/session_key),不信任任何客户端传入的身份头。
3. **真正要解决的是"CloudBase 容器访问微信 API 的网络出口"**——这是登录跑不通的根因,不是靠信任头绕过。
4. 只有在**证明请求无法绕过可信网关、且 AppID 强制匹配**之后,才可考虑可信身份头模式(且即便那时,`WECHAT_APPID` 为空必须拒绝该路径)。

---

## 二、正确排障顺序(P0:先让登录真实跑通)

### 1. 微信登录 jscode2session 网络出口
- 现象:按钮能点、点击后报错——多为后端 `jscode2session` 请求发不出去/超时。
- 排查:在 CloudBase 容器内确认能否出网访问 `api.weixin.qq.com`;若容器默认无公网出口,需按 CloudBase 文档开通**固定出口/NAT 网关或 API 白名单**。
- 验收:后端日志里 `jscode2session` 返回 openid(不落原文到日志,只记成功/失败 + request_id)。

### 2. 手机号登录:资质、隐私与 access_token
- 手机号解密需要 `access_token`(经 `getAccessToken`),同样依赖上一条的网络出口。
- 现象核对:手机号只存 HMAC-SHA256 摘要、响应仅回掩码、日志不落原文——这条护栏已在代码中,勿破坏。
- 验收:授权手机号后能建立/绑定账号,且库中无明文手机号。

### 3. 云端读取闭环(登录之外,但同属"真实闭环")
消息、训练记录、历次反馈、研究者仪表盘的**云端读取**要能通,不再出现"服务端加载失败"。

### 4. CloudBase schema 029 迁移与恢复验证
上线前跑 `2026_07_26_029` 迁移 + 备份/恢复演练(F18 已有迁移恢复矩阵可复用)。

### 5. 参与者 / 研究者双账号完整联调
两个真实账号跑通端到端。

---

## 三、验收标准(达标才算登录闭环)

- 微信**首次登录、重复登录、拒绝授权、token 过期**四条路径均正常。
- 研究者发送消息后,参与者**真实收到**。
- 训练记录、阶段反馈、成长仪表盘**不再出现服务端加载失败**。
- 所有失败都返回 **`request_id` + 可操作提示**(不是裸 500 或英文栈)。

---

## 四、配置项对照(务必按此)

| 配置 | 正确值 | 说明 |
|---|---|---|
| `TRUST_CLOUDBASE_IDENTITY_HEADERS` | `0`(默认) | 不信任客户端身份头 |
| `WECHAT_APPID` | **必填** | 走 jscode2session;信任头模式下为空必须拒绝 |
| `WECHAT_SECRET` | **必填(密钥管理)** | 不落 git、不进日志/异常栈 |
| CloudBase 容器出口 | **需开通** | 访问 `api.weixin.qq.com` 的网络出口是登录根因 |
