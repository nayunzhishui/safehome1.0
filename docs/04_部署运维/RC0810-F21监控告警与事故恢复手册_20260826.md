# RC0810-F21 监控、告警与事故恢复手册

日期：2026-08-26

## 1. 权威机器政策

`config/rc0810/operations_reliability_policy.json` 是 F21 的机器事实源，登记 health 权限、SLI/SLO、告警、回滚、事故、演练、性能、成本和账号连续性。本文只说明执行顺序；阈值以机器政策为准。

## 2. Health 边界

- 公开 `/healthz` 只返回 `ok/service/version`。
- `/healthz/deep` 与 `/readyz` 只允许内部 socket 源地址，或携带 `X-Operations-Token`；不以转发来源头授信。
- 受保护探针只读检查数据库、Redis、队列、内容、scheduler 和部署一致性，不执行迁移。
- 运维令牌只能保存在外部 Secret 管理，不得写入仓库、日志或截图。

## 3. 三类回滚

代码版本：停止放量，按 digest 选择上一已验证镜像，部署后核对受保护 health、错误率和副作用账本；不得自动反向迁移数据库。

数据库迁移：先停写和保全证据，在隔离目标恢复，优先向前修复；逐项比较 schema head、数量、ID、归属和 Consent 后由真人批准恢复。禁止自动删表回滚。

内容 artifact：关闭发布，选择上一已验证 artifact，复核 hash/manifest，清缓存并重放合成边界案例；历史结果继续使用作答时快照。

## 4. P0 事故

心理内容误发、跨对象泄露、删除失败、错误高风险反馈和外部消息误发均立即停止对应入口并按政策通知负责人。事件记录只写影响代码、时间线、证据引用、决策和后续动作，不写参与者正文、回答、消息正文或凭据。

恢复必须完成：受影响对象和主体清点、审计/发送/删除账本核对、修复证据、真人批准。自动化不得自行恢复生产入口。

## 5. 演练和 NO-GO

`python backend/scripts/run_rc0810_f21_isolated_drills.py` 只做本地隔离政策注入，覆盖 5xx、DB/Redis 中断、队列积压和内容版本错误；它不修改生产资源，也不能替代真实测试云演练。

以下任一项成立时保持 NO-GO：受保护 health 未授权可读；任一 P0 告警或恢复失败；性能预算超限；成本达到 100% 且未执行降级；少于两个独立控制面管理员；operations owner、测试云观察或账号恢复演练未完成。
