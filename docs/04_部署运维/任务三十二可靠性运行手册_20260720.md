# 任务三十二可靠性运行手册

更新时间：2026-07-20

## 1. 适用范围

本手册覆盖登录、记录提交、反馈生成、训练计划、消息、训练记录、研究者仪表盘、研究队列和 AI 合成沙盒九条旅程。观测仅保存 `request_id`、角色范围、模块、结果、HTTP状态码、错误码、时延、重试和恢复状态，不保存参与者原文、令牌、Cookie、请求正文或响应正文。

本地测试通过只表示工程机制可运行。测试云连续观察、CloudBase 网关链路、MySQL 备份恢复、微信开发者工具、Android/iOS 真机、值班负责人和安全隐私伦理复核仍是外部门禁。

## 2. 告警分级

| 级别 | 触发示例 | 首要动作 | 恢复时间目标 | 人工负责人 |
|---|---|---|---|---|
| P0 | 安全、隐私、数据完整性事件或服务整体不可用 | 关闭相关写开关、保留审计、隔离影响范围 | 人工负责人确认后冻结 | 待指定 |
| P1 | 核心旅程明显退化但暂无直接安全影响 | 停止扩大比例、检查错误码和死信、准备回滚 | 测试云观察后冻结 | 待指定 |
| P2 | 局部退化或可恢复积压 | 降低比例、恢复死信、跟踪下一观察窗 | 测试云观察后冻结 | 待指定 |

任何级别都不能由系统替人工负责人作出上线或伦理决定。

## 3. 发现、止损与恢复

1. 通过 `X-Request-ID` 串联入口、API、审计和云网关证据。
2. 检查九条旅程的成功率、P50/P95、错误率、5xx/502/401/403、重试率和恢复率。
3. 如是异步任务，先检查幂等键、租约、指数退避和死信状态；禁止直接改业务正文。
4. 如需止损，关闭服务端功能开关或将比例降至 0；小程序端显示状态不能替代服务端权限。
5. 仅在依赖已恢复且原因码明确时重放死信。
6. 运行固定合成故障演练，确认内容缺失、数据库超时、外部服务失败、凭证失效、重复消息和制品损坏均进入预期恢复路径。
7. 生成证据包，交由值班、安全隐私伦理和上线负责人分别复核。

## 4. 备份、恢复与回滚

- SQLite：使用 `backend/scripts/migrate_task32_reliability_release.py` 的备份校验能力，记录 SHA-256、完整性检查和七张可靠性表的行数，不导出参与者正文。
- MySQL：必须在测试云单独执行备份、隔离恢复、行数核对、关键旅程回放和回滚演练；本地 SQLite 结果不能替代该证据。
- 数据库回滚默认非破坏：先关闭可靠性工作台、任务执行、故障注入和灰度开关，保留事件、任务、版本、演练、证据和审计表。
- 功能回滚使用版本化功能开关；必须记录原因、操作者、前后版本和时间。
- 恢复完成后重新运行专项测试、全量测试、内容校验、API 契约校验和双端构建。

## 5. 证据包模板

证据包至少包含：

- 版本、环境、代码提交和配置摘要（不得包含秘密值）；
- 九条旅程的观察窗口与脱敏指标；
- 幂等、租约、退避、死信和人工恢复证据；
- 六类固定合成故障演练结果；
- SQLite 本地迁移与恢复证明，以及 MySQL 测试云证据状态；
- 微信开发者工具、Android/iOS 真机、CloudBase 网关链路的证据状态；
- 未完成门禁、风险、负责人和下一检查时间；
- 明确标记 `production_release_approved=false`，直至授权负责人完成外部流程。

系统生成的包始终是草稿证据，不能形成电子签名、伦理批准或上线授权。

## 6. 事后复盘模板

1. 事件时间线和影响的旅程；
2. 用户可见影响与数据影响，禁止复制参与者原文；
3. 首个信号、告警是否及时、请求链路是否完整；
4. 根因、放大因素和未生效的防线；
5. 止损、恢复、回滚及实际恢复时间；
6. 幂等、重试、死信或功能开关是否按预期工作；
7. 修复任务、负责人、截止时间和验证方式；
8. 是否需要安全、隐私、伦理或研究负责人追加复核。
