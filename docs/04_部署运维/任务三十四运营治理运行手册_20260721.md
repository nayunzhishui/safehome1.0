# 任务三十四运营治理运行手册

更新时间：2026-07-21

## 1. 适用边界

本手册只负责内容、规则、模型、词典、提示和知识索引的版本、回放、审核、发布、暂停、恢复、回滚与严重事件处置。当前只允许本地纯合成发布；生产发布、真实参与者数据和外部通知都没有自动批准。

临时展示越权继续保留，但不能用于正式权限、云环境或生产发布验收。

## 2. 默认开关

```text
OPERATIONS_GOVERNANCE_WORKBENCH_ENABLED=1
OPERATIONS_LOCAL_RELEASE_ENABLED=0
OPERATIONS_PRODUCTION_RELEASE_ENABLED=0
```

生产环境禁止把`OPERATIONS_PRODUCTION_RELEASE_ENABLED`设为1。需要止损时先关闭三个开关；数据库证据表和审计记录继续保留。

## 3. 发布前顺序

1. 运行`python backend/scripts/generate_task34_operations_registry.py --check`。
2. 运行`python backend/scripts/audit_task34_operations.py`，确认222个操作全覆盖、24项制品完整、27条固定回放无高严重度回归。
3. 创建新版本发布包；不得复用旧版本号。
4. 运行固定合成回放并送审。
5. 由独立审核者给出建议；高风险包分别由研究、心理和安全角色批准。
6. 由未参与提出、审核或批准的管理员执行发布。
7. 当前只可使用明确确认短语完成`local_synthetic`发布；不得把本地结果写成生产批准。

## 4. 原子发布与失败恢复

发布时系统先验证总清单和每项制品哈希，再取得进程锁、写入暂存文件、复核暂存哈希、备份现文件，最后替换文件并在数据库事务中切换运行指针。文件或数据库任一环节失败，恢复备份并保持旧指针。

恢复步骤：

1. 暂停当前发布包并记录结构化原因；
2. 检查目标旧包仍为本地合成已发布/已取代状态；
3. 验证旧包总哈希和每项制品哈希；
4. 执行`POST /api/operations-governance/runtime/rollback`；
5. 核对返回的`atomic_pointer_switch=true`和`artifact_restore_verified=true`；
6. 重跑固定合成回放后，才允许恢复业务。

不得用删表、覆盖审计或手工改状态代替回滚。

## 5. 告警和处置

| 级别 | 示例 | 首要动作 |
|---|---|---|
| P0 | 越权、数据泄漏、严重不良事件、AI严重安全失败 | 立即停用对应能力、保全证据哈希、排队研究/心理/安全/隐私通知，禁止自动恢复 |
| P1 | 高严重度回归、发布包哈希异常、回滚失败 | 阻断发布或保持暂停，恢复上一已验证包，人工复核 |
| P2 | 聚合漂移、供应商错误率或不适率越阈值 | 标记`review_required`，检查数据质量和规则版本，不评价参与者或家庭 |

通知表只保存角色、幂等键、尝试和失败码。真正对外发送仍需受控通知系统与真人确认；本模块只记录`dispatched`或`retry_queued`结果。

## 6. 事后复盘

复盘至少登记事件类型、严重度、受影响能力、发现时间、停用时间、证据引用、根因代码、纠正动作和待人工关闭状态。复盘完成不自动重新启用能力；必须创建新版本、通过回放和分权审核。

## 7. 迁移与外部门禁

本地迁移：

```powershell
python backend/scripts/migrate_task34_operations_governance.py
```

脚本可重复执行并只输出保守回滚计划。生产CloudBase/MySQL迁移前必须完成隔离备份与恢复演练、云权限复核、变更窗口、负责人批准和回滚负责人登记。本轮只读确认生产云托管、MySQL 5.7及备份/回档入口可访问，没有执行生产查询、迁移或写入。

人工、伦理、微信开发者工具、Android/iOS真机、云恢复和生产批准只能补充证据包，不得由程序自动签字。
