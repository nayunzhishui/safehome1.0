# 任务36迁移、备份恢复与非破坏回滚手册

更新时间：2026-07-26

## 1. 当前边界

当前目标schema是`2026_07_26_029 / therapeutic_assessment_collaboration`。本手册只提供本地隔离验证和生产命令证据，不批准也不自动执行CloudBase/MySQL生产迁移、恢复或回滚。

## 2. 本地自动演练

```powershell
python backend/scripts/task36_migration_recovery.py exercise --work-dir .codex_tmp/f18_lab --output .codex_tmp/task36_f18_migration_evidence.json
```

演练覆盖空库、旧库、重复执行、部分建表、事务中断、SQLite备份恢复和MySQL 5.7 SQL契约。输出必须满足：

- 七个`scenarios`全部为`true`；
- 备份包含SHA-256、schema hash、表行数和schema版本；
- 恢复库schema hash、表行数和版本与备份一致；
- 没有`DROP/TRUNCATE/DELETE`迁移语句；
- `production_mutation_executed=false`。

## 3. 生产前人工门禁

负责人需逐项确认维护窗口、CloudBase/MySQL目标环境、备份位置和保留期、备份hash、迁移账户最小权限、回滚负责人、入口关闭方式、任务暂停方式、健康探针和恢复后隐私墓碑复核。没有签字时只能运行`plan`、本地`exercise`和`production-command`。

## 4. 恢复后验证

恢复必须在隔离库完成；先比较schema、行数和hash，再执行：

```powershell
python backend/scripts/verify_privacy_restore.py --db <隔离恢复库> --secret <由负责人安全注入>
```

命令不得把secret写入文档或证据包。治疗性评估问题、反馈版本、行动和事件均纳入墓碑复核。

## 5. 非破坏回滚顺序

1. 关闭新入口；
2. 若已批准并运行公网隧道，停止隧道；
3. 吊销临时账号和令牌；
4. 暂停可靠任务和在线分析任务；
5. 切回旧应用读路径；
6. 验证health/ready和只读查询；
7. 保留加法表、版本和审计。

默认不DROP表、不删除历史版本和审计。生产回滚必须由负责人选择并记录，不由自动化程序签字。
