# Web 研究者后台受控外部访问与内网穿透实施计划

更新时间：2026-07-22

## 1. 目标与边界

目标是让指定研究协作者通过 HTTPS 查看 Web 研究者后台，同时继续执行应用账号、角色、对象范围和审计。外部访问层只解决“如何到达网站”，不替代 SafeHome 自身登录和权限。

本计划不自动执行以下事项：购买域名、修改生产 DNS、签署伦理/隐私批准、公开真实参与者数据、生成或传输密码、开启生产发布。上述动作必须由负责人明确批准。

## 2. 方案选择

### 2.1 推荐正式方案：命名 Tunnel + 身份访问门禁

访问链路：

```text
受邀访问者
  -> HTTPS 域名
  -> 外部身份访问门禁（指定邮箱/身份组、短会话）
  -> 命名 Tunnel
  -> 本机或测试服务器反向代理
  -> Web 静态资源 + /api 同源代理
  -> Flask / CloudBase
```

建议使用 Cloudflare Named Tunnel + Access，或具有同等能力的受控隧道。优点是源站不开放公网入站端口，可以按身份撤销，并能为访问会话设置时限。最终产品价格、账号额度和中国大陆可用性以实施当日平台页面为准。

### 2.2 内部团队方案：组网访问

如果观看者都是固定研究团队成员，可使用 Tailscale Serve 或等价私有组网。只允许加入同一受控网络的设备访问，适合内部评审，不适合向临时外部访客公开。

### 2.3 临时演示方案：短时 Quick Tunnel

Quick Tunnel 仅允许：

- 合成或完全脱敏数据；
- 临时测试账号；
- 明确开始和结束时间；
- 禁用导出、账号管理、权限管理、内容发布和生产操作；
- 演示结束立即停止进程并作废账号。

不得用 Quick Tunnel 展示真实参与者原文、联系方式、高风险记录或未脱敏研究数据。

## 3. 发布前工程清单

### W36-EXT-01 构建与同源代理

1. 执行 Web 生产构建，不把 Vite 开发服务器直接暴露到公网。
2. 由反向代理提供静态资源，并把 `/api` 代理到 Flask/CloudBase。
3. Web 的 `VITE_API_BASE_URL` 使用同源 `/api` 或批准的 HTTPS API 域名。
4. 后端 `ALLOWED_ORIGINS` 只登记确切外部域名，禁止 `*`。
5. 核验路由刷新、静态缓存、API 超时、最大请求体和错误页。

验收：外部地址可刷新深层路由；浏览器无混合内容和 CORS 错误；API 不暴露本地路径。

### W36-EXT-02 命名 Tunnel

1. 从官方渠道安装 `cloudflared`。
2. 由负责人登录目标 Cloudflare 账号并选择批准域名。
3. 创建 `safehome-research-web` 命名 Tunnel。
4. 将 Tunnel 凭据保存在操作系统受保护目录，不进入仓库、日志或截图。
5. 配置 ingress：批准域名指向本机反向代理，其余规则固定返回 404。
6. 注册为 Windows 服务或使用受控启动脚本；记录 PID、日志和停止命令。

配置模板仅保留非敏感项：

```yaml
tunnel: <TUNNEL_ID>
credentials-file: <PROTECTED_CREDENTIAL_FILE>
ingress:
  - hostname: <APPROVED_RESEARCH_HOST>
    service: http://127.0.0.1:<LOCAL_PROXY_PORT>
  - service: http_status:404
```

### W36-EXT-03 外部身份门禁

1. 为外部域名创建 self-hosted Access 应用。
2. 默认拒绝，只允许负责人批准的邮箱或身份组。
3. 使用短会话；离组、撤销或演示结束后立即失效。
4. Access 通过后仍必须登录 SafeHome，应用角色和对象范围继续执行。
5. 临时开发全权限开关存在时，页面必须显示醒目警告，且禁止把该状态作为正式权限验收证据。

### W36-EXT-04 应用安全与审计

1. 外部展示前轮换演示账号密码，不复用本地、测试云或生产凭据。
2. 禁止在文档、Git、命令历史和普通日志中保存明文密码、Tunnel token、Cookie 或参与者原文。
3. 设置登录限速、会话过期、停用账号和审计日志。
4. 导出、账号、角色、安全、备份恢复和生产开关继续由服务端保护。
5. 检查 CSP、HTTPS、安全响应头、错误信息脱敏和 request_id。

### W36-EXT-05 自动化启动与停止

后续脚本应拆为 `prepare`、`start`、`verify`、`stop` 四个阶段：

- `prepare`：检查构建产物、端口占用、CORS、合成数据模式和凭据文件权限；
- `start`：启动本地反向代理和 Tunnel，保存忽略于 Git 的运行状态；
- `verify`：只探测健康状态、登录重定向和角色边界，不读取真实正文；
- `stop`：停止 Tunnel 和代理、清除 PID、确认外部地址不可达。

脚本不得自动购买域名、创建生产账号、签署门禁或在缺少批准时启动真实数据外部访问。

## 4. 临时局域网方案

仅在可信私有局域网短时使用时，可以让 Web 监听局域网地址，并在 Windows 防火墙中只允许“专用网络”及指定网段。此方案没有外部身份门禁，不适合公共 Wi-Fi、跨互联网访问或真实研究数据。使用后应恢复仅监听 `127.0.0.1` 并撤销防火墙规则。

## 5. 专项验收矩阵

| 场景 | 预期 |
|---|---|
| 未在邀请名单 | 被外部门禁拒绝，不能到达 SafeHome 登录页 |
| 邀请用户、无 SafeHome 账号 | 只能到达登录页，不能读取后台数据 |
| 普通账号、正式权限模式 | 服务端按 participant 权限拒绝研究者操作 |
| 普通账号、临时开发全权限模式 | 可做研究者平台开发验证，页面显示临时越权警告 |
| researcher/supervisor/admin | 按正式能力和对象范围返回，敏感操作继续审计 |
| 会话过期或撤销 | 下一次请求重新认证或被拒绝 |
| Tunnel 停止 | 外部域名不可访问，源站不暴露公网端口 |
| CORS/深链/弱网 | 无通配 CORS；深链刷新可恢复；超时可重试且不重复写入 |
| 日志与导出 | 无 token、密码、手机号和参与者原文泄漏 |

正式外部验收还需要：负责人确认访问者、域名、数据范围、时间窗；隐私/伦理负责人确认真实数据范围；安全负责人确认撤销和日志；这些只能形成证据包，不能由自动化代签。

## 6. 回滚与应急

1. 立即停止 Tunnel connector 和本地反向代理。
2. 撤销 Access 策略、Tunnel token 和临时账号。
3. 删除或停用 DNS 路由，恢复原 CORS 白名单。
4. 关闭临时研究者全权限开关并重启服务。
5. 检查审计日志和异常访问；如凭据可能泄漏，执行轮换而不是恢复旧密码。
6. 保留应用数据和数据库迁移，不以删除历史数据作为回滚方式。
