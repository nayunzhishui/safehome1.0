# 3.1 P0 问题：后台复核接口缺少最小权限保护

## 当前问题

虽然导出接口 `/api/admin/export` 已经校验 `X-Admin-Token`，但以下后台敏感接口仍然没有统一权限校验：

```text
GET  /api/risk-review
POST /api/risk-review/<review_id>/review
GET  /api/profile-results
GET  /api/profile-results/<profile_id>
GET  /api/profile-results/<profile_id>/reviews
POST /api/profile-results/<profile_id>/review
```

其中风险复核接口和画像复核接口都属于后台敏感操作，不应该在没有任何后台令牌的情况下开放。

## 影响

```text
1. 任何能访问后端的人都可能查看风险复核队列。
2. 任何能访问后端的人都可能更新风险复核状态。
3. 学生画像详情可能被无权限查看。
4. profile review 可能被伪造。
5. audit_logs 虽然记录了动作，但动作本身没有先被授权。
```

## 根因

当前项目还没有正式登录系统，因此以为“先不做权限系统”即可。但在没有完整登录系统前，至少需要一个最小后台保护层：

```text
X-Admin-Token
```

这个机制已经在导出接口中使用，应该复用到后台复核、画像管理、导出以外的敏感后台接口。

## 修正原则

不做复杂登录，不接微信授权，不做 RBAC，只做最小后台令牌保护。

```text
后台敏感接口：必须要求 X-Admin-Token。
用户端普通接口：暂不要求 X-Admin-Token。
小程序普通流程：不能被破坏。
```

# 3.2 P0 问题：服务器健康检查过浅，无法定位云托管故障

## 当前问题

当前 `/healthz` 只返回：

```json
{"ok": true, "service": "safehome-backend"}
```

它只能说明 Flask 进程活着，不能说明：

```text
1. 数据库能不能连接；
2. SQLite 文件路径是否正确；
3. content 目录是否存在；
4. training_cards.json 是否能读取；
5. risk_keywords.json 是否能读取；
6. 当前 APP_ENV 是什么；
7. 当前 DATABASE_PATH 是什么；
8. 云托管 PORT 是否正确；
9. 版本信息是什么；
10. 最近一次启动是否完成 init_db。
```

## 影响

用户现在遇到小程序 `cloud.callContainer:fail 102002` 时，无法判断是：

```text
云环境错误
云托管服务名错误
Flask 没启动
数据库路径错误
content 文件找不到
服务端启动异常
```

## 根因

服务器当前只有“浅健康检查”，缺少“深健康检查”和“诊断信息接口”。

## 修正原则

新增：

```text
GET /healthz
GET /healthz/deep
```

其中：

```text
/healthz：轻量检查，适合云托管探活。
/healthz/deep：检查数据库、内容库、配置和版本，适合开发调试。
```

不能泄露：

```text
ADMIN_EXPORT_TOKEN
真实密钥
用户数据
自由文本内容
```

# 3.3 P0 问题：数据库迁移没有版本机制

## 当前问题

当前数据库表已经明显变复杂，但迁移逻辑仍主要依靠：

```text
CREATE TABLE IF NOT EXISTS
ensure_schema_columns
ALTER TABLE ADD COLUMN
```

并没有：

```text
schema_migrations 表
迁移版本号
迁移执行记录
迁移失败回滚提示
迁移前备份提示
```

## 影响

```text
1. 本地开发数据和云端数据结构可能不一致。
2. 多次启动后无法知道执行过哪些迁移。
3. 后续新增字段时容易遗漏旧库升级。
4. 如果云托管 SQLite 文件已存在，可能出现新代码访问旧字段失败。
5. 无法向导师或后续开发者解释数据库版本。
```

## 根因

项目从 MVP 快速迭代到研究数据闭环，表结构扩展速度超过了迁移机制建设。

## 修正原则

不引入 Alembic，不迁移 PostgreSQL。先做最小迁移表：

```text
schema_migrations
```

记录：

```text
version
name
applied_at
```

并将当前版本命名为：

```text
2026_06_04_001_baseline_safehome_schema
```

# 3.4 P0 问题：SQLite 生产持久化、备份和恢复方案不清楚

## 当前问题

当前数据库默认路径来自：

```text
DATABASE_PATH
```

但没有明确：

```text
1. 云托管环境 SQLite 文件放在哪里；
2. 容器重启后是否保留；
3. 是否有挂载卷；
4. 是否有每日备份；
5. 备份文件放在哪里；
6. 如何恢复；
7. 备份是否排除自由文本；
8. 是否有测试恢复流程。
```

## 影响

如果云托管容器重启、重新部署或实例迁移，SQLite 文件可能丢失或回退。  
这对真实试用阶段是严重问题。

## 根因

MVP 阶段默认 SQLite 适合本地演示，但进入真实试用前必须明确“数据如何保留”。

## 修正原则

短期不急着迁移 PostgreSQL，但必须补齐：

```text
1. DATABASE_PATH 生产路径说明；
2. 备份脚本；
3. 恢复脚本或恢复说明；
4. 启动前检查；
5. 禁止提交 *.sqlite 和 *.db；
6. 云托管挂载目录说明。
```

# 3.6 P1 问题：demo-parent 仍在前端默认写入，真实试用前需要匿名用户方案

## 当前问题

服务端写入接口已经逐步使用 `require_user_id`，但前端仍会默认补：

```text

```

Web API client 和小程序 API client 都存在默认用户机制。

## 影响

```text
1. 多个试用者数据会混在 demo-parent。
```

先不做正式登录，先做匿名用户 ID：

```text
safehome_user_xxx
```

来源：

```text
小程序：wx storage 保存 anonymous_user_id
Web：localStorage 保存 anonymous_user_id
```

开发环境仍可保留 demo-parent，但真实试用模式必须改成匿名 ID。

## 具体开发步骤

### 步骤 1：在 `backend/routes/utils.py` 新增后台令牌校验函数

新增：

```python
from flask import current_app, request

def require_admin_token() -> str:
    admin_token = current_app.config.get("ADMIN_EXPORT_TOKEN")
    request_token = request.headers.get("X-Admin-Token", "")
    if not admin_token or request_token != admin_token:
        raise ValueError("后台操作需要有效的 X-Admin-Token")
    return "admin-token"
```

同时新增包装函数：

```python
def admin_token_error_response(exc: ValueError):
    return fail("unauthorized", str(exc), status=401)
```

不要直接在多个文件重复写 token 校验。

### 步骤 2：保护 `backend/routes/risk_review.py`

以下接口必须要求 token：

```text
GET  /api/risk-review
POST /api/risk-review/<review_id>/review
```

实现方式：

```python
try:
    actor_id = require_admin_token()
except ValueError as exc:
    return fail("unauthorized", str(exc), status=401)
```

更新 review 时，如果 payload 中没有 reviewer_id，则使用：

```text

```

### 步骤 3：保护 `backend/routes/profile.py` 中的后台复核接口

至少保护：

