## 6.6-AUDIT-P0-01：限制公开注册角色，堵住自注册管理员漏洞

### 状态判断

已完成。

### 问题

当前 `/api/auth/register` 接受请求体中的 `role`，且允许注册 `admin`、`researcher`、`supervisor`。

```text
公开注册角色：parent, student
后台角色：admin, researcher, supervisor
```

### 位置

```text

apps/web/src/pages/RegisterPage.tsx
backend/tests
```

## 6.6-AUDIT-P0-02：错误后台令牌返回 401，不得返回 500

### 状态判断

已完成。

### 问题

错误 `X-Admin-Token` 请求 `/api/admin/export`、`/api/risk-review` 时返回 500。

### 原因

`auth_utils.get_current_actor()` 调用 `require_admin_token()` 时，`require_admin_token()` 抛出 `ValueError`，但上层只捕获 `AuthError`。

### 位置

```text
backend/routes/auth_utils.py
backend/routes/admin.py
backend/routes/risk_review.py
backend/tests/test_admin_auth.py
backend/tests/test_admin_export.py

```

### 允许修改

```text
backend/routes/auth_utils.py
backend/tests/test_admin_auth.py
backend/tests/test_admin_export.py
backend/tests/test_config.py
docs/00_当前事实基准/开发日志.md
docs/00_当前事实基准/当前进度交接.md
docs/00_当前事实基准/开发说明.md
```

### 禁止修改

```text
不要放宽后台权限。
不要把错误 token 当成匿名用户。
不要让错误 token 继续进入业务逻辑。
```

### 具体步骤

1. 在 `get_current_actor()` 中捕获 `ValueError`。
2. 将其转换成 `AuthError("后台操作需要有效的 X-Admin-Token", status=401)`。
3. 确保 `/api/admin/export` 错 token 返回 401。
4. 确保 `/api/risk-review` 错 token 返回 401。
5. 确保未授权导出不写成功审计日志。

## 6.6-AUDIT-P0-03：隐私接口补登录用户与 user_id 匹配校验

### 状态判断

已完成。

### 问题

`/api/privacy/revoke-consent`、`/api/privacy/delete-my-data`、`/api/privacy/export-my-data` 只信任传入的 `user_id`。

正式账号接入后，未登录或非本人用户可能代替他人：

```text
撤回研究授权
提交删除数据请求
查看隐私摘要
```

### 原因

隐私接口仍沿用匿名试用阶段的 `user_id` 参数模式，没有接入 `Authorization` 登录用户校验。

### 位置

```text
backend/routes/privacy.py
backend/routes/auth_utils.py
backend/tests/test_privacy_route.py
apps/web/src/pages/PrivacyCenterPage.tsx
```

```text

docs/00_当前事实基准/开发日志.md
docs/00_当前事实基准/当前进度交接.md
docs/00_当前事实基准/开发说明.md
```

### 禁止修改

```text
不要硬删用户数据。
不要删除匿名试用模式。
不要把隐私摘要改成导出自由文本原文。
不要绕过非诊断和隐私边界文案。
```

### 最小实现建议

分两种模式：

```text
development：保留匿名 user_id 试用能力，但如果传了 Authorization，则必须和 token 用户匹配。
production：隐私中心写入/撤回/删除请求/个人摘要必须登录，且 token 用户必须等于 user_id；admin 可按后续单独接口处理。
```

### 具体步骤

1. 新增隐私 owner 校验 helper，例如：

```python
require_privacy_owner(user_id)
```

2. 如果有 `Authorization`，校验 token 用户 id 等于 `user_id`。
3. 如果 `APP_ENV=production` 且没有登录，返回 401。
4. development 下保留匿名试用路径。
5. 前端隐私中心优先使用登录用户 id；未登录时显示匿名试用说明。
6. 增加测试：

```text
production 未登录操作隐私接口返回 401。
登录用户操作自己的 user_id 成功。
登录用户操作他人 user_id 返回 403。
隐私摘要不包含自由文本原文。
development 匿名试用仍可用。
```
