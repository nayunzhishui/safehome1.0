# 数据库备份与恢复说明

更新时间：2026-06-04

本文档说明 SQLite 试用阶段的最小备份和恢复方式。当前不迁移 PostgreSQL，也不代表正式生产数据库方案。

## 1. 本地备份

```powershell
cd D:\codex\workspace\safehome1.0
$env:DATABASE_PATH="D:\codex\workspace\safehome1.0\backend\safehome.sqlite3"
python backend\scripts\backup_sqlite.py
```

成功后会生成：

```text
backups/safehome_YYYYMMDD_HHMMSS.sqlite3
```

如果 `DATABASE_PATH` 指向的数据库不存在，脚本会报错并停止。

## 2. 本地恢复

恢复前必须停止 Flask 服务，避免服务运行中覆盖数据库。

```powershell
cd D:\codex\workspace\safehome1.0
$env:DATABASE_PATH="D:\codex\workspace\safehome1.0\backend\safehome.sqlite3"
python backend\scripts\restore_sqlite.py backups\safehome_YYYYMMDD_HHMMSS.sqlite3
```

恢复脚本会先把当前数据库保存为：

```text
safehome.sqlite3.before_restore_YYYYMMDD_HHMMSS
```

然后再用备份文件覆盖当前数据库。

## 3. 云托管注意事项

真实试用前必须确认：

1. `DATABASE_PATH` 指向云托管持久化目录；
2. 容器重启后数据库文件不会丢失；
3. 备份文件能从云端安全取出；
4. 恢复前已停止服务或切换维护窗口；
5. 备份文件不上传公开仓库。

## 4. Git 边界

以下文件不得提交：

```text
backups/
*.sqlite3
*.sqlite
*.db
```

备份文件可能包含用户记录、测评结果、高风险复核记录和联系方式，只能在授权范围内保存和使用。
