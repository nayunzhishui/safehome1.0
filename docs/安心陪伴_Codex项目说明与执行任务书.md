# 安心陪伴 / ReadFeedback：Codex 项目说明与执行任务书

## 1. 项目定位

“安心陪伴”是一个基于 UP 跨诊断情绪调节框架的家长非评判陪伴训练系统。项目面向亲子互动和学习压力相关场景，通过数字化记录、模式识别、非诊断反馈、训练卡推送和人工督导补充，帮助家长提升情绪识别、理解和非评判回应能力。

本项目不是诊断系统，也不是危机干预替代方案。第一版目标是形成可演示、可试点、可导出数据的 MVP 闭环。

## 2. 核心闭环

```text
目标设定
→ 情绪事件记录
→ 情绪与互动模式识别
→ 非诊断反馈
→ UP训练卡推送
→ 家长练习与打卡
→ 周度报告
→ 人工督导补充
```

底层逻辑主线：

```text
记录 → 识别 → 反馈 → 练习 → 追踪 → 支持
```

## 3. 并行开发要求

项目要求从“先小程序、后网页”调整为“小程序端与网页端并行开发”。并行开发不是各做一套系统，而是“一套基础，两端呈现”：

- `backend`：Flask + SQLite 后端，统一保存数据、生成反馈和导出数据。
- `apps/miniprogram`：家长端微信小程序或 Taro 小程序端。
- `apps/web`：React/Vite 网页端，包括公众展示页和管理后台。
- `shared`：前后端共享类型、常量和 mock 数据。
- `content`：训练卡、反馈规则、知情同意和隐私文本。
- `docs`：任务清单、API 文档、数据库字段说明和项目执行说明。

## 4. MVP 1.0 功能边界

第一版必须包含：

- 目标设定。
- 情绪事件记录。
- 情绪与互动模式识别。
- 即时非诊断反馈。
- UP 训练卡推荐。
- 练习打卡。
- 周度报告。
- 人工督导反馈入口。
- 后台数据查看和导出。

第一版暂不包含：

- 视频上传和视频分析。
- 语音上传和语音识别。
- 复杂 AI 对话。
- 社群系统。
- 完整咨询系统。
- 高风险危机内容的自动处理。

## 5. Codex 工作方式

每次只完成一个明确小任务。开始写代码前，应先说明：

- 要修改或创建哪些文件。
- 为什么需要这些文件。
- 如何运行。
- 如何测试。
- 完成后是否需要 Git 提交。

本阶段任务只生成目录、文档和内容样例，不写业务代码。

## 6. 伦理与安全边界

所有页面、反馈、报告和文案必须遵守以下原则：

- 不能诊断家长或孩子。
- 不能说孩子有某种障碍。
- 不能承诺改善效果。
- 不能让 AI 单独处理自伤、自杀、暴力等高风险内容。
- 不能把用户隐私数据暴露给前端公开页面。
- 优先使用支持性、非评判表达。

推荐表达示例：

| 不建议 | 建议 |
|---|---|
| 你是控制型家长 | 这次记录中出现了较多高要求表达 |
| 你的孩子有焦虑问题 | 孩子可能处在较高压力状态 |
| 你这样会伤害孩子 | 这种表达可能让孩子更防御或退缩 |
| 你应该改变 | 下次可以尝试一个更具体的替代表达 |
