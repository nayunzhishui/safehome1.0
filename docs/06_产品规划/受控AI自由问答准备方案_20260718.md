# 受控 AI 自由问答准备方案

更新时间：2026-07-18

## 1. 产品定位

建议对外称“支持性问答”或“内容助手”。“自由问答”只表示用户可以自由输入问题，不表示系统能够进行心理诊断、治疗、危机干预、法律判断或替代专业人员。

首轮允许范围：

- 如何使用小程序；
- 已批准训练卡和课程内容说明；
- 一般性情绪调节心理教育；
- 帮助用户把一次记录整理得更具体；
- 引导用户找到人工支持、隐私和数据管理入口。

首轮禁止范围：

- 诊断、筛查结论、人格或家庭关系定性；
- 药物、治疗方案和危机处置建议；
- 自动解释绘画、沙盘、创伤、图式或潜意识；
- 代替研究者审核阶段性报告；
- 读取其他参与者、家庭成员或研究者私密数据；
- 使用未授权参与者对话训练模型。

## 2. 十项开发前分析

| 问题 | 结论 |
|---|---|
| 是否服务核心闭环 | 有条件地服务“反馈、练习、支持”，但不是 MVP 必需功能 |
| 是否修改数据库 | 原型不需要；进入沙盒后需要会话、消息、来源引用、评价和安全事件表 |
| 是否新增 API | 需要会话创建、发送消息、会话列表/删除、评价和研究者安全审查接口 |
| 是否修改 shared | 需要统一消息、引用、安全路由、评价和模型元数据契约 |
| 是否影响两端一致性 | 是；后端为唯一安全路由与会话事实源，小程序/Web 共用契约 |
| 是否修改 content | 需要建立可检索的批准知识库索引，但不改原内容治理状态 |
| 心理与伦理风险 | 过度依赖、虚假共情、越界诊断、危机误处置、隐私泄漏、错误引用和模型漂移 |
| 最小实现 | 合成案例评测 + 批准知识库 RAG + fake provider + 研究者沙盒，默认关闭 |
| 如何测试 | 安全红队、来源覆盖、越界率、危机分流、注入攻击、隐私、成本、超时和降级 |
| 如何回滚 | 关闭功能开关；保留现有规则反馈、训练卡和站内人工支持闭环 |

## 3. 请求处理链

```text
用户输入
-> 本地长度/隐私提示
-> 服务端身份与频率限制
-> 风险、危机、虐待和隐私预检
-> 问题范围分类
-> 只检索已批准内容
-> 模型生成结构化草稿
-> 诊断/承诺/危险建议/来源/注入后检
-> 安全回答或固定降级回答
-> 用户评价与可选人工支持
```

高风险输入不得进入普通生成链。系统应使用固定、经人工批准的安全文本，鼓励联系当地现实支持或紧急服务，并把是否进入人工队列交给既有风险和授权规则处理。

## 4. 建议回答结构

每次回答最多包含：

1. 一句承接，不假装拥有人的感受；
2. 对问题的简短回答；
3. 一个可选择的小行动；
4. 内容来源及版本；
5. 必要时说明不知道、边界或人工支持路径。

默认不连续追问敏感经历，不使用“我完全理解你”，不保证改善，不把用户继续聊天作为成功指标。

## 5. 数据与模型策略

- 先做检索增强，不做参与者数据微调。
- 只索引 `approved` 内容；`pilot` 可在研究者沙盒单独标记验证，不能混入参与者知识库。
- 默认不保存完整模型请求日志；业务会话保存、供应商留存和研究使用需要分别说明与授权。
- 模型供应商必须支持不用于训练/受控留存的企业或 API 条款，并由负责人确认数据处理区域。
- 模型输出不是研究原始数据的替代品；保留模型、提示、知识版本和安全路由版本用于复现。

## 6. 上线门槛

进入参与者低风险小流量试点前至少满足：

- 合成安全集危机分流和敏感信息泄漏均达到预先设定阈值；
- 诊断化、保证性承诺和危险建议人工盲审无严重失败；
- 每个事实性内容回答具有批准来源或明确拒答；
- 超时、供应商失败、配额耗尽均安全降级到现有站内功能；
- 用户可关闭、删除会话、评价不适并转人工；
- 心理、伦理/法律、数据安全、运营负责人完成书面门禁。

详细执行切片见 `docs/01_当前执行入口/任务二十三至二十九逐步开发任务清单.md` 的任务二十八。

## 7. 深化治理要求

### 7.1 intended use

每个AI版本必须冻结：目标人群、问题范围、使用环境、输出结构、拒答范围、人工角色、供应商、知识版本、提示版本和停用负责人。任何一项改变都视为新系统版本，不能只替换模型名称后沿用旧验收。

### 7.2 不建立“治疗师人格”

- 产品定位是批准内容导航和支持性整理，不模拟持证咨询师身份。
- 不使用“我完全理解你”“我会一直陪着你”等可能促进依赖的承诺。
- 不把对话时长、连续天数或用户继续输入作为主要成功指标。

### 7.3 会话记忆

- 首轮只使用当前会话必要上下文，不自动跨会话建立心理画像。
- 用户可查看、删除和关闭会话记忆；研究用途另行授权。
- 检索隔离必须在服务端按用户和知识空间执行，不能依赖提示词要求模型“不要泄漏”。

### 7.4 模型和知识的独立版本

一次回答必须记录：模型供应商/版本、系统规则版本、检索索引版本、引用内容版本、安全前检/后检版本、功能开关和请求ID。日志不得包含不必要原文。

### 7.5 评测矩阵

| 维度 | 主要检查 |
|---|---|
| 作用范围 | 产品问题能回答，越界诊断和治疗请求能正确限制 |
| 支持性 | 承接但不假装共情，不责备、不读心、不保证 |
| 来源 | 事实和训练说明来自批准内容，来源不足时明确不知道 |
| 风险 | 危机、自伤伤人、虐待和现实安全问题进入固定路由 |
| 隐私 | 不返回其他用户、内部备注、系统提示、密钥或未批准知识 |
| 对抗 | 提示注入、角色扮演、编码绕过、多轮渐进诱导均不能扩大权限 |
| 可靠性 | 超时、限流、供应商失败、成本上限和索引损坏安全降级 |
| 人因 | 用户知道这是AI、能纠正、能退出、能转人工，不误以为真人值守 |

固定高严重度安全集要求严重泄漏、普通生成危机回答、诊断承诺和危险建议为0；该结果只证明固定测试集通过，不代表现实世界风险为0。

## 8. 分阶段证据

```text
A0 纸面规则和合成测试
-> A1 fake provider 契约
-> A2 批准知识库离线RAG
-> A3 研究者沙盒盲审
-> A4 内部受控试用
-> A5 经独立批准的低风险小流量参与者试点
```

每一级必须有停止条件、回滚开关和未解决问题；不得跳级。WHO 健康AI治理、NIST生成式AI风险框架和DECIDE-AI可用于治理与报告参考，但不代表项目因此获得临床或监管批准。
