## 1. 拆解原则

1. 先完成安全复核和人工/真机验收，再继续开发新功能。
2. 当前主用户仍以家长/照护者为主；大学生和成人自助方向允许在“测一测”中轻量露出，但不做完整独立流程。
3. 暂不处理知识星球、付费课程、专家服务、商业转化、账号打通和数据同步。
4. “三、思考下科普内容的呈现方式”只提出建议，不进入近期开发。
5. 算法方向先做规则版整理和离线探索，不接入真实机器学习模型或图片/文本情感计算模型。
6. 量表和数据资源以 `D:\codex\workspace\safehome1.0其他内容` 为准；当前已有虚构/示例量表需要标注为 demo，不作为正式量表结论。

## 3. 用户范围处理

| 用户类型 | 当前处理 |
|---|---|
| 家长/照护者 | 近期主线，首页、测一测、训练卡优先服务该类用户 |
| 学生 | 继续保留“学生支持性画像/阶段性画像”能力，避免人格化和诊断化 |
| 大学生 | 可在测一测中较显眼地露出分类，不做完整独立流程 |
| 成人自助 | 可在测一测中较显眼地露出分类，不做完整独立流程 |

## 4. 测一测与量表处理

1. 新建真实量表元信息目录：`content/scales_catalog.json`。
2. 先尽可能录入 `D:\codex\workspace\safehome1.0其他内容` 中量表元信息，默认 `enabled:false`。
3. 第一批开启不超过 10 个，方向包括：
   - 养育压力/养育倦怠；
   - 情绪调节/情绪稳定性；
   - 自我关怀/正念觉察；
   - 亲子沟通；
   - 家庭亲密度。
4. 当前已有示例/虚构量表保留入口，但必须增加：
   - `source_type: "demo"`；
   - `review_status: "demo_only"`；
   - 用户端显著提示“示例/演示内容”。
5. 计分规则不明确的量表不开放填写，进入待核验清单。
6. 结果页第一版只做分数/维度记录、支持性解释、推荐训练卡、非诊断边界。

## 5. 数据分析处理

数据分析纳入总计划，但不阻塞小程序功能开发。

| 阶段 | 内容 | 产出 |
|---|---|---|
| 数据 A | 文件级清单 | 文件路径、类型、样本量、变量数、可读性 |
| 数据 B | 变量级清单 | 变量名、标签、缺失率、取值范围 |
| 数据 C | 量表级分析 | 信度、描述统计、相关分析 |
| 数据 D | 探索分析 | 聚类/规则画像/可视化建议 |

规则：原始数据只读不改；临时 CSV 不提交；脱敏汇总可以进入文档；任何分析结论必须人工审核后才允许影响产品。

## 6. 科普内容呈现建议

近期只做建议，不开发知识星球接入。

建议方向：

1. 小程序内保留“课程/科普”轻量栏目；
2. 内容以 UP 框架核心知识、情绪反射弧、家长练习说明为主；
3. 每篇科普都能连接到一个小练习或训练卡；
4. 不做付费跳转、不做账号同步、不做用户数据流向知识星球；
5. 未来若接知识星球，先做人工审核后的外部链接说明，不做自动数据打通。

## 7. 暂不做范围

1. 知识星球账号打通；
2. 付费课程；
3. 专家服务商业化；
4. 真实 AI 自由问答；
5. 临床诊断、治疗承诺、危机干预；
6. 图片/语音/视频分析；
7. 真实机器学习模型上线；
8. 复杂多用户权限重构；
9. 正式发布上线。
