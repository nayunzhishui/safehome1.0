# 后续上线措施

## 0. 文档定位

本文档用于回答两个问题：

1. 当前只能在本地运行的 `safehome1.0`，如何逐步变成可落地使用的系统。
2. 上线过程中是否需要域名、服务器、HTTPS、备案、小程序配置、隐私合规和数据备份。

本文档不是立即上线命令清单，而是后续开发、部署、试用和正式发布的执行路线。心理健康相关功能涉及未成年人、敏感个人信息、非诊断反馈和人工督导边界，因此上线不能只看技术能否访问，还要同时满足产品、伦理、安全和管理流程。

当前进度统一口径见 `docs/00_当前事实基准/项目进度统一口径.md`。本文档只说明后续上线措施，不代表项目已经完成公网部署、域名配置、备案、HTTPS、小程序正式发布或生产权限系统。

## 1. 当前状态判断

### 1.1 当前项目状态

当前 `safehome1.0` 更适合定位为本地开发版和内部演示版：

- 后端、前端、小程序和内容库已经具备项目雏形。
- 本地可以用于开发、调试、功能演示和材料汇报。
- 已经完成学生画像规则、风险关键词、训练卡、画像 API、画像报告、人工复核和画像脱敏导出第一版。
- 但目前还不建议直接面向真实学生开放使用。
- 学生画像模块已完成 1.2-1 至 1.2-4，仍需完成试点前人工验收。

### 1.2 暂不建议直接正式上线的原因

正式上线前至少需要补齐：

- 稳定的 HTTPS API 地址。
- 小程序合法域名配置。
- 后台登录、权限控制和导出权限。
- 风险关键词识别和人工审核流程。
- 数据备份、脱敏导出、匿名 ID、审计日志。
- 隐私政策、用户协议、非诊断声明和危机边界声明。
- 小范围试用记录和验收结果。

### 1.3 当前最合理目标

建议分三步：

1. 先完成本地 MVP 闭环：测评 -> 画像 -> 训练卡 -> 打卡 -> 周报 -> 导出。
2. 再部署为小范围试用版：有服务器、有域名、有 HTTPS、有后台权限。
3. 最后申请小程序正式发布：完成备案、隐私合规、微信平台配置和试用验收。

## 2. 是否需要域名

### 2.1 本地开发和本地演示

不需要域名。

可使用：

- `http://127.0.0.1`
- `http://localhost`
- 局域网 IP，例如 `http://192.168.x.x`
- 微信开发者工具里的本地调试地址

适用场景：

- 自己开发。
- 给老师现场演示。
- 截图、录屏、写材料。
- 不收集真实学生敏感数据。

### 2.2 临时外网演示

可以暂时不购买正式域名，但不建议长期使用。

可选方式：

- 内网穿透工具，例如 cpolar、ngrok、cloudflared。
- 临时云开发环境。
- 短期测试服务器 IP。

适用场景：

- 让老师或同学临时访问。
- 小范围功能确认。
- 不作为正式小程序后端。

限制：

- 地址可能变化。
- 稳定性较差。
- HTTPS、备案、微信合法域名配置可能受限。
- 不适合真实用户长期使用。

### 2.3 Web 网页公开试用

建议需要域名。

原因：

- 用户更容易访问和记忆。
- HTTPS 证书更稳定。
- 后台 API、管理端、展示页可以分开管理。
- 后续接入小程序、备案、隐私政策和访问统计更规范。

推荐域名规划：

```text
api.safehome.example.com      后端 API
admin.safehome.example.com    Web 管理后台
www.safehome.example.com      项目介绍页或公开入口
```

如果预算有限，也可以先使用一个域名加路径：

```text
https://safehome.example.com/api
https://safehome.example.com/admin
```

### 2.4 微信小程序正式使用

基本需要稳定 HTTPS 域名。

原因：

- 小程序请求后端时通常需要配置 request 合法域名。
- 合法域名一般要求 HTTPS。
- 域名、主体、备案、隐私配置需要按微信公众平台最新要求核对。

结论：

- 只做本地开发：不需要域名。
- 做网页试用：建议域名。
- 做小程序正式发布：需要稳定 HTTPS 域名，并按平台要求完成配置。

## 3. 推荐上线架构

### 3.1 最小可上线架构

```text
微信小程序
  -> https://api.safehome.example.com
  -> Flask 后端 API
  -> SQLite 或 PostgreSQL

Web 管理端
  -> https://admin.safehome.example.com
  -> Flask 后端 API
  -> 管理员登录、数据查看、导出
```

### 3.2 推荐中期架构

```text
用户端：微信小程序
管理端：React/Vite Web 后台
接口层：Flask API
反向代理：Nginx
进程管理：systemd + gunicorn
数据库：PostgreSQL 或 MySQL
文件存储：本地磁盘起步，后续对象存储
日志：应用日志 + 审计日志
备份：数据库每日备份 + 导出文件单独留痕
```

### 3.3 SQLite 与 PostgreSQL 的选择

试用阶段可以继续 SQLite：

- 部署简单。
- 成本低。
- 适合单人开发、小范围演示、几十人以内试用。

正式多人使用建议迁移 PostgreSQL 或 MySQL：

- 并发能力更好。
- 备份恢复更规范。
- 权限、查询、统计和导出更可靠。
- 后续研究数据分析更方便。

本项目建议：

- 第一轮小范围试用：SQLite 可以保留，但必须做好备份。
- 第二轮真实学生试用：优先迁移 PostgreSQL。
- 正式部署：PostgreSQL/MySQL + 定时备份 + 审计日志。

## 4. 上线分阶段路线

## 4.1 阶段 A：本地可演示版

目标：

- 本地跑通完整闭环。
- 不依赖域名。
- 不面向真实学生长期使用。

必须完成：

- 后端能启动。
- 小程序能访问本地接口。
- Web 管理端能查看基本数据。
- 内容库 JSON 能正常读取。
- 学生画像规则能返回非诊断反馈。
- 风险关键词能触发“建议人工关注”的提示。

验收标准：

- 本地完成一次完整流程：测评 -> 画像 -> 推荐训练卡 -> 打卡 -> 管理端查看。
- 报告文案不出现诊断性结论。
- 高风险文本不会继续生成普通鼓励式反馈。

## 4.2 阶段 B：内网或临时外网测试版

目标：

- 让老师、开发者、少量测试用户远程体验。
- 验证页面流程、接口稳定性和反馈文案。

可选做法：

- 使用内网穿透。
- 使用临时云服务器 IP。
- 使用测试域名。

必须限制：

- 不开放公开注册。
- 不采集真实姓名、手机号、班级等完整身份信息。
- 不作为正式心理服务工具宣传。
- 不把临时地址写进正式小程序配置。

验收标准：

- 3 到 5 个测试用户可以完成流程。
- 接口错误可追踪。
- 数据可以导出并脱敏。
- 老师能根据后台数据理解学生状态，但不会把画像当诊断。

## 4.3 阶段 C：小范围试用版

目标：

- 在稳定服务器上部署。
- 使用正式域名和 HTTPS。
- 支持小范围真实场景试用。

必须完成：

- 云服务器部署。
- 域名解析。
- HTTPS 证书。
- Nginx 反向代理。
- 后端进程守护。
- 管理后台访问控制。
- 数据库定时备份。
- 隐私政策和用户协议。
- 非诊断声明和危机边界声明。
- 导出脱敏策略。

验收标准：

- 连续 7 天服务稳定。
- 后端重启后可自动恢复。
- 数据库每天自动备份。
- 管理后台不能被未授权访问。
- 小程序能通过 HTTPS API 完成全部流程。

## 4.4 阶段 D：正式小程序上线版

目标：

- 进入微信小程序正式发布流程。
- 面向更稳定的试点使用。

必须完成：

- 微信小程序 request 合法域名配置。
- 小程序隐私保护指引配置。
- 用户协议和隐私政策页面。
- 版本审核材料。
- 服务边界说明。
- 如使用中国大陆服务器和域名，按最新要求处理 ICP 备案等事项。
- 高风险用户处理流程。
- 管理员权限和导出审计。

验收标准：

- 小程序审核通过。
- 正式环境和测试环境分离。
- 用户知道系统不是诊断工具。
- 管理端可追踪导出记录。
- 遇到高风险文本时有人工关注流程。

## 5. 服务器选择

### 5.1 低成本推荐

适合当前阶段：

- 1 台轻量云服务器。
- 2 核 2G 或 2 核 4G 起步。
- Linux 系统优先。
- Nginx + Python + Node 构建产物。
- SQLite 起步，后续迁移 PostgreSQL。

优点：

- 成本低。
- 架构清晰。
- 方便部署 Flask API 和 Web 后台。
- 后续扩展到数据库和对象存储比较顺。

### 5.2 国内云服务器

可选：

- 腾讯云。
- 阿里云。
- 华为云。

优点：

- 小程序访问速度通常更稳定。
- 域名备案、证书、服务器管理链路完整。

注意：

- 使用中国大陆服务器通常需要考虑备案。
- 备案和小程序主体信息要提前规划。
- 真实上线前需核对微信公众平台和工信部备案平台的最新要求。

### 5.3 海外服务器

优点：

- 通常无需中国大陆 ICP 备案。
- 部署速度快。

限制：

- 国内访问速度不一定稳定。
- 小程序审核和合法域名配置仍需按平台要求核对。
- 不适合作为面向学校场景的长期正式环境首选。

### 5.4 Serverless 或云开发

可选：

- 微信云开发。
- 云函数 + 云数据库。
- Vercel/Netlify + 独立 API。

适用：

- 快速验证产品。
- 访问量小。
- 不想维护服务器。

限制：

- 当前 Flask 后端可能需要改造。
- 数据导出、审计日志、研究分析可能不如自有服务器灵活。
- 长期技术路线要重新设计。

本项目建议：

- 当前不优先改成云开发。
- 先用普通云服务器部署 Flask API 和 Web 管理端。
- 等 MVP 稳定后再评估是否拆分为云函数或平台化服务。

## 6. 域名和 HTTPS 配置

### 6.1 域名购买

建议购买一个正式域名，用于：

- 后端 API。
- Web 管理端。
- 项目说明页。
- 隐私政策和用户协议。

命名建议：

```text
api.safehome.example.com
admin.safehome.example.com
www.safehome.example.com
```

### 6.2 DNS 解析

需要配置：

```text
api     A 记录 -> 云服务器公网 IP
admin   A 记录 -> 云服务器公网 IP
www     A 记录 -> 云服务器公网 IP
```

如果同一台服务器承载多个服务，可由 Nginx 根据域名分发。

### 6.3 HTTPS 证书

建议：

- 使用免费证书起步。
- 到期前自动续签。
- Nginx 强制 HTTPS。
- 后端接口只通过 HTTPS 暴露给小程序和 Web。

验收标准：

- 浏览器访问不提示证书错误。
- 小程序能正常请求接口。
- HTTP 自动跳转到 HTTPS。

## 7. 后端部署措施

### 7.1 后端部署目标

后端需要从本地调试进程变成稳定服务：

- 后台运行。
- 崩溃后自动重启。
- 有日志。
- 有环境变量。
- 不把密钥写死在代码里。
- 不直接暴露调试端口。

### 7.2 推荐部署方式

```text
Nginx
  -> 反向代理
  -> gunicorn
  -> Flask app
  -> SQLite/PostgreSQL
```

Windows 服务器也可以部署，但本项目建议优先 Linux 云服务器。Linux 更适合 Nginx、gunicorn、systemd、自动证书和数据库备份。

### 7.3 后端环境变量

至少应配置：

```text
APP_ENV=production
SECRET_KEY=强随机字符串
DATABASE_URL=数据库连接
ADMIN_EXPORT_TOKEN=后台导出强随机令牌
ALLOWED_ORIGINS=https://admin.safehome.example.com,https://www.safehome.example.com
EXPORT_DIR=导出文件目录
LOG_DIR=日志目录
```

不能上线的情况：

- 使用默认密钥。
- APP_ENV=production 时未配置 ADMIN_EXPORT_TOKEN。
- APP_ENV=production 时继续使用 safehome-local-admin-token。
- ALLOWED_ORIGINS 仍然允许任意来源或未配置正式域名。
- 后台无鉴权。
- Flask debug 模式暴露到公网。
- 数据库文件没有备份。

### 7.4 后端上线前检查

必须检查：

- `/api/health` 或健康检查接口可用。
- 所有写入接口有参数校验。
- 高风险文本进入人工审核或风险提示路径。
- 导出接口只有管理员可访问。
- 自由文本导出默认脱敏或隐藏。
- 接口错误不会把服务器路径、密钥、堆栈完整暴露给前端。

## 8. Web 管理端部署措施

### 8.1 管理端定位

Web 管理端不建议作为公开入口，而应作为教师、督导或项目管理员的工作台。

核心功能：

- 查看学生画像。
- 查看趋势和打卡。
- 查看风险提示。
- 导出脱敏数据。
- 查看内容规则。
- 后续查看审计日志。

### 8.2 管理端部署方式

推荐：

- 本地构建静态文件。
- 上传到服务器。
- 由 Nginx 托管。
- API 请求指向 `https://api.safehome.example.com`。

上线前必须处理：

- 管理端登录。
- 管理端接口鉴权。
- 导出按钮权限。
- 生产 API 地址配置。
- 空状态和错误状态。

### 8.3 管理端最低验收

- 未登录不能访问学生数据。
- 普通用户不能导出数据。
- 高风险记录有醒目标识。
- 导出数据默认不包含联系方式和自由文本原文。
- 每次导出可记录操作者、时间、筛选条件。

## 9. 小程序上线措施

### 9.1 小程序开发版

开发阶段可使用：

- 微信开发者工具。
- 本地接口。
- 测试 API 地址。

适用：

- 功能调试。
- UI 调整。
- 老师内部演示。

### 9.2 小程序体验版

体验版适合：

- 邀请老师测试。
- 验证真实手机上的交互。
- 小范围收集体验反馈。

体验版前建议完成：

- API 切到 HTTPS 测试域名。
- 隐私提示已显示。
- 高风险提示已处理。
- 测评结果文案不诊断化。

### 9.3 小程序正式版

正式版必须重点处理：

- request 合法域名。
- HTTPS。
- 隐私保护指引。
- 用户协议。
- 小程序服务类目。
- 审核材料。
- 数据安全说明。
- 未成年人使用边界。

### 9.4 小程序端体验要求

上线前小程序必须做到：

- 首次使用说明系统用途。
- 测评前说明非诊断性质。
- 画像页显示优势视角和行动建议。
- 高风险输入不生成普通训练建议。
- 打卡不使用惩罚式断签设计。
- 用户可以理解数据用途。

## 10. 数据、安全与合规措施

## 10.1 数据最小化

上线初期不建议收集：

- 身份证号。
- 精确家庭住址。
- 不必要的手机号。
- 与功能无关的家庭隐私。
- 大量可识别自由文本原文。

建议先使用：

- 匿名 ID。
- 年级或分组。
- 测评分数。
- 画像类型。
- 训练卡完成记录。
- 脱敏后的关键词标签。

## 10.2 隐私政策

必须写清：

- 收集哪些数据。
- 为什么收集。
- 谁可以查看。
- 是否用于研究分析。
- 如何导出。
- 如何删除。
- 保存多久。
- 联系方式。
- 非危机服务边界。

## 10.3 用户协议

必须写清：

- 系统是心理支持和训练工具，不是诊断工具。
- 反馈仅用于自我理解和教育支持。
- 高风险情况应联系专业人员、学校老师、监护人或紧急服务。
- 用户不得上传他人隐私信息。
- 管理端仅限授权人员使用。

## 10.4 未成年人和学校场景

如果面向学生，尤其未成年人，建议：

- 明确监护人或学校授权流程。
- 明确教师和督导可见范围。
- 不公开个人画像。
- 不使用羞辱、排名、惩罚式比较。
- 不把画像作为处分、筛选、贴标签依据。

## 10.5 高风险内容处理

必须建立：

- 风险关键词规则。
- 高风险提示文案。
- 人工关注流程。
- 后台风险列表。
- 风险记录审计。

高风险情况下不应：

- 输出普通训练卡替代帮助。
- 使用“你一定会好起来”等保证式表达。
- 给出诊断结论。
- 让系统独立承担危机干预责任。

## 10.6 数据导出控制

导出必须满足：

- 默认脱敏。
- 管理员权限。
- 导出留痕。
- 高风险文本单独控制。
- 自由文本原文默认不导出。
- 研究导出使用匿名 ID。

## 10.7 数据备份

最低要求：

- 每日数据库备份。
- 每周离线备份。
- 导出文件单独保存。
- 备份文件加密或限制访问。
- 定期测试恢复。

SQLite 阶段：

- 停止写入或使用安全方式复制数据库。
- 按日期保留备份。
- 不要只保留服务器唯一一份数据库。

PostgreSQL/MySQL 阶段：

- 使用数据库 dump。
- 设置定时任务。
- 保留最近 7 天、4 周、3 个月的备份版本。

## 12. 最小可落地版本

### 12.1 最小功能范围

第一版可落地使用不需要一次性完成所有功能，但必须形成闭环：

```text
学生填写测评
  -> 系统生成阶段性画像
  -> 显示非诊断反馈
  -> 推荐 1 到 3 张训练卡
  -> 学生完成打卡
  -> 管理端查看趋势
  -> 管理员导出脱敏数据
```

### 12.2 最小技术范围

必须具备：

- Flask API。
- 内容规则 JSON。
- SQLite 或 PostgreSQL。
- 小程序学生端。
- Web 管理端。
- HTTPS 域名。
- 基础权限。
- 数据备份。

### 12.3 最小合规范围

必须具备：

- 隐私政策。
- 用户协议。
- 非诊断声明。
- 高风险边界声明。
- 数据导出脱敏。
- 管理端权限。

### 12.4 不进入第一版的内容

第一版不建议做：

- 复杂机器学习模型上线。
- 自动诊断。
- 大规模公开注册。
- 精细化教师权限体系。
- 多学校多租户。
- 自动危机干预。
- 复杂社交功能。

## 14. 成本预估

### 14.1 低成本试用

可能包含：

- 域名：按年付费，成本较低。
- 云服务器：按月付费，轻量实例即可起步。
- HTTPS 证书：可使用免费证书。
- 数据库：先用本机 SQLite 或服务器自建 PostgreSQL。
- 对象存储：第一版可不单独购买。

适合：

- 项目开发。
- 老师演示。
- 小范围试用。

### 14.2 正式试点

可能增加：

- 更高配置服务器。
- 云数据库。
- 对象存储。
- 日志服务。
- 短信或统一认证。
- 备份存储。

适合：

- 多班级试用。

## 15. 不能上线的情况

出现以下情况时，不建议开放真实用户：

- 后台没有权限控制。
- 导出接口可被任意访问。
- Flask debug 暴露公网。
- 高风险文本仍返回普通鼓励反馈。
- 没有隐私政策。
- 没有用户协议。
- 没有数据备份。
- 使用诊断性措辞。
- 真实学生身份信息和心理文本混合存储且无脱敏。
- 不知道数据泄露后如何处理。

## 16. 当前项目建议

结合目前 `safehome1.0` 的开发状态，建议不要马上追求正式上线，而是先完成“可控试用版”：

1. 先补齐本地 MVP 的画像 API、风险规则、训练卡推荐和后台查看。
2. 再准备一个云服务器和测试域名。
3. 用 HTTPS API 支撑小程序体验版。
4. 只邀请老师和少量测试用户试用。
5. 试用稳定后再处理正式小程序审核和备案问题。

最小上线判断：

```text
如果只是本地演示：不需要域名。
如果要别人远程访问网页：建议域名 + HTTPS。
如果要小程序正式给真实用户使用：需要稳定 HTTPS 域名，并按微信平台和服务器所在地要求完成相关配置。
```
