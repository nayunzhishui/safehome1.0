# 服务器与数据库部署检查清单

更新时间：2026-06-06

本文档用于本地开发、CloudBase 云托管和试点前部署检查。当前项目默认仍使用 SQLite，本轮已支持云端切换 MySQL；这不代表已经完成正式公网生产部署。

## 2. 云托管启动配置

云托管启动命令应指向后端 Flask 应用，例如：

```powershell
cd backend
python app.py
```

必须确认环境变量：

| 变量 | 说明 | 要求 |
|---|---|---|
| `APP_ENV` | 运行环境 | 试点/生产使用 `production` |
| `PORT` | Flask 监听端口 | 云托管按平台注入端口 |
| `DB_PROVIDER` | 数据库类型 | 本地默认 `sqlite`；云端 MySQL 使用 `mysql` |
| `DATABASE_PATH` | SQLite 文件路径 | 必须指向持久化目录 |
| `MYSQL_HOST` | MySQL 内网地址 | `DB_PROVIDER=mysql` 时必填，例如 `10.30.109.237` |
| `MYSQL_PORT` | MySQL 端口 | `DB_PROVIDER=mysql` 时填写 `3306` |
| `MYSQL_USER` | MySQL 账号 | `DB_PROVIDER=mysql` 时使用后端专用账号，不使用 root |
| `MYSQL_PASSWORD` | MySQL 密码 | `DB_PROVIDER=mysql` 时必填，不写入 Git |
| `MYSQL_DATABASE` | MySQL 数据库名 | `DB_PROVIDER=mysql` 时填写 `safehome` |
| `CONTENT_DIR` | 内容库目录 | 指向项目 `content` |
| `ADMIN_EXPORT_TOKEN` | 后台导出/复核令牌 | production 必须显式配置，禁止默认值 |
| `SECRET_KEY` | 登录 token 签名密钥 | production 必须显式配置，禁止 `safehome-local-dev-secret`，不少于 32 字符 |
| `ALLOWED_ORIGINS` | Web CORS 白名单 | 逗号分隔，不使用 `*` |

CloudBase MySQL 试点配置建议：

```text
DB_PROVIDER=mysql
MYSQL_HOST=10.30.109.237
MYSQL_PORT=3306
MYSQL_USER=safehome
MYSQL_PASSWORD=在云托管环境变量中填写，不写入仓库
MYSQL_DATABASE=safehome
CONTENT_DIR=/app/content
APP_ENV=production
ADMIN_EXPORT_TOKEN=生产强随机令牌
SECRET_KEY=生产强随机签名密钥（不少于32字符）
ALLOWED_ORIGINS=https://api.wefamily.chat,https://www.wefamily.chat
```

如果后端和 MySQL 在同一 CloudBase/腾讯云网络内，优先使用 MySQL 内网地址；外网地址只用于本地临时连接测试。

## 3. 健康检查

轻量检查：

```powershell
Invoke-WebRequest http://127.0.0.1:5050/healthz
```

深度检查：

```powershell
Invoke-WebRequest http://127.0.0.1:5050/healthz/deep
```

`/healthz/deep` 会检查：

- 数据库可连接；
- 当前数据库 provider 是 `sqlite` 还是 `mysql`；
- 当前 schema 版本是否等于预期版本；
- `users`、`emotion_diaries`、`feedback_results`、`student_profiles`、`risk_review_records`、`audit_logs`、`consent_records`、`records`、`schema_migrations` 是否存在；
- SQLite 路径父目录和数据库文件是否存在；
- SQLite 中训练卡数量是否与 `content/training_cards.json` 同步；
- `training_cards.json`、`feedback_rules.json`、`risk_keywords.json`、`readfeedback/student_profile_model.json` 是否存在。

接口不会返回 token、用户数据或自由文本。

## 4. SQLite 持久化

先运行只读运维检查：

```powershell
cd D:\codex\workspace\safehome1.0
python backend\scripts\check_sqlite_ops.py
```

真实试用前必须确认：

1. `DATABASE_PATH` 不在容器临时目录；
2. 云托管重启后数据库文件仍存在；
3. 备份目录不提交 Git；
4. SQLite 只适合小规模试用，不适合作为长期高并发生产数据库。

## 5. 备份与恢复

备份：

```powershell
cd D:\codex\workspace\safehome1.0
$env:DATABASE_PATH="D:\codex\workspace\safehome1.0\backend\safehome.sqlite3"
python backend\scripts\backup_sqlite.py
```

恢复前必须停止服务：

```powershell
cd D:\codex\workspace\safehome1.0
$env:DATABASE_PATH="D:\codex\workspace\safehome1.0\backend\safehome.sqlite3"
python backend\scripts\restore_sqlite.py backups\safehome_YYYYMMDD_HHMMSS.sqlite3
```

恢复脚本会先生成 `.before_restore_时间戳` 副本，再覆盖当前数据库。

## 7. 102002 排查顺序

当出现 `cloud.callContainer:fail 102002`：

1. 打开 `pages/debug/index`；
2. 截图保存 env、service、path、method、errCode、errMsg；
3. 检查云环境 ID 是否正确；
4. 检查云托管服务名是否正确；
5. 检查云托管服务是否正在运行；
6. 检查 `/healthz` 是否能访问；
7. 检查 `/healthz/deep` 是否显示数据库或内容库缺失。

## 8. 不得提交 Git

不得提交：

- `.env`
- `.env.local`
- `.env.production`
- `*.sqlite3`
- `*.sqlite`
- `*.db`
- `backups/`
- `node_modules/`
- `dist/`
- `__pycache__/`
- `.pytest_cache/`
- 真实 token
- 真实用户数据
