# 微信一键登录 + 手机号授权登录 · 联调修复清单（20260726）

## 结论先行

对照微信官方文档逐行核对后：**登录代码（小程序端 + 后端）已经写对了，不是代码 bug**。

- 小程序端：微信走 `wx.login()` 取 code；手机号用 `<button open-type="getPhoneNumber" bindgetphonenumber>` 取 `event.detail.code`（官方当前推荐的 code 换手机号方式，不是已废弃的 `encryptedData/iv`）。
- 后端：`GET /sns/jscode2session` 换 openid；手机号用 `access_token` + `POST /wxa/business/getuserphonenumber`，并兼容 `phone_info`/`phoneInfo` 两种返回字段名；`access_token` 支持 CloudBase 注入的 token 文件或标准 `cgi-bin/token`（带缓存）。
- `/api/auth/capabilities` 在缺密钥时返回 `not_configured`，前端据此隐藏按钮。

你反馈的症状是"按钮能点、点了报错/无反应"——这说明 `capabilities` 判定为"可用"（密钥或 CloudBase token 已配），问题出在**点击后的"换取"环节在部署环境里失败**。以下按最可能的根因排列修复步骤。

参考官方文档：
- 小程序登录 `auth.code2Session`（jscode2session）
- 手机号快速验证 `getPhoneNumber` + 服务端 `getuserphonenumber`
- `cgi-bin/token` 获取 access_token

## 最可能的根因与修复（按概率排序）

### 根因 1（最可能）：CloudBase 容器无法访问 `api.weixin.qq.com`，且未启用"网关注入身份"

生产链路是 `wx.cloud.callContainer` → CloudBase 云托管容器。默认部署下 CloudBase 容器**没有公网出访 / VPC NAT**，因此后端调用 `api.weixin.qq.com/sns/jscode2session` 会超时或失败 → 前端表现为"点了报错/转圈无反应"。你的文档里也把"CloudBase 公网出访或 VPC NAT"列为未完成的外部门禁，正是这个。

微信一键登录在 CloudBase 里的**正确做法是不调用 jscode2session**，而是直接用网关注入的 `X-WX-OPENID` 身份头（`wx.cloud.callContainer` 的流量经过可信网关，会自动注入）。代码已经支持这条路径（`_trusted_cloudbase_openid()`），但需要显式打开开关：

修复（在 CloudBase 云托管的**环境变量**里设置，不要写进前端代码）：

```
TRUST_CLOUDBASE_IDENTITY_HEADERS=1
```

打开后，`POST /api/auth/wechat-login` 会优先用网关注入的 openid，`identity_source` 返回 `cloudbase_header`，**完全不依赖公网出访和 WECHAT_SECRET**，微信一键登录即可在 CloudBase 内闭环。

> 安全说明：这个开关默认关闭，是因为如果把云托管服务的**公网默认域名**直接暴露、且请求不经可信网关，伪造 `X-WX-OPENID` 头可绕过。所以务必：只让小程序经 `callContainer`（可信网关）访问，不要把公网默认域名当正式登录入口对外开放。这与你文档里"公网负向探针"门禁一致。

### 根因 2：手机号换取所需的 access_token / 出访

手机号 `getuserphonenumber` 需要 `access_token` 且要访问 `api.weixin.qq.com`：

- CloudBase 会自动注入 token 文件到 `/.tencentcloudbase/wx/cloudbase_access_token`（代码已读取，见 `CLOUDBASE_ACCESS_TOKEN_PATH`）。确认这个文件在容器里存在。
- 若不用 CloudBase 注入，则需在环境变量配 `WECHAT_APPID` / `WECHAT_SECRET`，后端会用 `cgi-bin/token` 自取（同样需要容器能出访 `api.weixin.qq.com`）。
- 微信 mp 后台需**开通"手机号快速验证"能力**且小程序主体/类目资质通过，否则 `getuserphonenumber` 返回 errcode。

### 根因 3：部署的容器不是最新代码 / 云环境指向不对

- `apps/miniprogram/services/cloudConfig.js` 当前默认 `cloudEnvId=prod-d3gl35otiaa7c8d24`、`containerService=flask-gh3l`、`httpBaseUrl=…flask-gh3l-261352-9-…`。确认这个云环境里跑的是**最新发布的后端代码**（你文档里多处提到"修复未部署，云端仍显示旧错误"）。
- 重新构建并上传 CloudBase 包（仓库有 `scripts/build_task9_cloudbase_package.ps1` / `verify_…`），发布后再在开发者工具里复测。
