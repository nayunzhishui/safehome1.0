## 2. 已改动的内容

项目方案（`content/programs.json`，版本 `2026.10-program-protocol-v1-release-20261011`）：

- 三个项目的 `review_status` 由 `pilot_draft` 改为 `production_approved`，原状态保存在 `release_approval.previous_review_status`。
- 每个项目的三方审核字段 `approval`（research、psychology、ethics）仍为 `pending`，测量计划仍为 `draft_requires_research_review`。

后端与小程序：

- `backend/routes/programs.py`：生产环境放行两种状态，`pilot_approved`（三方已批准）和 `production_approved`（负责人开放）。项目列表、项目详情和提交练习记录都按这一规则判断；`pilot_draft` 在生产环境仍不显示，也不能提交。
- 列表接口的 `availability` 新增 `released_count`（已开放项目数）。`approved_count` 仍只统计三方已批准的项目；`pending_review_count` 包括负责人开放但仍待三方审核的项目。
- `backend/scripts/validate_content.py`：项目标为 `production_approved` 时，必须有负责人开放记录（批准人、日期、记录文件和原状态），否则校验不通过。
- `backend/routes/content_review.py`：负责人开放的项目可改为 `paused`（暂停，生产环境随即不再列出、也不接受新记录），三方签字齐全后可改为 `pilot_approved`；要结束项目，先暂停再改为 `completed`。
- 小程序项目列表和详情页的状态显示为“已开放”，不显示“已批准试点”或“开发预览”。研究者账号只在列表里确有草案时才看到“研究者预览”提示。
- 每条项目练习记录都保存提交时的 `program_review_status`。本次开放期间的记录为 `production_approved`，日后可与三方批准后的记录区分。

## 3. 没有改、也不能因此视为完成的事项

- 研究、心理、伦理三方审核都还没有做。伦理审核完成前，项目练习记录不要用于研究分析或发表。
- 测量计划（测量时间点、基线和后测量表、主要结果）仍待研究负责人确认。
- 方案内容、纳入与排除条件、暂停与退出标准、不良反应处理和安全门槛都没有改；反思文本照常经过安全信号筛查。
- 项目方案直接读取内容文件，不需要同步生产数据库；新版本部署到云托管后才在线上生效。

## 4. 回滚方式

- 回退本次提交并重新部署，即恢复为 `pilot_draft`，生产环境不再列出项目，也不接受新的项目记录。已提交的记录保留。
- 只撤销开放、不回退其他改动：把三个项目的 `review_status` 改回 `release_approval.previous_review_status` 中的值，删除 `release_approval`，重新部署。
