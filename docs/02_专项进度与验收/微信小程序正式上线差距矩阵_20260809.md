## 1. 总体结论

SafeHome 当前已经超过原型阶段，核心业务、心理内容、测评、风险识别、研究能力、隐私流程、MySQL/Redis、CI 与 CloudBase 联调基础均已形成。

当前主要矛盾不再是“功能不够”，而是：

> **开发/研究/治理能力已经扩张得很快，但正式用户客户端、生产权限边界、生产配置、数据生命周期、心理安全运营、微信平台接入和真机发布证据尚未完成最终收口。**

## 3. 上线总原则

上线前必须从“功能优先”切换为以下原则：

1. **Feature Freeze**：停止继续扩张非必要功能。
2. **Least Privilege**：正式版本只打开用户实际需要的能力。
3. **Participant / Research / Admin / Dev 分面**：不能依赖隐藏按钮实现隔离。
4. **Server-side Trust**：客户端 Header、`user_id`、布尔值、hash 声明均不能作为最终可信事实。
5. **Fail Closed**：心理高风险、未成年人、隐私、研究授权、AI 外部处理不确定时默认拒绝或降级。
6. **Immutable Release**：正式版本必须由可追踪、不可变的代码/内容制品构成。
7. **Evidence-driven Gate**：发布批准必须来自真实测试、审核、内容版本、配置和运行证据。
8. **Real-device Acceptance**：GitHub/静态测试不能替代微信 DevTools 和真实 iOS/Android 验收。

# 6. P0：Release Candidate 之前必须全部关闭的阻断项

以下项目未完成前，不应进入正式微信审核候选版本：

必须移除/不打包：

- `pages/debug/index`
- `pages/integration-test/index`
- `pages/researcher-dashboard/index`
- 其他仅面向研发/研究人员的内部入口

```text
Production app.json
→ 无 debug
→ 无 integration-test
→ 无 researcher/admin workbench
```

## P0-2：建立不可混用的 Production Profile

建议：

```text
development
staging

```

production 必须默认：

```text
SHOWCASE = OFF
DEBUG = OFF
```

所有高风险能力应由独立后台制品开启，而不是普通用户 backend 一次全开。

## P0-3：删除所有 participant→admin / participant→researcher 的开发提升语义

必须冻结安全不变量：

```text
parent/student
+ 任意客户端 Header
+ 任意 query/body
→ effective role 永远不能升级
```

回归测试必须覆盖：

- Showcase Header
- Researcher Workspace Header
- 伪造 `user_id`
- 伪造 capability
- 已禁用 Token
- 旧 `auth_epoch`

## P0-4：全仓完成对象级授权收口

统一架构：

```text
Authentication
→ Actor
→ Capability
→ Object Scope / Assignment
→ Purpose / Consent
→ Resource
```

参与者 self-service API 不允许后台角色通过裸 `user_id` 直接读取/写入。

研究者跨 participant 必须使用：

```text
researcher
→ capability
→ enrollment/assignment
→ object scope
→ target
```

## P0-5：Consent 变为 self-only + provenance

参与者 consent：

```text
subject_user_id = actor.id
```

后台 actor 不能以参与者身份代签，也不能把参与者撤回重新覆盖为同意。

至少记录：

- `actor_id`
- `subject_user_id`
- `consent_type`
- `consent_version`
- `consent_text_hash`
- `purpose`
- `decision`
- `source`
- `supersedes_id`
- `created_at`

---

## P0-6：统一 Logout Token Revoke

正式语义：

```text

→ POST /logout with Bearer
→ server auth_epoch++ / revoke
→ finally client.clearToken()
```

验收：退出前获取的 token 在退出后必须返回 401。

# 18. 最终判断

当前 SafeHome 不需要再用“增加功能数量”衡量完成度。

下一阶段正确目标是：

```text
功能开发期
    ↓
Feature Freeze
    ↓
Production Boundary
    ↓
Security Closure
    ↓
Data/Privacy Closure
    ↓
Psychology Safety Closure
    ↓
WeChat Integration
    ↓
Staging
    ↓
Real-device Acceptance
    ↓
Release Candidate
    ↓
微信审核
    ↓
Production
```

**当前正式发布结论：**

```text
RELEASE STATUS = NOT READY
TARGET = SAFEHOME CORE V1 RELEASE CANDIDATE
```

如果按本矩阵优先完成 P0，再按 P1 完成真实平台与运营闭环，项目可以从当前 L3 后期进入可认真提交微信审核的 L4 Release Candidate，而无需先把所有研究与 AI 能力一起推向生产。
