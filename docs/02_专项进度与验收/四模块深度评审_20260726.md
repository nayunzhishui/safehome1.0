## 1. AI 接入(任务36 F15 受控 AI 问答沙盒)

### 事实
- **无真实 LLM**:`ai_qa_provider.py:24-53` 是本地字符串拼接的 `FakeProvider`;`config.py:154-155` 强制非 fake 即拒启动。参与者入口多层关死(11/12 端点限研究角色,无参与者可达问答端点),只检索**已发布**内容(`ai_qa_retrieval_service.py:50-58` 双状态过滤 + 类型白名单),无参与者原文注入路径,kill switch 真实生效,审计只存 hash。**这部分工程质量可接受。**
- **"AI"部分是演示态**:
  - [P0] **预算熔断双重失效**:`config.py:83` 默认预算 0 → `budget>0` 恒假守卫跳过;即便配置,`ai_qa_provider.py:52` 硬编码 `cost_micros=0`,累计恒 0,阈值永不触及。
  - [P0] **超时是事后测量非取消**:`ai_qa_service.py:225-228` 先跑完再比耗时,接真实 HTTP 无法阻止挂起/计费。
  - [P0] **无 prompt 实体**:`PROMPT_VERSION`(`:19`)指向的模板/system prompt/拒答指令/输出 schema **全库不存在**;"受控"的核心不在代码里。
  - [P0] **post_check 无 grounding 校验**:`ai_qa_safety_service.py:48-52` 只查"引用列表非空",不校验输出与引用的对应关系;词表 `POST_BLOCK_TERMS` 缺"诊断"二字,"你很可能符合抑郁发作标准"可穿透。
  - [P1] **熔断可被单个客户端远程打开**:`_circuit_open` 全局无 user 维度,连发 3 条 `fake_mode:"failure"` 可拖垮全体研究者。
  - [P1] **评测走的是与生产不同的代码路径**:`_evaluate_case` 绕开检索/熔断/落库,`citation_coverage` 恒 1.0;验收脚本 `audit_task36_f15_ai_qa.py` 是读回同一 JSON 自反射,`test_task36_ai_qa_full_closure.py` 是源码子串匹配——对能力退化零检出。
- **AI 角色边界**:当前不越界,但这是 fake provider 的属性、不是架构的属性。无结构化输出契约(没有"只许输出待讨论清单"的白名单校验),`uncertainty` 字段恒 `medium` 装饰性。

### 建议(接真实 LLM 前必须完成的 P0,缺一不可)
1. 真实超时与取消(HTTP connect/read timeout + `wait_for` + 显式 cancel;计时移入重试循环内)。
2. 真实成本计量 + 按用户/按日双层熔断(provider 从 usage 回填 `cost_micros`;失败调用也记账;去掉 `budget>0` 静默禁用)。
3. 密钥管理(不落 git/不落 Config 明文/不进日志与异常栈;无密钥即降级而非报错)。
4. prompt 模板实体化并纳入 content governance,含角色限定(仅四类整理性输出)、拒答指令、强制引用格式、输出 schema。
5. 输出 grounding 校验(关键断言必须可归因到 citations,未标注段落一律降级),取代"引用非空即通过"。
6. 结论性表述检测升级(补"诊断"及中英文变形归一;至少覆盖诊断/预后/用药/绝对化承诺四类)。
- **P1**:熔断重构(per-provider+per-user、半开、手动复位);`fake_mode` 限开发/测试环境;日志脱敏基线;回归套件重建(对抗集:同义改写/英文/变形/多轮诱导/grounding 幻觉/超长输入);把 grep 式验收换成端到端行为断言。
- **P2**:`/api/ai-qa/config` 加鉴权;kill-switch/清库去掉 `allow_legacy_admin`(现审计落 `admin-token` 不可归因);保留期清理接调度器让 7 天真正生效。

> 最危险组合:**无 prompt 契约 + 无 grounding 校验 + 词表缺"诊断"**——一旦切真实模型,当前路径允许"自由生成的临床结论 + 一条无关引用卡 + `uncertainty:medium`"直达用户,而全套现有测试与审计会一致报 PASS。**切换前上述 P0 六项必须全部落地。**

## 2. 情感计算(文本情感分析 + 情绪温度计 + 离线基准 T29 + 在线分析 F13/F14)

### 事实
- **算法真实度低**:情感分析是 **26 词规则词典**(`analysis/text_analysis/dictionaries/emotion_terms.json`,自标 `sample_..._v1`,README 已诚实声明未过授权/标注/效标),否定处理是"丢弃"而非"极性翻转"(`analyze_text_sources.py:244-247`,"不焦虑"不产生正向证据)。
- **[P0] 被评测的算法 ≠ 被部署的算法**:离线基准分类器 `offline_benchmark_service.py:203-206` 是纯 `text.count(term)` 子串计数,无分词/否定/程度/转折;生产管线用另一套 `_analyze_sentiment`。
- **[P0] 240 例合成基准与词典同源,accuracy 构造性恒 1.0**:生成器 `generate_task29_synthetic_benchmark.py` 每句由"模板+一个词典词"拼成,gold=该词类别,实跑 accuracy=1.0、零错例、108 个唯一文本。基准从不评估对外主展示的 valence/arousal;缺否定/中性/混合/OOV 样本。这是词典自查闭环,不是评测。
- **[P0] F14 在线执行器三条流水线没有一条在做分析**:`research_online_analysis_service.py` 的 `_affect_result` 直接对 ground-truth 标签计数、`_semantic_result` 用"数组相邻两条共现"当边、`_topology_result` 全硬编码。治理外壳(哈希校验/版本比对/`real_participant_processing_enabled=False`/审计)扎实,内核为空。
- **[P0] 聚合边界有真实缺口**:`_assert_safe_shape`(`research_analysis_service.py:112-132`)只做键名黑名单、不看值、`result` 子树不限键,可把参与者原文塞进 `metrics.result` 并带 `raw_text_included:False` 返回;离线产物出口 `text_analysis_service.py:20-53` 的 `privacy_gate_passed` 是文件**硬编码 True** 自证、无独立校验。
- **[P0] 同意语义是 opt-out**:四处 `NOT EXISTS(... agreed=0)`——从未表态者被默认纳入分析,与"经授权"表述相反。
- **[P0/正面] 双人盲标框架**是模块内质量最高段:不回显 gold、Cohen's kappa、release gate 要求 kappa≥0.7+≥200 双标+方法负责人签字且不自动放行;`offline_benchmark_registry.json` 对外部数据集全部 `blocked_rights_review`。**门禁纪律可信,建议原样保持。**
- **参与者感知价值≈0**:情绪温度计记录后仅一句 toast(`thermometer/index.js:150-153`),四维采集只用一维、只看当天;"支持性反馈"是 8 条规则 33 个精确子串(`feedback_rules.json`),与情感计算零交叉引用,多数记录落 `general_support` 兜底文案。**唯一走通的闭环是日记→反馈→训练卡(`diary-form`,高风险正确降级不推卡)。**
- **研究者价值有限**:UI 只渲染 quality_status/record_count/privacy_gate_passed 三个数字(`ResearchDashboard.tsx:650-652`),API 返回的 emotion_categories/valence/arousal/共现网络全被丢弃;产物是"全库单点聚合",无按人/按时间/对照/前后测结构,不具备"亲子关系与情绪变化"分析能力。

### 建议
- **P0(停止把演示当证据 + 堵聚合出口)**:①把 accuracy 改标 `lexicon_self_consistency_check`、去掉"通过"语义,文档改称"词典自洽回归";②基准改用上线算法跑(准确率会掉下来,这正是应有信息);③`_assert_safe_shape` 补递归深度/字符串长度/数组规模/`result` 显式白名单,并覆盖离线与在线两个出口;④隐私门禁改独立结构断言,不再自证;⑤同意语义(opt-in 还是 opt-out)先做**伦理决策 + 文档对齐**再改代码;⑥修 `ALLOWED_LABELS` 与词典类别不一致的潜在 KeyError。

- **P2**:UI 呈现已有产物;离线产物加分层维度(时间窗/批次/角色);加"最少参与者数"门槛;`feedback_results` 来源契约写死禁入分析;基准补否定/中性/混合/OOV 负样本。
- **[需门禁]** 真实效标验证(授权词典/真实记录金标准/外部效标)需 T35 数据·伦理·模型权利签字,**建议不为指标好看而提前放行**。

## 3. SNA 与关系试点

### 事实
- **项目里没有真 SNA**:全仓三处"网络"代码——语义共现网络(文本概念为节点,自标"非真实社会关系网络")、家庭绑定拓扑审计(只统计边数/分量/度分布,`mostly_dyads` 直接判 `insufficient_data`)、退化的兼容入口。**无家庭三角/角色分化/桥接性/多人关系边。** 关系试点本身零图结构,"关系"载体是量表维度分 + GMM 聚类。
- **红线突破**:见 §0 的 P0-RL1~RL4(此模块是红线突破的主发生地)。补充:
  - [P0] 聚类画像的 cluster 级 `human_review_status=pending` 被门禁忽略——`assessment_profile_service.py:295-302` 只读模型级字段,画像名/解释已直出;Web `RelationshipAssessmentPage.tsx:132-136` 提交即渲染,无人工环节。
- **交付链路**:链路 A(F06 手写交付)合规;**链路 B(自动 relationship_report)的"确认"只是改 status、无内容审阅、且参与者在 confirm 前已可见**——人工确认对红线不产生约束。无"研究者→督导→参与者"二次确认(同一 researcher 可自 preview→自 confirm→自 send,四眼原则不存在)。`GET /api/research/deliveries` 因缺 import 必 500(F19 已在设备端修复了 import,见 §5 核对)。
- **参与度**:仅"周记录/关键事件→曲线+时间轴"是真闭环;死数据多——`relationship_pilot_tasks.review_status` 只写不更新且英文直出参与者、机制假设核对结果落库后无任何消费者、手记"共同修订"参与者侧无写回接口、五步旅程第4步全靠研究者主动发起无兜底。

### 建议
- **P0(守红线)**:①从展示越权前缀移除 `/api/relationship-pilot/`,`showcase_access.json` 置 false,生产环境该值为真则拒绝启动;②报告可见性改**服务端门禁**(非研究角色且 status∉{confirmed,sent,updated} 时剥离 `four_layer_profile`/画像/解释,含 `?download=1` 路径),前端补 `canShowProfile` 防回归;③参与者不能自建报告(`relationship_pilot_routes.py:80-85` 改 `_researcher`),同步修正被固化的测试与契约文案;④画像解释门禁下沉到 cluster 级。
- **P1**:链路 B 并入链路 A 或强制 confirm 时必须含研究者手写解释;引入督导二次确认(confirm 的 actor≠preview 的 actor,或要求 supervisor);研究备注加 `check_text_risk` + 展示白名单;关系任务入 `research_queue`;机制假设核对结果接进研究者视图或先隐藏该交互。
- **P2**:手记"共同修订"落地或改文案;清理前端英文字面量;`GET /growth` 对非研究角色剔除 `four_layer_profile`;"网络"命名纠偏。
- **未来做真 SNA(多参与者)的前置条件(只列,不建议现在做)**:独立 `relationship_edges` 表(ego-network 与 whole-network 分表)、四层同意书(ego/alter/监护人/撤回级联)、独立伦理批件 + 最小组规模阈值、**明令禁止个体级网络指标回流参与者**。且必须先修好上述 P0,否则 SNA 产物会沿同一路径泄漏,伤害面远大于维度分。
