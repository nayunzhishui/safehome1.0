## 四、发现的问题与修改意见

严重程度：**P0=会导致线上事故或数据越权，必须改**；**P1=功能/并发/正确性缺陷，应尽快改**；**P2=工程质量与体验债务，排期改**。

### 后端 · 安全与权限

**P0-01　展示越权开关在生产环境无熔断，任意已登录普通账号可提权为 admin**
- 位置：`backend/services/showcase_access_service.py:36`（`allow_showcase_*` 系列）、`backend/routes/auth_utils.py:103` `elevate_actor_for_showcase_researcher_platform`、`content/showcase_access.json`。
- 证据：JSON 现值全开；`showcase_access_service` 与 `config.py:validate()` **没有任何 `APP_ENV=="production"` 判断**。开关为真时，任意公开注册的 parent/student 账号在访问 `/api/relationship-pilot/*`、`/api/text-analysis/summary`、`POST /api/messages` 时 `role` 被提升为 `admin`，而 `research_access_service.has_object_scope` 对 `admin` 直接返回 True，跨参与者对象范围检查被绕过——即普通用户可读写全部参与者档案/报告/叙事并以研究者身份群发消息。
- 影响面：仅当发布时忘记手动改 JSON 即成线上越权；纯依赖人工，无代码兜底。
- 建议修复：在 `allow_showcase_*` 函数入口加 `if Config.APP_ENV == "production": return False`；并在 `Config.validate()` 中当 `production 且开关为真` 时直接 `raise`，让生产根本起不来。发布前把 JSON 全置 false。

**P1-01　CloudBase 头信任模式下未配 AppID 时 appid 校验被短路**
- 位置：`backend/routes/auth.py:129`。
- 证据：`if configured_appid and (not request_appid or not hmac.compare_digest(...))`——`configured_appid` 为空则整段 appid 比对短路，仅凭 `X-WX-OPENID` 格式 + `X-WX-SOURCE` 可伪造身份。默认关闭故列 P1。
- 建议：信任模式下强制 `configured_appid` 非空，否则拒绝该路径。
