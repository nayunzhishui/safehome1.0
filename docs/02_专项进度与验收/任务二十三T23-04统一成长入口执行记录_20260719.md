# 任务二十三T23-04统一成长入口执行记录

日期：2026-07-19
状态：`verified_local / external_visual_pending`

## 1. 本轮目标

把通用成长仪表盘作为参与者唯一成长入口，内部明确区分：

1. 记录与练习；
2. 测评变化；
3. 关系探索；
4. 研究者反馈。

不生成单一成长分数，不混合不同量尺；旧通用和关系仪表盘URL继续可用。

## 2. 实现

- `GET /api/growth/overview`新增`sections`，分别返回四类最小事实。
- 测评继续按`worksheet_id`分组，新增重复量表组数量，不合并分值。
- 关系探索只汇总报名、任务、连续记录和阶段报告数量，并把三类事实加入时间线；不返回开放原文。
- 研究者反馈单独返回总数、未读数和最近一条最小摘要。
- 小程序成长页改为“四条成长线索轨道”，每条线索有独立内容、空态和行动。
- “我的”页面只保留一个成长入口。
- 关系试点的成长按钮改到统一入口的“关系探索”分区。
- 历史`/pages/relationship-growth/index`默认重定向到统一入口；原关系连续记录表单保留在`?detail=1`详细页，由统一入口进入。
- Web API client和shared类型复用同一`GrowthOverview`契约，没有创建第二套字段。

## 3. 视觉决策

- 主题仍是安心陪伴的低饱和绿色，不引入新的整站视觉语言。
- 唯一识别元素是四格“成长线索轨道”，结构本身表达数据不可混合。
- 关系探索使用克制的蓝灰色，研究者反馈使用低饱和琥珀色，均只用于分区识别。
- 操作按钮最小高度88rpx；空态明确告诉参与者可以做什么。
- 页面删除原三项汇总大数字，避免把不同含义的数量误读成总成长指标。

## 4. 问题循环

| 问题 | 处理 | 结果 |
|---|---|---|
| 首次测试3项失败 | 一项是预期缺少`sections`，一项是合成日记fixture缺必填字段，一项是旧双入口仍存在 | 先修正fixture，再实现API和单入口 |
| 关系仪表盘既是看板又包含连续记录表单，直接删除会破坏功能 | 旧URL改为统一入口兼容跳转；表单作为`detail=1`详细页保留 | 单入口与记录能力同时保留 |
| 旧`summary.record_count`含测评，直接改名可能破坏既有客户端 | 保留旧字段兼容，新`sections.activity`只统计记录与练习 | 新旧契约均可用 |
| 历史链接可能带特定`enrollment_id` | 统一入口保留该ID并传给关系详细页 | 不强制跳到其他报名 |
