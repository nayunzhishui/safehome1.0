# 任务十量表上线前人工审核清单

更新时间：2026-07-05

## 1. 使用边界

本清单用于人工核对当前小程序“测一测”中启用的 16 个测评条目。当前状态只代表“可进入试点填写”，不代表已经完成正式上线、伦理授权、计分复核或诊断/筛查解释开放。

必须坚持：

- 不做诊断；
- 不做筛查结论；
- 不做人格定性；
- 不把测评结果写成固定标签；
- 高敏感量表只允许支持性解释和训练推荐。

## 3. 每份量表必须人工核对

| 核对项 | 通过标准 |
|---|---|
| 题项数量 | 小程序题项数与源文件题项数一致，若不一致需写明原因 |
| 题项文字 | 题干与源文件一致，只允许标点、空格、排版差异 |
| 题序 | 题目顺序与源文件一致，除非明确记录了重排原因 |
| 选项 | 选项文字、数值和方向一致，真机不挤压、不竖排 |
| 计分规则 | 总分、维度分、反向题和缺失处理已确认 |
| 维度归属 | 每个题项所属维度可追溯到源文件或规则说明 |
| 结果文案 | 不出现诊断、筛查结论、人格定性、责备性表达 |
| 训练推荐 | 推荐训练卡与测评含义一致，不暴露内部 ID |
| 敏感边界 | GAD-7、PHQ/CESD、GHQ、EPQ、大五等必须显示非诊断边界 |

## 4. 当前不能视为完成的事项

- 云端数据库是否已同步为 16 个启用测评，仍需部署后核对。
- 所有量表计分规则尚未全部完成正式人工确认。
- 筛查、健康和人格类量表不得因“已录入”而自动开放诊断解释。
- 归因风格问卷等长选项量表需真机复验选项显示。

## 5. 验收建议

1. 先在微信开发者工具清缓存并重新编译。
2. 每次抽查一类量表：普通支持性量表、学生量表、高敏感量表、长选项量表。
3. 每份量表至少核对前 3 题、中间 2 题、最后 3 题。
4. 对高敏感量表，额外检查结果页是否出现阈值诊断或人格定性。
5. 云端发布后再次核对 `/api/assessments` 返回数量和本清单是否一致。

## 6. 标准人工审核表字段

后续人工验收每份量表时，建议按下面字段登记，不要只写“通过/不通过”。

| worksheet_id | 量表名称 | enabled_for_user | 题项状态 | 选项状态 | 计分规则状态 | 反向题状态 | 维度状态 | 是否建议隐藏 | 人工审核内容 | 原因 |
|---|---|---|---|---|---|---|---|---|---|---|
| 示例 | 示例量表 | true/false | 一致/不一致/待复核 | 一致/不一致/待复核 | 已确认/未确认/部分确认 | 已确认/未确认/不适用 | 已确认/未确认/不适用 | 是/否 | 记录核对到第几题、哪类问题 | 写明题项数量不符、题目原文不一致、选项分值不确定、反向题不确定或维度归属不确定 |

### 6.1 自动审核产物

本轮新增自动审核脚本：

```powershell
python backend/scripts/audit_assessment_content.py
```

输出：

```text
docs/02_专项进度与验收/任务十量表题项选项自动审核.csv
```

自动审核只检查结构风险，例如空选项、长选项、边界文案和题项数量；不能替代人工核对源文件。
