## 2. T23-00当前事实基准

### 2.1 首页现状

当前小程序首页顺序为：

```text
标题与消息中心
情绪天气
测一测 / 情绪日记
三步开始
更多
最近记录
阶段性反馈
联调入口（仅开发条件）
```

首页当前并行读取：

- `GET /api/diaries`：今日数量与最近记录；
- `GET /api/profile/stats`：未读消息数量；
- `GET /api/emotion-thermometer/day`：今日情绪温度数量；
- `GET /api/progress-summary`：阶段性反馈。

首页尚未读取`GET /api/training-plan`，也没有跨记录、测评、训练和消息的唯一动态下一步。

### 2.2 已有能力

- `GET /api/training-plan`已返回练习节奏、`is_due_today`、`next_practice_date`和最多两项`today_plan_items`；不得建立第二套训练卡排序。
- `messages`已保存未读状态、来源和消息ID；首页已有消息中心。
- `checkins`可识别当日已完成练习。
- `assessment_results`和`emotion_diaries`可判断是否已有测评和事件记录。
- 项目和关系任务草稿保存在小程序本机，后端不可见。

### 2.3 入口和状态事实源

| 状态 | 权威事实源 | 计划行动 |
|---|---|---|
| 有未读人工/阶段反馈 | `messages` | 打开具体消息 |
| 训练暂停/阶段完成 | `records`中的训练节奏 + schedule service | 查看练习节奏 |
| 今日到期训练 | 既有training-plan节奏规则 | 进入个性化训练方案 |
| 今日已完成 | `checkins.created_at` | 查看本周复盘 |
| 尚无测评 | `assessment_results` | 去测一测 |
| 尚无事件记录 | `emotion_diaries` | 记录一次具体事件 |
| 无练习节奏 | training assignment不存在 | 设置练习节奏 |
| 当前未到期 | schedule service | 查看下次日期，不催促 |
| 本机项目/关系任务草稿 | 小程序storage key | 继续对应本机草稿 |
| 接口失败 | 请求错误 | 显示重试，不伪装成无任务 |

### 2.4 冻结布局

保持现有首页区块及顺序，只在“测一测/情绪日记”之后、“三步开始”之前插入“今天的一小步”。现有固定入口继续保留；“唯一主行动”仅指唯一动态状态卡，不代表删除静态入口。

## 3. 发现的冲突与处理

| 编号 | 冲突/问题 | 处理 |
|---|---|---|
| C23-01 | 原计划“首页只突出一个主按钮”容易被理解为移除现有双入口 | 按负责人冻结决策解释为“唯一动态主行动”，现有区块不删除、不移动 |
| C23-02 | 首页现有四个请求分别`catch`为空，失败和真实空态混淆 | 今日任务使用独立错误状态；失败显示重试，不影响原区块当前兼容行为 |
| C23-03 | 训练计划已有排序，若Journey再次推荐训练卡会形成双事实源 | Journey只读取节奏/到期状态并跳转既有个性化计划，不重新排序训练卡 |
| C23-04 | 项目草稿只在本机，后端无法聚合 | 客户端在服务端行动返回后检查本机草稿并按明确优先级覆盖；不上传草稿原文 |
| C23-05 | 计划核对时假设存在`backend/__init__.py`和`backend/tests/conftest.py` | 实际入口是`backend/app.py`，测试fixture为各测试文件局部函数；已按真实结构继续 |

## 4. T23-01契约决策

- 新增只读`GET /api/journey/today`，不修改数据库。
- 参与者只能读取本人；客户端传入其他`user_id`返回403。
- 返回一个`primary_action`和一个可选`secondary_action`，不返回消息正文、日记原文、量表答案或内部规则权重。
- 服务端优先级：未读人工反馈 > 训练暂停/阶段完成 > 到期训练 > 今日已完成 > 尚无测评 > 尚无记录 > 未设置节奏 > 当前未到期。
- 本机草稿在客户端覆盖普通行动，但不覆盖未读人工反馈、暂停状态或服务端错误。
- 治疗性评估动作保持门禁；本轮不接入未批准流程。
