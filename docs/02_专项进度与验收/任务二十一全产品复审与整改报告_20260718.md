# 任务二十一全产品复审与整改报告

日期：2026-07-18

## 结论

当前产品的支持性定位、非诊断边界和主流程已经清楚；最影响体验的不是缺少功能，而是训练相关页面同时呈现过多入口和说明，以及微信提醒此前没有形成可控闭环。本轮按心理安全、认知负荷、视觉层级和工程可靠性完成了高优先级整改。

## 复审与改动

| 视角 | 复审发现 | 本轮整改 |
|---|---|---|
| 心理咨询 | “正确话术”和重复风险边界可能增加表现压力；“闭嘴3秒”语气偏硬 | 示例降为可选参考；安全说明按需展开；改为“停住第一句话3秒”；主目标改成只完成第一小步 |
| 产品体验 | 三张完整卡、三日计划、新手路径、阶段路径和全部卡库同时争夺注意 | 一张优先推荐、两张紧凑备用；三日安排和全部卡库默认收起；删除重复阶段路径 |
| 认知负荷 | 选择前要求阅读情境、频率、完成标准、停止规则、示例和多个提示 | 首屏只保留标题、时长、用途、一个小目标和主按钮；其余内容渐进展开 |
| UI与美术 | 绿、橙、蓝嵌套信息块权重接近，装饰编号无决策价值 | 移除01/02/03；绿色只承担主行动；说明统一浅底；备用卡改描边按钮 |
| 推荐逻辑 | 完成过的技能被永久排除，不符合重复练习规律 | 7天内完成卡降权并标记“可巩固”，不再永久删除；无替代项时允许重复 |
| 通知体验 | 缺少授权时机、拒绝状态、一次授权消耗和设置恢复 | 仅在保存节奏后由用户主动开启；拒绝不阻断；展示接受、拒绝、禁止、已使用状态 |
| 工程可靠性 | 缺少模板配置保护、调度鉴权、幂等、失败重试和隐私审计 | 新增偏好/投递表、发送总开关、调度令牌、同日幂等、最多3次重试和授权审计 |

## 全产品层面的判断

1. 首页、记录、反馈、训练、成长与人工支持已形成连续主线，现阶段不宜继续增加并列入口。
2. 暖白、低饱和绿、轻边框和较大圆角适合支持性产品；后续应保持“一个页面一个主行动”，避免增加新的强调色。
3. 用户端文案总体符合非诊断、非标签化要求；仍需在正式试点前由心理与伦理负责人逐卡签字。
4. 站内消息负责可追溯反馈，微信订阅消息只承担轻提醒；两者不应互相替代，也不应发送敏感原文。
5. 研究后台和用户成长仪表盘已在任务二十完成全量复审，本轮不重复大改，避免破坏已经通过的桌面与移动端布局验证。
