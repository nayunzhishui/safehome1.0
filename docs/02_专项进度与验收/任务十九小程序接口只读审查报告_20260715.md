# 任务十九：小程序接口只读审查报告

日期：2026-07-15

范围：`apps/miniprogram/services/api.js`、`shared/constants/api.ts`、`shared/types/api.ts`、`backend/routes` 及其鉴权入口。

约束：本报告只记录现状与风险；除任务十九明确要求的九点量尺、训练卡、消息和阶段性反馈接口外，没有据此重构其他接口。

## 结论

小程序已有统一请求封装，主要业务能够通过同一个 API client 调用；“混乱”主要来自历史兼容、资源边界重叠和权限口径不完全统一，不是单一接口故障。当前最需要先处理的是权限安全，其次才是命名和分页统一。

## 发现清单

| 优先级 | 发现 | 影响 | 本轮处理 |
|---|---|---|---|
| P0 | 临时展示模式仍可在 `require_role` 中对研究者只读路径做角色绕过，且白名单包含关系试点研究者仪表盘 | 普通已登录角色可能读取不属于自己的参与者摘要；现有展示包不应作为正式发布包 | 仅报告，未修改；正式发布前必须关闭或收紧展示绕过并补跨角色失败测试 |
| P1 | 同时存在 Bearer token、`X-Admin-Token`、开发环境 legacy user 回退三套身份入口 | 调试方便，但生产权限推理复杂，容易把“兼容”误当“授权” | 仅报告 |
| P1 | 多个私有接口仍同时接受 token 归属和 `user_id` 查询或请求字段 | 客户端调用方式不统一，若路由遗漏所有权校验会形成越权风险 | 仅报告；消息接口已明确普通用户只能访问本人 |
| P1 | 分页参数混用 `limit`、`page_size`、`page`，部分列表只返回 `count`，部分返回 `total/has_more` | 页面难以复用统一分页组件 | 仅报告；任务十九消息列表已兼容 `limit` 并补齐稳定分页字段 |
| P2 | 训练相关同时存在 cards、recommend、training-plan、assignment、checkins、programs、courses 多组资源 | 业务边界可以解释，但前端调用者不容易判断“内容、推荐、计划、完成记录”的区别 | 仅报告，建议先补接口域地图，不直接合并 |
| P2 | 关系试点把报名、报告、任务、连续记录、成长、研究者仪表盘集中在同一前缀和较大的路由模块 | 路径一致但服务职责较多，维护时容易牵连 | 仅报告，建议后续按 enrollment、report、growth 拆服务，不改公开 URL |
| P2 | 小程序 API client 部分路径来自共享常量，部分使用字符串拼接；Web、小程序和 shared 类型同步依赖人工纪律 | 字段或路径调整时可能出现跨端漂移 | 本轮只同步了消息字段与 read-all 常量，未做全量重构 |
| P3 | 错误码、空态文案和返回 envelope 总体使用 `{data,error}`，但历史接口仍有少量特例 | 前端错误处理存在重复分支 | 仅报告 |

## 当前消息闭环路径

研究者端：小程序“我的/个人中心” → “研究者工作台” → 选择参与者 → “发送参与者消息”或“阶段性反馈” → `POST /api/messages` 或报告的确认、更新、发送接口。

参与者端：小程序“我的/个人中心”或首页消息入口 → “消息列表” → `GET /api/messages` → 点击后 `GET /api/messages/<message_id>` 自动标记已读。

## 建议顺序（后续单独立项）

1. 先修 P0 展示模式权限绕过并重新生成发布包。
2. 建立接口域地图和统一的身份、所有权规则，不先改 URL。
3. 统一列表分页契约，再逐页迁移 `limit` 兼容调用。
4. 最后拆分大型路由模块，并用兼容层保持现有小程序路径不变。

## 本轮未改动边界

- 未合并、删除或重命名现有 cards、training-plan、programs、courses 等接口。
- 未移除 `user_id`、`limit` 等历史兼容字段。
- 未改变临时展示开关及其权限行为。
- 未修改 Web 后台的既有业务流程。

## 2026-07-16 复核整改状态

负责人明确要求暂不关闭临时展示角色绕过，因此P0项保持原状。其余属于任务十九消息与阶段反馈范围的问题已整改：研究者首次写操作自动认领报名，其他研究者不能读取其报名详情、报告、成长数据或继续写入；阶段反馈改为新增不可变报告版本；消息发送阻断非在组报名、识别同幂等键不同内容，并缩减参与者消息响应字段。其他历史接口的身份入口、分页、资源命名和路由拆分仍只保留本报告结论，没有顺手修改。
