## 3. 高风险 Findings

### F-01：研究同意撤回后的通用导出过滤缺口

**级别：高；已确认。**

#### 证据

- `backend/routes/admin.py:832-837`：统一导出入口检查 `research.export` capability，但该检查本身不会自动追加研究 Consent 过滤。
- 已应用过滤的专用分支：
  - `backend/routes/admin.py:850-854`：`profile`
  - `backend/routes/admin.py:875-879`：`records`
  - `backend/routes/admin.py:903-907`：`student_followups`
  - `backend/routes/admin.py:921-925`：`sandplay`
  - `backend/routes/admin.py:939-943`：`parent_assessments`
  - `backend/routes/admin.py:957-960`：`raw_wide/long`
- 通用分支：`backend/routes/admin.py:980-1023`。
- 通用分支在 `:986-988` 初始化空的 `where_clauses`，只在提供 `user_id` 时追加普通用户过滤；没有调用 `_append_research_consent_filter()`。
- `research_revoked_filter` 的语义在 `backend/services/privacy_request_service.py:197-215`：最新研究授权为 declined/未验证的用户应被排除。
- `backend/services/privacy_request_service.py:137-160` 的撤回联动只更新部分表的 `export_allowed`，未覆盖通用分支涉及的所有业务表。

#### 影响范围

通用 `EXPORT_TABLES` 中以下包含参与者数据的类型存在“未同意/已撤回用户仍可能被导出”的缺口：

```text
goals
diaries
feedback
checkins
assessments
reports
supervision
```

`parent_assessments` 走专用分支，不属于该通用分支绕过；其自身 `research_consent=0` 不能通过通用分支规避。

#### 复现/验证

在 development/testing 环境：

1. 创建某用户的 diary、goal 或其他通用导出数据；
2. 调用 `/api/privacy/revoke-consent` 撤回匿名研究授权；
3. 使用有效管理员认证请求：

```http
GET /api/admin/export?type=diaries&user_id=<已撤回用户>
X-Admin-Token: <有效令牌>
```

4. 观察通用分支仍按用户过滤并返回该行（字段仍可能经过脱敏）。

现有 `backend/tests/test_privacy_route.py:115-165` 主要覆盖 `records` 专用分支，没有覆盖上述通用导出类型。

#### 修复建议

- 将研究导出资格过滤下沉到统一服务层/查询构造器，所有参与者数据导出必须经过同一规则；
- 明确用户自有数据导出与研究导出的合法依据，不要只依赖单表 `export_allowed`；
- 为 `goals`、`diaries`、`feedback`、`checkins`、`assessments`、`reports`、`supervision` 每种类型增加撤回前/后的回归测试；
- 新增导出类型时让测试或静态门禁强制声明 Consent 过滤策略。

#### 修复建议

- 仓库默认 showcase 应关闭，不随源码默认开启全权限；
- validation/staging 不应默认拥有普通账号到 `role=admin` 的转换；
- 展示能力改用独立的短期、强认证、受 scope 限制的 capability，不要复用真实 `admin` role；
- 强制绑定本机/内网、短期审批、自动过期、审计和合成/脱敏数据；
- 对任何非本地部署硬失败，不能只依赖配置 allowlist；
- 发布构建中增加 showcase 配置和可达性的失败关闭检查。

### F-03：非生产默认后台 token 与 SECRET_KEY 可预测

**级别：高；环境误配风险，已确认。**

#### 证据

- `backend/config.py:13-14`：定义固定默认值 `safehome-local-admin-token` 与 `safehome-local-dev-secret`。
- `backend/config.py:21`、`:60-61`：未显式设置时使用 development 和上述默认值。
- `backend/routes/auth_utils.py:46-58`：development/testing 未显式关闭时可能自动启用 legacy admin token。
- `backend/routes/auth_utils.py:61-73`：Bearer token 使用该 `SECRET_KEY` 签名。
- `backend/routes/auth_utils.py:98-115`：成功的 `X-Admin-Token` 请求被转换为 admin actor。

#### 影响

如果 development/testing/validation 服务错误暴露到共享网络或公网，攻击者可以直接尝试：

```http
GET /api/admin/export?type=diaries
X-Admin-Token: safehome-local-admin-token
```

已知签名密钥还会降低该环境 Bearer token 的完整性保护。生产配置在 `backend/config.py:340-349` 拒绝默认 token、默认 secret 和过短 secret，因此本项不是“生产默认必然可利用”，而是非生产暴露/环境误配高风险。

#### 修复建议

- 默认 token 和 secret 置空；未显式配置时启动失败，而不是使用固定样例值；
- 所有可访问环境要求高熵随机密钥；
- legacy `X-Admin-Token` 默认关闭，仅允许明确的本机短期测试；
- staging、validation、pilot 执行不低于生产的密钥和监听地址门禁；
- 增加配置测试，验证错误的 `APP_ENV`、监听地址和 secret 组合会 fail-closed。

建议仅保留 localhost-only、固定 demo 身份的显式测试开关；validation/staging/production 一律要求 Bearer；增加任意 `user_id` 冒写的负向测试。

### F-05：非法分页参数可能触发 500

**级别：中；已确认代码路径。**

- `backend/routes/research_analysis.py:60-68`：直接 `int(request.args.get("limit") or 50)`。
- `backend/routes/therapeutic_assessment.py:409-418`：直接 `limit=int(request.args.get("limit") or 50)`。

例如 `limit=abc` 可能抛出未捕获 `ValueError`，返回 500，且不符合统一验证错误 envelope。建议统一使用已有 `parse_int()`，限制负数、零、过大值，并增加参数化回归测试。

### F-06：SQLite 数据库层未保证关联完整性

**级别：中；已确认代码证据。**

- `backend/database.py:707-714`：SQLite 连接创建后未执行 `PRAGMA foreign_keys = ON`。
- `backend/models.py:121-137`：`relationship_pilot_enrollments` 的 `user_id`、`assessment_result_id`、`worksheet_id` 没有 `REFERENCES`。

数据库可能接受不存在的关联 ID，或在父记录删除后保留孤儿 enrollment。建议启用 SQLite 外键、补充约束和 `ON DELETE` 策略，迁移前清理孤儿数据，并增加 SQLite/MySQL 一致性测试。

### F-07：非生产多 worker 启动迁移/同步缺少跨进程互斥

**级别：中；代码风险已确认，真实并发故障待验证。**

- `backend/app.py:257-272`：非 production 启动路径执行初始化和迁移。
- `backend/database.py:717-735`：初始化包括 schema、补列、索引、内容同步和迁移记录。

当前读取路径未确认有文件锁、`BEGIN IMMEDIATE` 或其他跨进程互斥。多个 worker 同时冷启动可能出现 `database is locked`、唯一约束竞争或部分实例启动失败。建议把迁移改为部署阶段独立串行步骤，或增加明确的单写者/锁机制，并做多进程冷启动测试。

### F-08：MySQL 事务内透明重连可能造成部分提交

**级别：中；代码风险已确认，真实断线故障注入待验证。**

- `backend/database.py:572-583`：MySQL 使用 `autocommit=False`。
- `backend/database.py:604-608`：每次 `execute()` 前执行 `ping(reconnect=True)`。

多语句事务中若连接中断，后续 SQL 可能在新连接继续执行，而旧连接未提交语句丢失，退出时新连接仍可能提交后续操作。建议事务期间禁止透明 reconnect；检测连接变化后整体失败/回滚，事务级重试必须从事务入口重新执行。

### F-09：家长测评 `action_key` 接受任意值且无幂等

**级别：中；已确认输入校验缺口。**

- `backend/routes/parent_assessments.py:352-375`：只检查非空，然后保存 `action_key[:120]`。
- 未见服务端枚举、状态机匹配、`Idempotency-Key` 或防重复唯一约束。

报告所有者可提交任意字符串，重复请求可能生成重复 action，污染统计/UI 或下游事件。建议服务端枚举、状态机校验、幂等键和必要的唯一约束，并覆盖非法/重复/并发请求测试。

### F-17：migration advisory lock 异常释放路径

相关位置：

```text
backend/services/schema_migration_service.py:108-125
backend/app.py:270-272
```

需要继续确认所有异常是否进入 `finally`、进程中断后是否可恢复以及 SQLite/MySQL 锁语义是否一致。本项目前不应写成已发生故障。

## 7. 低风险问题

### F-18：legacy admin token 未使用恒时比较

- `backend/routes/utils.py:26-33` 使用普通字符串不等式比较 token。
- 建议使用 `hmac.compare_digest()`，并配合失败限流、审计和 legacy 路径下线计划。

### F-19：默认开发 CORS origin 扩大本地攻击面

- `backend/config.py:81-85` 默认允许 `http://127.0.0.1:5173` 和 `http://localhost:5173`。
- `backend/app.py:368-371` 允许 `Authorization`、`X-Admin-Token` 请求头。
- 当前未发现 wildcard 或 `Access-Control-Allow-Credentials: true`，不是典型 Cookie CORS 漏洞；但本机恶意 5173 页面在已掌握 token 时可能跨源读取响应。

建议正式/测试环境显式配置 HTTPS origin，开发后端只监听 loopback，后台接口尽量不开放管理令牌的跨域请求头。

### F-20：请求路径日志膨胀风险

- `backend/app.py:335-342` 记录 method/path/request_id/status/duration，没有发现记录 body/query/token 的证据。
- 超长攻击路径理论上可能膨胀日志，但实际影响取决于代理 URI 限制、日志轮转和速率限制。

建议对日志 path 设置长度上限并清洗，使用结构化日志，避免记录 query 中的敏感字段。

## 8. 正面审查结论与不应误报项

基于已读取代码，没有足够证据将以下内容判定为漏洞：

1. **Bearer token 永不过期**：`backend/routes/auth_utils.py:76-95` 有 7 天 `max_age`，并校验账号状态和 `auth_epoch`。
2. **停用用户仍可使用旧 token**：认证路径检查用户状态和 `auth_epoch`。
3. **常规日志直接泄露密码、token、body、query 或自由文本**：`backend/app.py` 日志主要记录请求元数据。
4. **微信错误日志泄露 AppSecret、完整 URL 或响应体**：已读日志说明未记录这些内容。
5. **导出接口已确认 SQL 注入**：动态表名来自内部白名单，筛选值使用参数绑定；尚不能据此宣称全后端无 SQL 注入。
6. **生产默认 secret/token 必然可利用**：生产配置存在默认值和过短值拒绝逻辑。
7. **典型 wildcard/credentials CORS 漏洞**：当前未发现 `*` 或自动携带 Cookie 的证据。
8. **新增参与者探索性分析越界**：当前实现限制 5—100 条记录、高风险 withheld，不包含原始文本、其他参与者数据、个体网络指标或关系质量判断。
