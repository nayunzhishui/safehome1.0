- `POST /api/profile` 第一版复用 `assessment_results` 保存画像结果，并默认不保存自由文本原文。

- Web 后台新增 `/profiles` 学生画像列表，从 `assessment_results` 筛选 `student_profile_v1`。
- Web 后台支持 `/profiles/<id>` 画像详情 URL。
- 后台导出已支持 `GET /api/admin/export?type=profile`，默认匿名化且不导出自由文本原文。
- Web 后台新增 `/reviews` 人工复核列表，筛选高风险、需复核或低置信度画像。
- Web 后台 `/reviews` 已支持保存人工备注、复核结论和处置状态，数据单独写入 `profile_reviews`，不覆盖学生端报告。
- Web 后台周报页新增画像复测、需复核、高风险和练习积累趋势。
- `POST /api/profile` 现在同时写入 `assessment_results` 和 `student_profiles`，返回 `student_profile_id`。
- 已实现 `GET /api/profile-results`，可按 `user_id`、`round` 和 `limit` 查询画像历史。
- 已实现 `GET /api/profile-results/<profile_id>`，可查看单条画像详情，并写入 `audit_logs`。
- 已创建 `student_profiles`、`profile_reviews`、`records`、`audit_logs` 四张研究平台化表。
- 生成学生画像时会同步写入 `records` 研究摘要，不写自由文本原文。
- 后台导出会写入 `audit_logs`，记录导出类型、筛选用户和导出行数。
- 人工复核保存会写入 `audit_logs`，记录 `review_profile` 操作。
- `type=profile` 导出已改为从 `student_profiles` 读取，默认只导出匿名摘要。
- Web 后台 `/content/rules` 已支持反馈规则和画像规则只读查看。
- `GET /api/weekly-report` 已返回 `profile_trend`，包含画像记录数、最高轮次、画像名称频次、需复核数和高风险数。

- 画像和 records 导出若包含高风险或需复核记录，需要 `confirm_high_risk=true` 二次确认。
