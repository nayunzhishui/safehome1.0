# 6.5 技术难点处理逐步开发清单

> 项目：`safehome1.0 / 安心陪伴 / ReadFeedback / 安心家平台`  
> 文档用途：承接 `docs/6.4日问题处理逐步开发清单.md`，围绕下一轮“正式身份系统、模型服务化、数据治理、反馈规则、伦理边界与试点验收”形成 Codex 可逐步执行的开发清单。  
> 执行方式：每次只允许 Codex 执行一个任务编号；每个任务都必须先审查、后修改、再测试、最后汇报。  
> 文档原则：本文件不是功能愿望清单，而是问题诊断与解决清单。Codex 不能自由发挥，不能一次性大改，不能跳过验收。

## 0. 本轮开发定位

### 0.1 为什么需要 6.5 清单

此前 `6.4日问题处理逐步开发清单` 已经围绕试点前问题做过一轮安全、健康检查、数据库迁移、风险复核、导出审计和人工验收方面的加固。

但当前项目仍然存在一组更深层的问题：

```text
1. 当前仍缺正式登录注册和角色权限系统。
2. 家长、学生、研究者、督导之间只是功能入口分流，还不是正式身份分流。
3. 匿名 ID 已能支持试用数据隔离，但不能支撑正式试点、家庭绑定和研究授权。
4. 学生画像模型已有接口和数据表基础，但缺少模型版本注册、低置信度处理、模型失败兜底和版本解释。
5. 多源数据已经分散存在于日记、测评、画像、沙盘、打卡、周报、复核等表中，但还需要统一数据字典、records 摘要和研究导出规范。
6. 反馈规则和训练卡已有基础，但仍需强化非诊断表达、规则版本、内容审核和高风险中止普通反馈。
7. 隐私、知情同意、授权撤回、数据删除、脱敏导出等伦理边界需要从文案落实为系统限制。
8. 前端已有家长、学生、研究后台入口，但移动端报告分层、角色首页和视觉融合仍需完善。
9. 研究者后台和督导工作台需要进一步区分权限，避免研究数据查看与风险处置混用。
10. 试点前需要建立完整的角色化联调、测试账号和验收文档。
```

因此，6.5 清单不是重复 6.4，而是在已有功能闭环上继续做：

```text
身份系统 → 权限系统 → 家庭绑定 → 模型版本 → 数据治理 → 反馈规则 → 伦理边界 → 角色后台 → 试点验收
```

# 6.5-P0-01：正式登录注册与角色系统最小版

## 当前问题

当前系统已经有 `users` 表，也有 `role` 字段，但该字段默认是 `parent`，并未形成正式登录注册流程。当前 Web 和小程序主要依赖匿名 ID，后台敏感操作主要依赖 `X-Admin-Token`。

这导致：

```text
1. 家长、学生、研究者、督导无法用正式账号区分。
2. 研究后台无法基于登录身份控制权限。
3. 匿名试用数据无法自然迁移到正式用户。
4. 家长—学生绑定、授权撤回、研究导出权限都缺少正式身份基础。
```

## 当前代码基础

```text
backend/models.py 已有 users 表。
backend/database.py 已有 ensure_user()。
backend/routes/utils.py 已有 require_user_id() 和 require_admin_token()。
apps/web/src/services/userIdentity.ts 已有匿名 ID。
apps/miniprogram/services/userIdentity.js 已有匿名 ID。
shared/constants/api.ts 已有 API_ENDPOINTS。
```

## 修正原则

```text
1. 不删除匿名 ID。
2. 正式账号系统必须兼容匿名试用模式。
3. 第一版只做最小账号系统，不接微信授权，不做复杂 RBAC。
4. 密码必须哈希存储，不允许明文存储。
5. token 不写入日志。
6. 登录失败不暴露账号是否存在。
```

# 6.5-P0-02：后端角色权限守卫与后台接口保护

## 当前问题

当前后台接口虽然部分使用 `X-Admin-Token`，但家长、学生、研究者、督导、管理员的权限边界尚未真正建立。

这会导致：

```text
1. 普通用户可能直接访问后台路径。
2. 研究者和督导权限混用。
3. 学生可能访问不属于自己的数据。
4. 家长可能查看未授权的学生原始文本。
5. 后台接口只靠前端隐藏无法真正保护数据。
```

## 当前代码基础

```text
backend/routes/utils.py 已有 require_admin_token()。
6.5-P0-01 完成后应已有 require_login() 和 token 用户信息。
backend/app.py 已注册多个后台和用户端路由。
apps/web/src/main.tsx 已有后台路径判断。
```

## 修正原则

```text
1. 后端必须做权限判断，不能只靠前端隐藏。
2. 第一版可以保留 X-Admin-Token 兼容，但要优先支持登录角色。
3. 用户只能访问自己的数据。
4. 研究者默认只能访问脱敏数据。
5. 督导只处理风险复核与人工支持，不默认拥有导出全量数据权限。
```

## 10. 下一步建议

建议下一步先执行：

```text
6.5-P0-01 正式登录注册与角色系统最小版
```

原因：

```text
1. 后续家长—学生绑定依赖正式用户。
2. 后续研究者/督导权限依赖正式角色。
3. 后续授权撤回、导出控制、审计日志都需要 actor_id。
4. 不先做身份系统，后续权限和伦理边界都会继续依赖临时 token 和匿名 ID。
```

但执行 6.5-P0-01 前必须再次确认：

```text
1. 当前工作区干净。
2. 用户同意进入正式登录注册开发。
3. 不删除匿名试用模式。
4. 不接微信授权。
5. 只做最小账号系统。
```
