## 一、当前项目状态快照

### 这个项目是什么

**安心陪伴（SafeHome）**：面向家长的亲子关系支持小程序。核心功能是帮助家长记录情绪事件，获得规则式支持性反馈，练习沟通技能，必要时触发人工督导。同时承载研究数据收集（家长量表、学生画像）。

### 技术栈

| 层 | 技术 | 说明 |
|----|------|------|
| 小程序前端 | 微信原生小程序 JS | `apps/miniprogram/` |
| Web 管理/研究后台 | Vite + TypeScript | `apps/web/` |
| 后端 API | Python Flask | `backend/` |
| 数据库（开发） | SQLite | `backend/safehome.sqlite3`（gitignore）|
| 数据库（生产） | 腾讯云 MySQL（CloudBase） | 通过 `DB_PROVIDER=mysql` 切换 |
| 部署 | 腾讯云 CloudBase 云托管 | Container Service: `flask-gh3l` |
| 内容数据 | JSON 文件 | `content/`（训练卡/规则/词库/量表）|

### 当前主线 vs 历史残留

| 类型 | 路径 | 判断 |
|------|------|------|
| 主线 | `apps/miniprogram/`、`backend/`、`content/` | 当前开发重心，保持最新 |
| 主线 | `docs/00_当前事实基准/` | 事实基准，每轮必读 |
| 参考 | `apps/web/` | 研究后台，状态待确认（本轮未深度审查）|
| 历史归档 | `docsold/` | 已迁移至 `docs/09_历史归档/`，不再维护 |
| 临时文件 | `.codex_tmp/`、根目录 zip 文件 | 应清理 |
| 备份 | `backups/` | 内容待确认，不应含真实用户数据 |

## 二、已完成的关键功能（不要重复开发）

以下功能已稳定，后续开发前请核实仍存在，避免重新实现：

**后端**
- `POST /api/auth/register`、`POST /api/auth/login`、`GET /api/auth/me` — 正式账号注册/登录/Token 验证
- `POST /api/diaries`、`GET /api/diaries` — 情绪日记写入/查询
- `POST /api/feedback/generate` — 规则式反馈生成（含风险预检和高风险阻断）
- `POST /api/risk/check` — 风险关键词检查
- `GET/POST /api/cards`、`/api/cards/recommend` — 训练卡列表和推荐
- `POST /api/checkins` — 训练打卡
- `GET /api/weekly-report` — 周报摘要
- `POST /api/supervision` — 人工督导申请
- `GET/POST /api/assessments`、`/api/assessment-results` — 测评和结果
- `GET /api/admin/export` — CSV 导出（已匿名化、audit_log、高风险二次确认）
- `GET /api/privacy/*` — 隐私中心（同意状态/撤回/数据删除申请/个人导出）
- `GET /healthz`、`GET /healthz/deep` — 健康检查
- `audit_logs` 表覆盖所有管理操作
- `risk_review_records` 自动记录每次风险检查结果
- `consent_records` 完整同意/撤回链

**小程序**
- `cloudConfig.js` 云配置统一管理（支持 extConfig/storage 覆盖）
- `userIdentity.js` 匿名 ID 本地持久化
- `api.js` `callContainer` 封装，统一错误格式

## 三、主要设计决策（继续开发时需遵守）

### 3.1 非诊断原则
所有用户端内容必须非诊断、非标签化、支持性、非评判。高风险内容只触发人工支持提示和现实资源引导，**不生成训练卡建议**。这在代码中有明确实现（`risk_service.py`、`feedback_service.py` 的 `_high_risk_feedback_result`）。

### 3.2 双数据库支持
后端通过 `DB_PROVIDER` 环境变量切换 SQLite（开发）/ MySQL（生产），所有 SQL 通过 `_mysqlize_query` 转换。新增字段用 `ensure_column` 而非 migration 工具。

### 3.3 双轨鉴权（当前状态，待收口）
- **旧轨**：大多数用户端写入/查询路由通过 `user_id` 参数标识用户
- **新轨**：`/api/auth` 注册登录后返回 Bearer token，保护管理/复核/导出端路由

两套体系当前并存。新功能开发时，优先使用新轨（Bearer token + `require_login`），不要扩大旧轨的覆盖范围。

### 3.4 content 目录只读
`content/enrichment/` 是候选内容库，**必须人工审核后小批量导入**，不得自动进入正式运行。正式内容文件（`training_cards.json`、`feedback_rules.json`、`risk_keywords.json`）每次后端启动时通过 `sync_training_cards` 同步到 DB。

## 四、后续迭代优先级建议

### 第一优先级：上线前必做（对应 P0）

1. **去除首页 mock 数据**  
   `home/index.js` 中的 `latestRecord`、`growthStats`、`recommendedTask` 需从真实 API 拉取，或在无数据时显示空态提示，不能以固定数字展示给用户。  
   参考：后端已有 `/api/diaries`（日记数量）、`/api/checkins`（打卡数量）、`/api/weekly-report`（周报）等接口。

2. **隐藏 debug/integration-test 页**  
   从 `app.json:pages` 中移除这两个页面，或通过条件编译（`wx.getAccountInfoSync().miniProgram.envVersion !== 'release'`）限制仅开发/体验版可访问。

3. **恢复 `urlCheck: true`**  
   在 `project.config.json` 中恢复，同时在腾讯云小程序管理后台配置合法 request 域名白名单（`flask-gh3l-xxx.sh.run.tcloudbase.com`）。

4. **`require_admin_or_owner` 升级**  
   `feedback/generate` 等接口的所有权验证需改为使用新轨 Bearer token，不能仅靠 user_id 字符串比对。

### 第二优先级：试点扩量前做（对应 P1）

5. **输入长度校验**  
   后端在 `diaries.py`、`supervision.py` 等写入路由加 `event_description`、`message` 等字段的最大长度验证（建议 2000-5000 字符）。前端日记表单对应字段加 `maxlength` 属性。

6. **频率限制**  
   对 `/api/auth/register`、`/api/auth/login`、`/api/feedback/generate` 添加 IP/user_id 级别的请求频率限制（Flask-Limiter 或 CloudBase 网关层）。

7. **首页查询优化**  
   `listDiaries` 接口增加 `date` 参数，服务端过滤今日日记，避免前端拉取100条数据再过滤。

8. **`/healthz/deep` 鉴权**  
   生产环境对该接口增加 `X-Admin-Token` 或 IP 白名单保护，避免泄露数据库基础设施信息。

9. **督导联系方式存储**  
   评估 `supervision_requests.contact` 字段是否需要加密存储（AES-256 或 CloudBase 字段级加密）。

10. **更新 API 文档**  
    将 `docs/03_技术真相/API接口文档.md` 中的鉴权说明更新为当前双轨现状，明确哪些接口需 Bearer token、哪些接受匿名 user_id。

### 第三优先级：后续版本（对应 P2）

11. 风险识别引入上下文否定检测（至少过滤"不想…"句式）
12. 首页"支持性反馈"入口逻辑优化（直接跳最近一条反馈结果或提示记录）
13. 引入 Flask-Migrate 或显式 migration 文件替代 `ensure_column` 补丁
14. 家庭绑定（`family_links`）完成小程序 UI 入口
15. 督导页添加预期响应时间说明
16. `apps/web` 后台深度审查（鉴权保护、数据展示、路由权限）
