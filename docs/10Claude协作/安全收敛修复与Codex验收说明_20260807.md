# 2. P0-02：风险复核身份

## 修复前

客户端可以传：

```json
{
  "reviewer_id": "other-user"
}
```

服务层再把该值作为：

- `risk_review_records.reviewer_id`；
- `audit_logs.actor_id`。

## 修复后

唯一权威：

```text
current authenticated actor
```

规则：

```text
请求不传 reviewer_id -> 用当前 actor
请求传自己 reviewer_id -> 兼容
请求传其他 reviewer_id -> 403 reviewer_identity_mismatch
```

最终 audit actor 永远由认证层决定。

同时新增：

- `safety_route`；
- `priority`；
- `due_at`；
- `escalated_at`；
- `review_version`；
- 状态合法性；
- 已关闭记录不允许静默重开；
- review note/action/close reason 长度限制。

# 3. 风险/危机安全系统

## 3.1 术语

内部新主字段：

```text
safety_route
```

值：

```text
standard
human_review
urgent_human_review
```

旧 `risk_level` 暂保留兼容，不得作为临床风险概率。

## 3.2 Context v2

工程支持：

- negation；
- historical；
- hypothetical/quotation；
- immediacy。

高风险关键词在引用/否定/历史语境中：

> 降低紧急优先级，但**不会被直接丢弃**。

高风险 + 即时性：

```text
urgent_human_review
```

## 3.3 重要边界

`content/risk_keywords.json` 当前明确：

```text
engineering_enhanced_pending_clinical_review
```

即：

> 工程增强完成 ≠ 心理/精神卫生专业验证完成。

真实试点前仍需专业人员做：

- 双人标注；
- precision；
- recall；
- F1；
- Cohen kappa；
- FP/FN复盘；
- 否定/历史/引用/隐喻专项。

不要由 Codex 把状态自动改成 `approved`。

# 4. 未满14周岁：方案 A + B

## 4.1 方案 A

普通 student 首先确认：

```text
under_14
14_or_over
```

不收集 DOB/生日。

试点/生产门禁：

```text
没有年龄确认
-> assessment/research/profile/sensitive text 受保护能力不得继续
```

## 4.2 防绕过

学生一旦自报：

```text
under_14
```

不能再自行切换：

```text
14_or_over
```

如录入错误，必须 supervisor/admin override 并审计。

## 4.3 方案 B

`under_14`：

```text
年龄确认
-> 家庭绑定
-> 监护人单独同意敏感数据处理
-> 学生本人 assent
-> protected capabilities active
```

### 绑定不等于同意

这是强制设计：

```text
family link != guardian consent
```

不能因为学生输入家长6位绑定码就自动创建敏感数据处理同意。

### 学生拒绝优先

```text
guardian consent = active
child assent = refused/withdrawn
-> BLOCK
```

## 4.4 受保护能力

- assessment；
- research；
- sensitive_text；
- profile。

## 4.5 前端

没有新增小程序独立路由。

复用：

```text
/pages/settings-detail/index?type=protection
```

理由：

- 不扩大页面集合；
- 不破坏原 UX registry 一一对应；
- 家长/学生同页完成保护流程。

`我的` 中新增“参与者保护”入口。

# 5. 认证收敛

正式身份：

```text
Bearer token -> named actor -> role/capability/object scope
```

## legacy X-Admin-Token

默认：

```text
development/testing: 兼容可用
pilot/production: disabled
```

只有显式设置：

```env
LEGACY_ADMIN_TOKEN_ENABLED=1
```

才重新打开。

这只是迁移兼容，不应作为正式后台会话。

## user_id/X-User-Id

匿名/请求字段身份：

```text
development compatibility only
```

在正式环境中，有 token 后 participant 永远只能作为自己。

后台 researcher/supervisor/admin 只有在路由允许时才能把明确 user_id 当 target selector。

# 6. Web

`apps/web/src/services/authState.ts`：

```text
localStorage bearer
-> sessionStorage bearer
```

并迁移后删除旧 localStorage token。

注意：

> sessionStorage 仍不是 XSS 防护。

长期 Web 如能同域，建议评估 HttpOnly Secure SameSite cookie；小程序继续 bearer。

`adminToken.ts` 需要：

```env
VITE_ENABLE_LEGACY_ADMIN_TOKEN=true
```

才启用 legacy 内存 token。

# 9. 显式 Migration

新增独立 registry：

```text
explicit_schema_migrations
```

为什么不直接继续写旧 `schema_migrations`：

> 旧表当前还承担 `/readyz` 的单一 `CURRENT_SCHEMA_VERSION` marker 职责，直接改变会误伤现有 readiness。

当前 migration：

```text
2026_08_07_062
participant_safety_identity_convergence
```

列出：

```powershell
python backend/scripts/apply_explicit_migrations.py --list
```

应用：

```powershell
python backend/scripts/apply_explicit_migrations.py --apply
```

脚本不执行 destructive rollback。

## MySQL 验收

必须在测试 MySQL 上：

# 10. 人工督导

内部目标时间：

```text
urgent_human_review: 15 min
human_review: 240 min
standard: 1440 min
```

用户文案必须说明：

> 内部目标 ≠ 紧急服务承诺。

状态增强：

```text
pending
acknowledged
replied
resolved
```

另保留未来扩展状态定义。

事件表：

```text
supervision_request_events
```

联系信息：

- participant普通接口不返回原文；
- 返回 mask；
- reviewer 专用读取可看到原联系信息；
- 读取行为写 audit。

没有在本分支自制 AES 加密；如果以后需要字段加密，应结合腾讯云 KMS/数据库加密设计，不要硬编码私钥。
