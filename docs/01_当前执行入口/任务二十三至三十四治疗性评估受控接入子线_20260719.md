# 任务二十三至三十四：治疗性评估受控接入子线

定位：不新增任务三十五，不另建一套平行系统；把既有治疗性评估方案按任务二十三至三十四的主旅程、反馈、隐私、运营、契约、研究和治理能力逐步接入。

## 1. 产品与专业边界

- 用户端统一使用“会前自我了解准备”或“协作式支持性评估”，不把小程序称为治疗、诊断工具或AI治疗性评估师。
- 小程序负责准备、记录、共享选择、经人工确认的反馈交付、微行动和随访支持。
- 适用性判断、敏感假设、风险处置、评估干预和正式治疗性评估由具备相应胜任力的真人承担。
- 当前负责人决策表D01—D26尚未完成正式签字，只允许合成数据、内部走查和不接真实服务的L0原型；真实参与者、L1—L2和任何多人路径继续阻断。
- L3完整Therapeutic Assessment不进入普通自助入口。

## 2. 既有能力与禁止重复建设

任务十二已经具备关系探索报名、测评/画像快照、阶段报告、研究者确认后发送、参与者消息、探索手记、每周补充记录、成长时间线和研究者工作台。接入时必须先建立复用矩阵，不重复实现报告、消息、训练卡、打卡、人工支持或成长仪表盘。

专业方案的七个对象作为统一语义：

1. 评估问题 Assessment Question；
2. 代表事件 Episode；
3. 证据条目 Evidence Item；
4. 工作假设 Hypothesis，区分O观察、P重复线索、H待核对假设、U未解决；
5. 反馈版本 Feedback Revision；
6. 微行动实验 Action Experiment；
7. 随访 Follow-up。

原始事实、系统整理、研究者判断和参与者确认必须分开保存，不得互相覆盖。

## 4. 首页接入规则

- 不新增长期占据首页的大型“治疗性评估”模块。
- 只有在该参与者存在已获准且进行中的会前准备、待补充、待确认反馈、微行动或随访时，“今天的一小步”才能显示对应动作。
- 建议动作包括“继续会前准备”“补充一条资料”“查看待确认反馈”“继续一个小行动”“完成一次回看”。
- `paused_for_safety`、`withdrawn`和`closed_referred`不得显示普通继续按钮；只显示已批准的状态说明和真人/现实支持路径。
- 治疗性评估状态读取失败时显示重试，不回退成普通无任务，也不泄露敏感摘要。

## 5. 开发前十问

| 问题 | 当前结论 |
|---|---|
| 是否服务核心闭环 | 是，连接问题—事件—反馈—练习—随访，但不是MVP基础功能 |
| 是否修改数据库 | 内部点击原型不需要；正式接入大概率需要版本化对象，先经TA-01复用审计决定 |
| 是否新增API | 正式接入需要草稿、提交、状态、人工复核、修订、行动和随访契约 |
| 是否修改shared | 需要统一状态、来源、共享范围、版本和可见性枚举 |
| 是否影响两端一致性 | 是；小程序和研究者Web必须使用同一状态机和权限语义 |
| 是否修改content | 需要经批准的边界、问题、共享、反馈和暂停文本，不硬编码临床解释 |
| 心理与伦理风险 | 高；包括误标签、多人泄密、风险漏接、反馈关系伤害和AI越权 |
| 最小实现 | 合成数据L0会前准备，默认关闭，不接真实API服务 |
| 如何测试 | 状态机、对象授权、共享、撤回、风险暂停、弱网、可访问性和合成认知走查 |
| 如何回滚 | 服务端功能开关关闭入口；保留原记录/反馈/训练/人工支持闭环和历史审计 |
