### 2.2 每次启动前必须执行

```powershell
cd D:\codex\workspace\safehome1.0
git status --short
git diff --name-only
git diff --cached --name-only
```

### 2.3 未提交内容保护规则

如果存在未提交改动：

1. Codex 先列出未提交文件；
2. 不需要等待用户确认，可继续开发；
3. 不得覆盖已有改动；
4. 不得执行 `git reset --hard`、`git clean -fd`、`git add .`；
5. 如果当前任务需要修改已变更文件，先阅读 diff，再做最小增量修改；
6. 任务结束后必须汇报修改文件、测试结果和是否涉及已有未提交文件；
7. commit 必须等用户确认后执行；
8. push 必须每次单独询问用户。

## 3. 自动化权限与暂停条件

### 3.1 Codex 可自动执行

1. 修改仓库内代码、content、文档、配置；
2. 运行 npm / Python 测试、构建、内容校验；
3. 启动本地服务；
4. 使用 Chrome 检查 Web 页面；
5. 使用微信开发者工具编译、预览和检查报错；
6. 查看 CloudBase 服务状态、服务日志、健康检查结果；
7. 查看小程序后台开发配置；
8. 创建明显标记的测试数据；
9. 保存真机和浏览器验收截图；
10. 更新总计划、开发日志、当前进度交接、开发说明。

### 3.2 必须暂停并提示用户确认

即使用户要求“持续执行直到所有任务完成”，遇到以下情况也必须暂停：

1. 微信扫码、验证码、账号登录；
2. 查看、复制、记录账号密码、密钥、token 明文；
3. 修改 CloudBase 环境变量；
4. 重启云托管服务；
5. 上传体验版；
6. 提交审核；
7. 正式发布；
8. 删除数据库、部署包、原始数据、用户上传文件；
9. 将真实量表设置为正式用户可用，即 `enabled_for_user=true`；
10. 修改数据库表结构；
11. 安装新依赖；
12. 测试失败涉及旧架构、权限系统、数据库迁移、部署脚本；
13. 需要处理真实高风险文本或真实用户隐私数据；
14. 接入知识星球、付费系统、外部账号系统或自由 AI 咨询。

### 3.3 禁止事项

1. 不做临床诊断、治疗承诺、危机干预；
2. 不接入真实 AI 自由问答；
3. 不做知识星球账号打通、付费课程、专家商业服务；
4. 不删除 `pages/integration-test/index`；
5. 不破坏小程序核心闭环；
6. 不随意重构架构；
7. 不让统计/算法结果未经人工审核直接影响用户报告；
8. 不提交 `node_modules`、`dist`、数据库、缓存、真实 token、临时 CSV；
9. 不把真实用户数据、openid、联系方式、原始敏感文本写入仓库或文档。

## 5. 用户优先级与功能主线

### 5.1 用户优先级

1. 第一优先：家长用户  
   - 家长养育压力；
   - 家长情绪调节；
   - 亲子沟通；
   - 家长陪伴儿童/青少年进行 UP 情绪能力培养。

2. 第二优先：大学生用户  
   - 学业压力；
   - 考试焦虑；
   - 不确定性不耐受；
   - 自我关怀。

3. 第三优先：成人自助成长用户  
   - 情绪调节；
   - 睡眠与健康促进；
   - 健康生活方式。

### 5.2 6-9 月主线

当前 P2 首页、P3 测一测、P4 训练推荐均先以家长线为主。大学生线和成人自助线先保留目录、内容规划和未来入口，不优先开发完整闭环。

```text
首页/新手引导 -> 测一测 -> 情绪日记 -> 支持性反馈 -> 训练推荐 -> 打卡/3天轻量计划 -> Web审核/导出/复核 -> 总验收
```

## 21. Git、Commit 与 Push 规则

1. Codex 完成开发后先汇报修改文件、测试命令、测试结果和遗留问题；
2. 用户确认后才能 commit；
3. commit 不能使用 `git add .`，必须按文件精确 add；
4. push 前必须单独询问用户；
5. 不允许 force push；
6. 不允许把数据库、缓存、node_modules、dist、真实 token、临时 CSV、截图证据误提交到仓库。

## 25. 历史记录处理原则

原计划中的历史完成记录不直接删除，但不再放在主执行流中干扰 Codex。

处理规则：

1. 旧的 P0/P2/P3 完成记录按当前口径重新整理；
2. 代码完成但未真机验收的任务，统一标为 `[~] 代码完成 / 待真机验收`；
3. 计划中声称已完成但需本地核验的任务，统一标为 `[~] 待本地核验`；
4. 冗余历史命令和长段落移动到“历史记录”或对应开发日志固定章节；
5. 主计划优先保留当前任务、执行规则、验收标准和下一步。
