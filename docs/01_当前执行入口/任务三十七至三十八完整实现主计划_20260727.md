## 3. 共同强制规则

每个工程子任务按适用范围补齐：

- backend路由、服务、错误码和幂等；
- 数据库schema、迁移、备份、恢复、非破坏回滚；
- shared类型、状态和枚举；
- Web研究者工作台；
- 微信小程序参与者端或研究者端；
- 对象范围、角色能力和默认拒绝；
- 审计、隐私删除、来源追踪和版本；
- 异常恢复、超时、重试、死信、熔断或人工接管；
- 专项测试、全量测试、静态审计、跨端契约和文档。

若某子任务不需要某一层，必须在执行记录中写明“不适用及原因”，不得为满足形式而新增无用表或接口。

统一状态：

- `planned`：只有计划；
- `in_progress`：正在实现；
- `engineering_complete_local`：本地工程和自动验收完成；
- `external_gate_pending`：需要伦理、资质、真实数据、真机、测试云或负责人；
- `release_approved`：负责人依据证据明确批准；
- `rolled_back`：已关闭入口并恢复到上一稳定版本；
- `blocked`：无法继续且证据、原因和恢复条件已记录。

自动化执行器必须支持机器注册表、有限循环、checkpoint、幂等键、可恢复重跑、错误分类、脱敏证据哈希和每个子任务独立提交推送。

自动化不得代替伦理审批、数据授权、专业资质核验、督导签字、真实参与者知情同意、生产数据库迁移批准、CloudBase生产发布批准或A0—A4人工结论。
