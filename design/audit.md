# 任务20现状设计审计

更新时间：2026-07-17

## 高优先级

1. 首页消息按钮仅靠 CSS 轮廓形成不完整图形，图标语义弱、未读状态与点击区域层级不清。
2. 周报直接暴露 `one_open_question`、`general_support` 等内部标识，训练效用与互动线索缺少统一显示名映射。
3. 三步开始的反射弧横向超宽，窄屏左侧被裁切；“标一个位置”与“记录一次/去训练中心”的操作关系没有视觉连接。
4. 人工支持只能接收 URL 中的 `diary_id`，没有让用户浏览并选择自己的情绪事件或测评记录，也没有后端归属校验。
5. 项目测试每节共用一个 `draftText`，反思问题仅展示，无法逐题填写；提交后参与者缺少历史回看入口。
6. 研究者小程序工作台暴露内部状态和 worksheet ID，只覆盖关系试点，缺少全模块参与者档案。
7. 个性化训练节奏只保存设置，未计算今日是否到期、下次练习日，也未驱动推荐顺序。

## 中优先级

1. 情绪日记顶部说明层级过多，“用于生成支持性反馈，不评价谁对谁错”与其他页面边界说明重复。
2. 更多线索区连续大文本框和芯片缺少分组节奏，字段密度高。
3. 情绪反馈页面“练习位置、开始练习、今日建议、人工支持、保存反馈”主次动作竞争。
4. 关系成长仪表盘在数据不足时仍显示大面积空图；曲线、时间轴、成长报告和本周记录缺少摘要导航。
5. 个性化训练页选项卡高度与文字基线不统一，来源卡显示内部 card ID。

## 低优先级

1. 温度计加减按钮虽然可用，但视觉重量偏重，说明文字挤压按钮列。
2. 刷新按钮未显式设置 flex 居中和最小高度，在不同微信内核上可能出现基线偏移。
3. 多个页面圆角、边框和浅色背景接近但不完全统一，可通过已有 design token 收口。

## 设计方向

- 使用“暖白背景 + 深绿主动作 + 浅绿信息面 + 橙色安全提醒”的既有系统，不新增另一套品牌视觉。
- 移动端流程图改为可换行的纵向节点或2列网格。
- 表单采用“必填先行—可选折叠—底部单主动作”。
- 研究者Web端采用中等密度数据工作台；参与者小程序保持低密度、行动导向。

## 2026-07-17 反馈规则与反馈页复核结论

- 心理边界：保留“可能、可以观察、还不能确定”的不确定性；删除替用户推断动机、爱或大脑机制的表达。
- 产品顺序：先确认记录行为和当下感受，再描述可观察线索，最后只给一个主练习和最多两个备用选择。
- 工程门禁：高风险继续阻断普通反馈和训练卡；普通推荐过滤未启用或非共享选择卡；去重并限制最多 3 张。
- 认知负担：情绪日记只把场景、具体事件和主要感受放在首层；想法、行为、身体和后续结果统一放入可选折叠区。
- 视觉动作：反馈页删除重复的“先尝试什么/今日建议”双区，把主练习、理由和开始按钮放在同一卡片。

本轮已修订五条基础反馈规则；修复尝试、身体警报和学生考试卡住规则原本已包含不确定性与现实支持边界，保持现有内容。
