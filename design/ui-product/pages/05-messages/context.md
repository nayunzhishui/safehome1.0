# 消息页 UI 改造需求冻结

状态：`frozen`
日期：2026-08-10
路由：`pages/messages/index`
视觉方向：方案 A「温润编辑式消息簿」

## 目标与用户

- 目标：让家长或学生快速辨认研究者补充、必要提醒和消息状态，降低通用卡片堆叠与通知中心模板感。
- 用户：已登录并需要查看自己消息的家长或学生；异常时也要能明确恢复登录或复制诊断证据。
- 核心任务：扫读消息列表并打开一条需要查看的消息。
- 成功标准：3 秒内识别这是非营销、非实时聊天的消息列表；未读、已读、撤回和版本清楚；所有原接口、状态、诊断和跳转保持不变。

## 功能真值

- `onShow` 每次调用 `loadMessages`，读取 `GET /api/messages?page=1&page_size=50`。
- `openMessage` 整行进入 `pages/message-detail/index?id=:id`；详情读取负责原有自动已读语义。
- 列表展示真实 `title`、`body`、`created_at`、`sender_role`、`delivery_version`、`is_unread`、`is_withdrawn`。
- 登录失效时通过原有 redirect 进入登录页；普通错误重新加载。
- 错误诊断仅复制原有 requestId/serviceVersion；不展示敏感正文或认证信息。
- 页面覆盖 Default、Loading、Empty、Error、LoginRequired、NetworkFailure、LongContent。

## 冻结布局

1. 开放式象牙白画布，顶部使用短标题“消息”和一行边界说明，不使用英雄卡片。
2. 默认态以一列编辑式消息行承载内容，列表仅有外边界与分隔线，不把每条消息做成独立卡片。
3. 未读消息使用左侧森林绿短线、较强标题和文字状态共同表达；已读降低字重；撤回使用中性状态并显示固定撤回文案。
4. 信息顺序固定为标题 → 两行内摘要 → 来源/时间/版本 → 状态；整行保持 88rpx 以上点击区域。
5. Loading、Empty、Error 继续复用 `page-state`；错误诊断紧邻错误状态，不混入正常列表。
6. 底部边界提示保留，视觉降级为安静的说明区，不与消息争夺注意力。

## 视觉规格

- Figma 画板：390 × 844；代码适配原生导航栏后的滚动内容区。
- 内容左右边距：24px；标题 28/36；正文 14/22；消息标题 16/23；辅助信息与状态不低于 12/18。
- 列表使用 16px 圆角外框；消息行内边距 20px，行间由 1px 分隔线建立节奏；无阴影。
- 颜色沿用 Canvas、Surface、Ink、Muted、Primary、Line；撤回只用中性灰，不用危险红制造焦虑。
- 不使用插画、照片、渐变、玻璃拟态、聊天气泡、铃铛装饰或自动播放动效。

## 明确保留

- 原标题、边界语义、列表字段、状态判断、刷新时机、错误恢复、诊断复制、Toast 和详情跳转。
- 研究者来源、版本号、撤回说明与未读/已读文字状态。
- 原生导航栏和既有 `page-state`、`status-pill`、`bottom-tip-card` 组件语义。

## 禁止新增或修改

- 不新增搜索、筛选、分页、下拉刷新、全部已读、删除、回复、聊天输入、客服、消息分类 Tab 或未读统计标题。
- 不修改 JS、API、后端、数据库、shared、认证或详情页自动已读语义。
- 不把消息描述为实时响应或紧急支持渠道。

## 风险与待验收

- 2026-08-09 录屏没有进入消息页，本轮视觉基线以当前 WXML/WXSS 和同族页面代码为准。
- 原始时间字符串、50 条长列表、超长标题/正文、200% 大字体、读屏和弱网需在本地检查及最终真机批次继续验证。
- Android/iOS 真机验收按总规则延期到全部页面本地完成后。
