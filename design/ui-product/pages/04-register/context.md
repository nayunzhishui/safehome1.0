# 注册页 UI 改造需求冻结

状态：`frozen`
日期：2026-08-10
路由：`pages/register/index`
视觉方向：方案 A「编辑式手帐」

## 目标与用户

- 目标：让首次使用的家长或学生清楚、平静地创建账号，降低卡片堆叠和模板化 AI 感。
- 用户：公开注册仅面向家长与学生；研究者、督导和管理员由项目负责人单独开通。
- 核心任务：填写用户名、密码、角色和可选昵称，提交注册后进入原有目标页或首页。
- 成功标准：3 秒内识别页面用途与唯一主行动；必填/选填关系清晰；加载和错误可理解；所有原事件、接口与跳转保留。

## 功能真值

- `onUsernameInput`：用户名，前端与后端均要求至少 3 个字符。
- `onPasswordInput`：密码，前端与后端均要求至少 8 个字符。
- `onRoleChange`：原生 picker，仅 `parent/家长` 与 `student/学生`。
- `onNicknameInput`：昵称可选，空值不提交。
- `submitRegister`：调用现有 `POST /api/auth/register`，成功保存原会话、显示“已注册”并按既有 redirect/home 跳转。
- `goLogin`：进入现有登录页并保留 redirect。
- 整体状态：Default、Loading、ValidationError、ApiError、LongContent；成功态使用现有 Toast 后立即跳转，不制造静态成功页。

## 冻结布局

1. 开放式象牙白画布，不使用外层大卡片。
2. 顶部依次为 SafeHome、页面标题“创建账号”、现有开放角色说明。
3. 单列“账号信息”表单，顺序严格保留：用户名 → 密码 → 角色 → 昵称（可选）。
4. 用户名与密码的长度要求由持久辅助文字表达，不只依赖 placeholder。
5. 角色继续使用原生 picker，不改为新业务选择流程；选中值清晰展示。
6. “注册”是唯一主行动；“已有账号，去登录”为低权重文字行动。
7. 错误继续使用原有整体消息，不推断字段级错误来源。

## 视觉规格

- Figma 画板：390 × 844；代码按原生导航栏后的内容区适配。
- 内容左右边距：24px；表单控件宽约 326px并居中。
- 页面标题：28/36；段落：14/22；区标题：20/28；标签与按钮：14/20；辅助文字：12/18。
- 输入与选择控件：52px 高、16px 圆角；主按钮：44px 高、16px 圆角。
- 颜色沿用现有象牙白、深墨绿、森林绿与陶土橙点缀；无渐变、玻璃拟态、插画和装饰性图标。
- Figma 使用已确认的 Noto Sans SC；小程序保留系统中文字体栈。

## 明确保留

- 原字段、字段顺序、默认角色“家长”、角色值、校验阈值、错误文案来源、loading、Toast、会话写入和跳转。
- 原生导航栏与原生 picker 行为。
- 与登录页一致的 AuthField/Button 视觉语言。

## 禁止新增或修改

- 不新增手机号、邮箱、验证码、邀请码、协议勾选、找回密码、密码显隐、游客入口或第三方登录。
- 不开放 researcher、supervisor、admin 公共注册。
- 不修改 JS、API、后端、数据库、shared 或认证语义。
- 不承诺代码和接口未明确提供的数据保存、隐私或服务能力。

## 风险与待验收

- 旧录屏未进入注册页，当前视觉基线以真实 WXML/WXSS 和登录页同族设计为准。
- 原生 picker、键盘顶起、极长服务端错误、200% 大字体和读屏需在后续本地/最终真机阶段验证。
- Android/iOS 真机验收按总规则延期到全部页面本地完成后。
