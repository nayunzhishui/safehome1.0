# 消息详情页方案 A 内部方向比较

全局视觉方向已冻结为方案 A。本页只比较真实消息内容的组织方式。

## A1：编辑式来函（采用）

- 结构：类型小标题 → 大标题与元信息 → 左线正文 → 条件性来源行动 → 共同核对 → 页尾边界与返回。
- 优化：最适合长中文阅读，来源、版本和撤回状态清楚；减少结果卡与聊天产品的 AI 感。
- 代价：视觉更克制，依靠字体、留白和细线而不是插画或大容器制造识别。
- 适配真值：最强；不新增字段、入口或交互。

## A2：来源时间轴

- 结构：时间、版本、来源节点组成纵向时间线，正文挂在当前节点下。
- 优化：适合多版本消息或完整修订历史。
- 代价：当前接口只返回一条当前消息，没有历史版本数组；时间线会伪造不存在的数据关系。
- 结论：不采用。

## A3：对话回复式详情

- 结构：研究者头像/气泡 → 用户反馈气泡 → 底部回复栏。
- 优化：看起来熟悉、互动感强。
- 代价：页面没有回复 API 或实时聊天能力，会制造假入口并强化通用 AI/客服感。
- 结论：禁止采用。

## 最终冻结

采用 A1。创意来自“真实来函的编辑排版”，而不是信封插画或聊天拟物。正文是页面核心；来源按钮、共同核对和安全边界依次降级，撤回态优先保护旧内容不再暴露，但不擅自改变其他条件操作。
