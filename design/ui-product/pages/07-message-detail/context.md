# 消息详情页 UI 改造需求冻结

状态：`frozen`

视觉方向：方案 A「温润编辑式来函」
确认依据：用户已确认方案 A，并授权按功能真值逐页自动完成 ImageGen、Figma、实现与本地审核。

## 目标与用户

- 目标：把一条人工补充或系统提醒呈现为可安心阅读、可辨认来源与版本的“来函”，降低大卡片、模板化和 AI 聊天感。
- 用户：已登录并从消息列表打开本人消息的家长或学生。
- 核心任务：读完当前消息，理解来源和边界；仅在真实条件满足时查看关联来源或提交共同核对。
- 成功标准：3 秒内识别消息类型、标题、来源/时间/版本和正文；撤回状态不暴露旧正文；每个状态最多一个实心主行动；现有接口、自动已读、反馈核对与跳转语义不变。

## 功能真值

- `onLoad` 从路由读取 `id`；缺少 `id` 时不请求接口，显示错误并返回消息列表。
- `loadMessage` 调用 `GET /api/messages/:id`；后端只返回当前账号可访问的消息，并在首次打开未读消息时自动标记为已读。
- `supervision_feedback` 显示“人工补充反馈”，其他类型显示“消息提醒”。
- 标题、正文、来源角色、创建时间、交付版本与撤回状态均来自真实接口；撤回后正文只显示固定撤回说明，来源入口与共同核对仍按各自现有条件显示。
- 只有 `relationship_screening_report + source_id` 可打开关系探索报告；只有 `relationship_narrative + source_id` 可打开已确认探索手记。
- 只有四类允许消息可提交共同核对；`uncomfortable` 只登记为人工复核信号，不据此推断风险或诊断。
- 返回动作继续使用 `navigateBack`，不改为虚构的固定目的地。

## 冻结布局

1. 象牙白开放画布，顶部为紧凑类型标记和消息标题，不使用英雄卡。
2. 来源、时间、版本组成单行或自然换行的编辑式元信息；正文以高行距全宽阅读区呈现，左侧使用克制竖线建立“来函”识别。
3. 真实来源入口紧跟正文，仅在 `canOpenSource` 为真时出现，作为当前状态唯一实心主行动。
4. 共同核对作为独立小节，问题在上、四个语义选项在下；保存中禁用，选中后必须有文字状态，不能只靠颜色。
5. 边界说明降级为页尾细线便笺，保持现实支持措辞但不用高危险红色卡片制造恐慌。
6. “返回消息列表”保持轮廓次行动；Loading 与错误态复用 `page-state`。

## 状态矩阵

- Loading：加载提示，无其他旧内容。
- MissingId：说明缺少消息 ID，唯一动作返回消息列表。
- LoadError / NetworkFailure：显示真实错误，唯一动作重新打开。
- Default：消息标题、元信息、正文、边界与返回。
- WithSource：正文后显示真实来源主按钮。
- Evaluable：显示四项共同核对。
- EvaluationSaving：四项禁用，保留原内容。
- Evaluated：显示已选项和可调整说明。
- Uncomfortable：显示人工复核说明，非诊断、非风险结论。
- Withdrawn：正文只显示撤回说明，不显示旧正文；来源行动和共同核对仍按 `canOpenSource`、`canEvaluate` 的真实条件显示。
- LongContent：标题、元信息和长正文自然换行、页面滚动，不裁切。

## 视觉规格

- Figma 画板：390 × 844；内容左右 24px，正文最大可读宽度占满内容列。
- 标题 28/36，正文 15/25，元信息 12/18，小节标题 14/20；均使用 Noto Sans SC。
- 色彩只使用既有 Canvas、Surface、Ink、Muted、Primary、Primary Deep、Line、Danger；普通边界不用 Danger 主导。
- 只保留必要的反馈组件容器；正文、边界与元信息不用重复卡片。
- 不使用插画、头像、聊天气泡、信封拟物、渐变、玻璃拟态、emoji 或装饰动效。

## 明确保留

- 原生导航标题、路由参数、错误文案语义、标题/正文/来源/时间/版本绑定、撤回保护、真实来源条件、四项核对、保存禁用、Toast 和 `navigateBack`。
- `feedback-rating` 与 `page-state` 的事件和属性契约。
- 高风险边界原意：消息不处理紧急安全风险，应优先寻找现实支持。

## 禁止新增或修改

- 不新增回复、聊天、删除、转发、收藏、复制、举报、紧急呼叫、客服、消息历史或伪造来源。
- 不修改 JS、API、后端、数据库、content、shared、认证、自动已读或人工复核规则。
- 不改写接口返回正文，不把研究者补充包装为诊断、治疗建议或确定事实。
