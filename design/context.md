# 任务20产品设计上下文

更新时间：2026-07-17

## 目标

把小程序“记录—反馈—练习—复盘—人工支持—项目试点”与研究者端“参与者检索—全模块审阅—阶段反馈—消息送达—审计”整理成一套连续、低认知负担、非诊断的体验。

## 核心用户

1. 参与者：希望快速完成记录，理解系统给出的支持性线索，并知道下一步去哪里。
2. 研究者：希望按被授权参与者检索、查看全部模块记录、识别待处理事项并发送可追踪反馈。
3. 研究负责人/管理员：希望查看全体参与者、审计研究者操作、维护内容治理边界。

## 关键任务

- 参与者完成测评、情绪日记、项目练习后，能看到保存结果、支持性反馈、训练建议和后续消息。
- 参与者能主动把某一条情绪事件或某一次测评关联到人工支持请求。
- 用户自行设置的练习节奏真实影响“今天是否到期、推荐顺序和下一次练习日期”。
- 研究者能从统一参与者档案查看测评、日记、训练、项目、关系试点、人工支持和消息记录。
- 阶段性反馈作为不可变的新版本交付，同时进入参与者消息和成长时间轴。

## 设计原则

1. 一屏一个主任务，次要说明折叠或弱化。
2. 先给结论和下一步，再给解释和边界。
3. 内部 ID、枚举、英文键只在调试或审计环境出现。
4. 所有反馈使用“这次记录中可以看到”“可能”“可以试试”等支持性措辞。
5. 原始参与者填写保持只读；研究者反馈、备注和状态更新另存，不覆盖原文。
6. 研究者按最小权限访问：研究者查看被分配参与者的全部模块，负责人/管理员查看全体。
7. 触控目标不小于 44px 等效尺寸，按钮文字水平和垂直居中，窄屏不横向裁切。

## 非目标与外部边界

- 不把支持性反馈写成诊断、筛查、人格判断或疗效证明。
- 不自动开放未经心理、研究、伦理或版权审核的量表、项目或高风险训练。
- 微信系统级定时推送依赖订阅消息授权、模板和云端定时任务；本任务先实现站内到期提醒和节奏驱动推荐。
- 不保留“任意研究者查看所有参与者”的越权路径。

## 成功标准

- 16个需求均有明确页面、接口、数据源、测试和人工验收项。
- 截图指出的内部字段、裁切、错位、空图标和无输入框问题消失。
- 项目第1—3节及每个反思问题均可独立填写、保存草稿、提交和回看。
- 人工支持可选择并显示真实关联记录，后端校验记录归属。
- 研究者档案覆盖测评、情绪日记、训练、项目、关系试点、督导和消息，并支持用户ID检索。
- 练习节奏返回今日到期状态、下次日期和节奏内推荐。

## 2026-07-18 深化范围

任务二十的单页问题已经基本收口。任务二十三至三十四不再以“多改页面”为目标，而以以下系统目标为准：

1. 首页保留现有界面和区块，只新增一个跨模块动态主行动，并复用既有训练到期逻辑。
2. 即时反馈、训练、关系报告和AI回答使用统一的共同核对语言；旧帮助度与关系核对数据继续兼容。
3. 参与者能看见输出依据、纠正“不符合/不适”、退出和转人工。
4. 研究者从待处理队列进入，不靠在多个页面自行寻找异常。
5. 所有页面覆盖空、加载、错误、成功、权限不足、撤回授权和弱网恢复。
6. 设计成功不能只用点击率衡量；同时观察认知负担、错误恢复、不适、退出和人工升级。

深化阶段仍沿用暖白、低饱和绿、橙色谨慎提示，不做全站换肤。视觉变化必须服务层级、可访问性和心理安全。

## 2026-07-19 首页布局冻结

- 保持现有首页视觉结构，不做整体改版。
- “今天的一小步”插入“测一测/情绪日记”双入口之后、“三步开始”之前。
- 现有情绪温度计入口（当前代码显示为“情绪天气”）、核心入口、三步开始、更多、最近记录、阶段性反馈和消息中心不删除、不移动。
- 新卡片只承担动态主行动和状态反馈，详细内容继续进入对应页面，不在首页展开。

## 2026-07-19 治疗性评估受控接入

- 不在首页新增永久“治疗性评估”模块；只有存在获准且进行中的会前准备、反馈修订、微行动或随访时，才通过“今天的一小步”继续。
- 用户端称“会前自我了解准备”或“协作式支持性评估”，不使用AI治疗师、自动诊断或治疗效果承诺。
- 复用现有日记、测评、关系报告、研究者确认、消息、训练打卡和成长时间线；界面围绕评估问题、代表事件、证据、待核对假设、反馈版本、微行动和随访组织。
- 当前只设计合成数据L0内部流程；真实参与者、多人共享、L1—L3和AI用户输出继续受人工门禁阻断。

## 2026-08-09 小程序全量 UI/UX 逐页改造

状态：`homepage_requirements_frozen_existing_api`

- 改造范围覆盖当前小程序全部页面，但严格一次只处理一个页面；每页都单独完成审查、需求冻结、ImageGen、Figma、前端实现、Loop 与 Harness。
- 每个页面按阶段选用最小必要的 UI skills，并在执行前说明；不得把多个页面合并成一次批量换肤。
- 总目标是在不改变业务语义的前提下，减少模板化和 AI 拼装感，提升可读性、创意感、审美与页面辨识度。
- 主视觉方向冻结为“温润编辑感”：暖米白底、森林墨绿、少量陶土橙，更多依靠字体、留白、细分隔和开放式版面建立层级，减少重复圆角卡片、胶囊按钮、渐变光斑和泛治愈装饰。
- 用户仍以 30—45 岁、可能正处于亲子沟通压力中的家长为主要对象；页面应让用户在约 3 秒内知道当前最值得做的一件事。
- 首页作为第一张视觉母版。现有情绪温度计、测一测/情绪日记、今天的一小步、三步开始、更多、最近记录、阶段性反馈、消息中心和四栏 tabBar 的功能、数据、跳转及主要顺序全部保留。
- 首页允许重做排版、视觉层级、留白、图标、插画语言、状态呈现及不改变业务含义的微文案；不新增 API、字段、数据请求或业务入口，不修改后端。
- 首页成功标准：一个明确主行动；首屏主次清楚；长文本与窄屏可读；不呈现诊断、疗效或人格结论；不以重复卡片和装饰性胶囊制造“精致感”。

## 2026-08-09 首页需求冻结版 v1

用户已确认以下需求，后续首页概念图、Figma 和前端实现均以本节为准。

### 页面目标

- 首页帮助家长快速判断今天可以从哪里开始，并保留全部既有业务入口。
- 在模块顺序不变的前提下，建立一个明确主行动，降低卡片堆叠和模板化观感。
- 目标用户仍以 30—45 岁、可能正处于亲子沟通压力中的家长为主。

### 固定信息顺序

1. 顶栏与消息入口；
2. 情绪温度计；
3. 测一测与情绪日记；
4. 今天的一小步；
5. 三步开始；
6. 更多入口；
7. 最近记录；
8. 阶段性反馈；
9. 开发入口仅按现有条件显示。

以上顺序不允许调整。“今天的一小步”仍是页面唯一强视觉行动；位于它之前的情绪温度计、测一测和情绪日记通过更轻的开放式布局降低竞争，不伪装成第二组主按钮。

### 允许修改

- 排版、字号、行高、留白、分隔、圆角、阴影和色彩层级；
- 状态的视觉表达和不改变业务含义的短文案；
- “三步开始”收成一行“如何开始”入口，保留原跳转，不再默认展示三个按钮；
- “更多”、最近记录和阶段性反馈改成更安静的列表或编辑式区块；
- 使用细线、纸张纹理和轻叶影建立首页品牌母题。

### 禁止修改

- 不调整模块顺序；
- 不删除现有入口、点击事件、数据、状态、跳转和埋点；
- 不新增 API、字段、业务入口或后端能力；
- 不使用人物、家庭照片、通用治愈插画、emoji 正式图标、渐变光斑或装饰性循环动效；
- 不使用诊断、筛查、疗效或人格定性表达。

### 状态与适配

- 保留今天的一小步的 Loading、Error、Ready、Paused、Completed、Not Due、登录门禁和参与者保护状态；
- 保留最近记录与阶段性反馈的有数据、无数据、错误和弱网状态；
- 支持窄屏、长中文、大字体、安全区域和不低于 `88rpx` 的触控目标；
- 辅助文字不低于 `24rpx`，正文以 `28rpx` 为基准。

### 验收标准

- 模块顺序与当前页面一致；
- “今天的一小步”是唯一强视觉行动；
- “三步开始”只保留单行入口；
- 无人物图，视觉母题来自细线、纸张纹理和轻叶影；
- 主要内容不依赖重复圆角卡片建立层级；
- 业务逻辑、后端和 API 零变化；
- ImageGen、Figma 与真机页面的差异均有记录。

### 2026-08-09 功能对齐冻结 v2

- 本冻结版的视觉约束继续有效；用户已确认保留现有接口和后端能力，可以重新进入 ImageGen 视觉探索，仍需用户确认概念稿后才能进入 Figma。
- 顶部入口的真实能力是情绪温度计：读取当天温度计记录次数，并进入 `pages/thermometer/index` 记录强度、效价、唤醒和控制感；不得设计成天气选择器。
- 两张 ImageGen 预览都擅自新增天气选项、替换“更多”条目并编写阶段反馈结论，已判定为淘汰稿。
- 新一轮 ImageGen 必须逐项绑定 `design/function-truth-table.md` 的首页章节，不得仅依据视觉氛围生成。
- 支持性反馈保留现有“先记录一件具体事件，再生成对应反馈”的流程；入口辅助文案应明确“记录后获得反馈”，不得表现为读取历史反馈。
- 最近记录仍以进入真实记录页为目标。该页后续复用现有 `GET /api/diaries`，不新增接口；但它是独立页面，必须在首页前端实现前完成自己的功能真值表、冻结、ImageGen 与 Figma。

首页视觉概念稿可继续生成；Figma 与前端仍保持阻断，分别等待概念稿确认和“最近记录”页面依赖完成。

## 2026-08-10 UIproduct 全页面自动改造冻结

- 用户确认首页采用方案 A“编辑手帐”，它成为全小程序的视觉母版；各页保持自身任务差异，不机械复制首页结构。
- 全部工作只在 `UIproduct` 分支进行，`main` 分支指针不得变化。
- 正式逐页改造前，先从当前代码为 `app.json` 全部页面生成详细功能与接口证据，并写入 `design/function-truth-table.md`。
- 页面顺序由机器注册表控制；上一页未完成 ImageGen 审查、Figma 审查、代码实现、五轮 Loop 和四类 Harness 时，不得进入下一页。
- 后端、数据库、API、`content` 和 `shared` 业务语义均不修改；发现能力差距只记录并停止对应设计。
- ImageGen、Figma、开发者工具截图和真机证据必须可追溯；工具或人工环境不可用时标记“未完成”，不得自动写成通过。

## 2026-08-10 情绪记录页需求冻结 v1

状态：`frozen_for_imagegen`；页面路由预定为 `pages/diary-history/index`。

- 目标：让家长从首页“最近记录”进入一个真实、可读的情绪事件记录列表。
- 用户与场景：已登录家长回看近期具体事件，确认当时的场景、描述、主要感受和强度。
- 唯一主任务：阅读最近保存的真实记录；唯一主行动为“记录一件事”。
- 信息优先级：页面标题与当前显示数量 → 记录时间/场景 → 事件描述 → 家长情绪与强度 → 去记录。
- 布局：沿用方案 A 的温润编辑感，使用时间脊线、留白和细分隔形成真实时间序列；记录项不套重复圆角卡片。
- 色彩与字体：复用首页 Figma Variables；暖白画布、墨色正文、森林绿行动、陶土橙只用于强度的克制提示；Figma 使用 Noto Sans SC，代码保留系统中文字体栈。
- 图标与插画：不使用人物、家庭照、emoji 或空泛治愈插画；本页不需要插画。
- 动效：只允许加载完成和展开内容的短过渡；v1 没有展开功能，因此不增加装饰动效。
- 保留：登录守卫、现有 `GET /api/diaries`、真实字段、原生返回、进入日记表单。
- 修改：新增纯前端记录页；首页有记录时改为进入该页；首页无记录仍进入日记表单。
- 禁止：新增后端/API/数据库字段；虚构总数、统计、趋势、诊断结论、编辑、删除、详情或筛选能力。
- 状态：Default、Loading、Empty、Error、Network Failure、Long Content；只读列表不制造 Disabled、Active 或 Selected。
- 上游：首页最近记录；下游：`pages/diary-form/index`；不改变周报和支持性反馈路径。
- 成功标准：用户 3 秒内知道这是自己的情绪记录；每条内容来源可追溯；长中文完整换行；错误可重试；触控目标不小于 88rpx。
- 回滚点：新增页面及首页跳转可以独立回退，不影响 `GET /api/diaries` 或日记创建链路。
- 假设：v1 展示最近 50 条足以解决首页“进入真实记录页”的依赖；接口没有总数，因此只写“当前显示”。
